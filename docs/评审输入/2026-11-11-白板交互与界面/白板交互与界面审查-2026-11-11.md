## 二、用户提出的 9 个问题：原因与修改方案

### 问题 1　贴纸面板没有边框、太窄、内容太大、排列不清

**原因（三层叠加）**

1. **背景和边框是无效声明**（根因 A）。`board.css:360-366`：
   ```css
   .glass { background: var(--panel); border: 1px solid var(--edge); ... }
   ```
   `--panel`、`--edge` 在整个 `app/src` 里都没有定义。`var()` 引用未定义变量且无回退值时，整条声明在计算阶段失效：背景变透明，只剩 `backdrop-filter` 的模糊；`border` 回到初始值 `none`。截图 1 里面板左侧能直接看到画布上的笔迹，就是这个原因。圆角 `border-radius: var(--r-xl)`（`.sheet`）同样失效，所以面板是直角。
2. **预览没有缩小**（旧 P2-16）。`.gallery .thumb { --wk: .52 }`（`board.css:739`）被 `WidgetFrame.jsx:21` 内联的 `--wk: fw/baseW` 覆盖；预览 item 没有 `frame`，于是 `wk = 1`，每个预览都按 352×168 全尺寸渲染。面板只有 440px 宽（`board.css:646`），一行只放得下一个，第二个被裁掉一半（截图 1 右侧）。
3. **信息组织方式不对**。`BoardStickerPanel.jsx:141-238` 为**每一天**渲染 2 个完整小组件（概览 + 路线），为**每个活动**、**每个收藏**各渲染 1 个完整小组件。15 天的旅程光「日程与路线」就是 30 个全尺寸小组件，既占屏又慢（每个都要跑一遍 `widgetModel()`，时钟小组件还各自开一个 `setInterval`）。另外每次添加后面板都会自动关闭（`onClose()`），想连续贴几个只能反复打开。

**修改方案**

- 先修根因 A（见第四节 A 的统一映射），面板立即有底色、边框和圆角。
- 面板改为**停靠式抽屉，默认在左侧**，材质与地图页搜索卡片一致（详见第五节布局图），不再盖在画布中央；用户可拖动到右侧或底部，规格见本节末尾「停靠与拖动规格」。
- 面板内结构：
  - 顶部：标题 + 搜索框（按活动名、地点名、第几天过滤）+ 关闭按钮。
  - 分段控件：小组件 / 便签 / 表情 / 图片（选中态用 `--accent`）。
  - **概览组**（倒计时、当地时间、费用）：2 列网格，预览按 0.48 倍缩放，S 型 80×80、M 型 168×80。
  - **日程组**：每天一行紧凑条目，不再渲染完整小组件：
    ```
    第 1 天  11/25 周三 · 3 项安排        [概览] [路线]
    ```
    「路线」在该天定位站点少于 2 个时置灰并提示「至少 2 个有位置的安排」（旧 P3-9）。鼠标悬停条目时，在条目右侧弹出该小组件的实际预览。
  - **活动组**：按天折叠分组，每行「图标 + 标题 + 时间」，右侧「小 / 中」两个按钮直接选规格添加。
  - **收藏组**：2 列网格，每格 = 标记色图标 + 名称两行省略。
- 预览缩放：`BoardStickerPanel` 给预览传 `frame: { w: baseW * 0.48, h: baseH * 0.48 }`；或改 `WidgetFrame`：无 `item.frame` 时不内联 `--wk`，由外层 CSS 决定。
- 添加后**不自动关闭**面板；新对象在视口中央出现时播一次 300ms 的轻微放大 + 描边高亮，让用户知道贴到了哪里。
- 支持**从面板直接拖到画布**：在条目上 `pointerdown` 后移动超过 4px 即进入拖拽，跟手显示半透明预览，在画布上松手处创建（坐标用 `screenToWorld`）。
- 面板只在打开时渲染预览；预览组件用 `React.memo` 并以 `widgetDeps()` 作为比较依据。

#### 停靠与拖动规格（已确认）

**停靠位置**：左（默认）、右、下三处。不提供顶部停靠：顶部已有白板切换器和同步/成员胶囊，面板放上去会与之重叠，也会挡住新对象出现的视口中心。

| 停靠 | 几何（桌面，视口宽 ≥ 760px） | 内容排布 |
| --- | --- | --- |
| 左 | `left:16px; top:76px; bottom:96px; width:360px` | 竖向：分段控件在上，分组纵向滚动 |
| 右 | `right:16px; top:76px; bottom:96px; width:360px` | 同左 |
| 下 | `left:16px; right:16px; bottom:84px; height:280px; max-width:960px; margin:0 auto` | 横向：分段控件竖排在左侧 96px 列，各分组为横向滚动的行，与工具栏之间留 12px |

`top:76px` = 顶部胶囊 16px 外边距 + 44px 高 + 16px 间距，保证面板不压住左上的白板切换器和右上的同步/成员胶囊；`bottom:96px` 让出底部工具栏和右下缩放控件。

**拖动栏**：

- 面板标题栏左侧放一个小拖动柄：两行三点（⋮⋮）图标，24×24 可见、44×44 热区，`cursor: grab`；整个标题栏空白处也可拖。它是一个 `<button aria-label="移动面板（当前停靠：左侧）">`。
- 按下后移动超过 4px 才进入拖动（避免误触），并对拖动柄 `setPointerCapture`。
- 拖动中：
  - 面板收缩为 280×200 的浮动卡片，半透明（`opacity: .92`），跟随指针，略微放大阴影。
  - 三个停靠目标同时出现：沿左、右、下边各显示一条 `--accent` 虚线圆角区域（宽/高与停靠后的面板一致，透明度 .25）。
  - 当前会吸附到的那一边加实色描边、透明度升到 .5。判定规则：取指针到左、右、下三条边的距离，最近的那条边胜出（不需要拖到边上，任何位置松手都会吸到最近的一边，**不存在自由漂浮状态**）。
  - 按 Esc 取消拖动，回到原停靠位置。
- 松手：面板以 200ms 缓动（`cubic-bezier(.2,.8,.2,1)`）从当前位置变形到目标停靠位置和尺寸；内容在动画结束后切换排布，避免变形过程中内容跳动。开启「减少动态效果」时直接跳到目标位置。
- 拖动面板时画布不平移、不触发任何白板手势（拖动柄位于 `.ui` 内，已被画布事件排除，但要确认 `pointermove` 在面板上也被捕获）。

**键盘与无障碍**：拖动柄获得焦点时，按 ←/→/↓ 直接切换到对应停靠位；右键或长按拖动柄弹出菜单「停靠在左侧 / 右侧 / 底部」。切换后读屏播报「贴纸面板已停靠在右侧」。

**记住选择**：停靠位置写入账号偏好 `boardPanelDock: 'left' | 'right' | 'bottom'`（与 `autoCollapseMapSidebar` 同一套偏好机制，多设备同步）。「我的设置 › 地图与白板」中加一项「贴纸面板位置」，三选一，与拖动结果双向一致。

**与画布的配合**：

- 面板浮在画布上方，不改变画布尺寸，但要计算「可见画布区域」= 视口减去面板所占矩形。以下几处都改用这个区域：新对象出现的「视口中心」（`getCenterSpawnPoint`）、「适应全板」（`center()` 的 viewport 参数加上偏移）、操作条的左右 clamp。
- 停靠在左侧时，左上角白板切换器不动（面板从 76px 开始，在它下方）。停靠在底部时，右下缩放控件上移到面板上方。

**窄屏**：视口宽 < 760px 时一律为底部弹层（高度 60%，可上拉到 90%），隐藏拖动柄，偏好值保留，回到宽屏时恢复。

**实现提示**：

```jsx
// BoardStickerPanel.jsx
const [dock, setDock] = usePreference('boardPanelDock', 'left');
const [drag, setDrag] = useState(null);         // { x, y, target } | null
function nearestDock(x, y, vw, vh) {
  const d = { left: x, right: vw - x, bottom: vh - y };
  return Object.entries(d).sort((a, b) => a[1] - b[1])[0][0];
}
// 拖动柄 pointerdown → capture；pointermove 超过 4px 后 setDrag({ x, y, target: nearestDock(...) })（rAF 合并）
// pointerup → setDock(drag.target); setDrag(null)；lostpointercapture / Esc → setDrag(null)
// 渲染：<div id="panel" className={`ui sheet glass dock-${drag ? 'floating' : dock}`} style={drag ? { left: drag.x - 140, top: drag.y - 20 } : undefined}>
// 停靠目标：{drag && ['left','right','bottom'].map(k => <div key={k} className={`dock-target ${k} ${drag.target === k ? 'on' : ''}`} />)}
```

用 `.dock-left/.dock-right/.dock-bottom` 三个类给出几何；变形动画用 FLIP（松手时记录浮动卡片的 rect，切换类后用 `transform` 从旧 rect 过渡到新 rect），比直接过渡 `left/top/width/height` 更顺。

**验收**：1280 宽度下，从左拖到画布右半部分任意位置松手，面板吸附到右侧；拖到靠近底部松手，吸附到底部并变为横向排布；刷新页面、换另一台设备登录后，面板仍在上次的位置；停靠在任一侧时，新贴纸出现在面板以外可见区域的中心。

**验收**：1280 宽度下面板有清晰边框和底色，不遮挡画布中部；15 天 × 每天 5 项的测试旅程中，打开面板时没有明显卡顿；连续添加 3 个贴纸无需重新打开面板。

### 问题 3　画笔只在松手后才出现笔迹

**原因**（根因 B，新发现，上一份报告未覆盖）：`board.css:71-80`
```css
#draft { position:absolute; left:0; top:0;
         width:100000px; height:100000px;
         transform: translate(-50000px, -50000px); }
```
`<svg id="draft">` 没有 `viewBox`，路径坐标以 SVG 自身左上角为原点。SVG 被整体平移到世界坐标 (−50000, −50000)，于是世界坐标 (300, 200) 的点实际画在 (−49700, −49800)，远在视口之外。松手后 `handlePointerUp` 生成正式的 stroke 对象，由 `BoardItem` 在正确位置渲染，所以「松手才出现」。

此外还有三处次要问题，修好位置后会马上暴露：

- 草稿颜色固定为 `var(--text)`，忽略已选的 `penColor`；荧光笔草稿固定为黄色、宽 18，正式笔迹是所选颜色、宽 16、带 `mix-blend-mode: multiply` → 松手瞬间颜色和粗细会跳一下（旧 P3-5）。
- 每个 `pointermove` 都 `setDraftPoints([...gesture.points])`：复制整个点数组 + 整个 `Board` 及全部可见对象重渲染（旧 P2-6）。对象一多，跟手延迟明显。
- 只取 `pointermove` 的单个采样点，快速画线时会出现折角。

**修改方案**

```css
/* board.css：草稿层不再平移，直接溢出显示 */
#draft {
  position: absolute; left: 0; top: 0;
  width: 1px; height: 1px;
  overflow: visible;
  pointer-events: none;
  z-index: 99999;
}
```

```jsx
// board.js：笔迹颜色与粗细统一出口，BoardItem 和草稿层共用
export const PEN = { default:'var(--ink-default)', accent:'var(--ink-accent)', red:'var(--ink-red)',
                     orange:'var(--ink-orange)', blue:'var(--ink-blue)', purple:'var(--ink-purple)' };
export const HL  = { yellow:'var(--hl-yellow)', green:'var(--hl-green)', blue:'var(--hl-blue)', pink:'var(--hl-pink)' };
export const HL_WIDTH = 16, HL_OPACITY = 0.45;
export function strokeLook(tool, color, size) {
  return tool === 'highlighter'
    ? { stroke: HL[color] ?? HL.yellow, width: HL_WIDTH, opacity: HL_OPACITY }
    : { stroke: PEN[color] ?? PEN.default, width: size ?? 4, opacity: 1 };
}
```

```jsx
// Board.jsx：草稿用 ref 直接改 d，不走 React 状态
const draftRef = useRef(null);
const [drawing, setDrawing] = useState(null);      // 仅在起笔/收笔时 set 一次：{ tool, color, size }

// pointerdown（pen/highlighter）
gestureRef.current = { type: 'draw', tool, points: [[pt.x, pt.y]], raf: 0 };

// pointermove
const evs = e.nativeEvent.getCoalescedEvents?.() ?? [e.nativeEvent];
for (const ev of evs) { const p = screenToWorld(ev.clientX, ev.clientY); g.points.push([p.x, p.y]); }
if (!g.raf) g.raf = requestAnimationFrame(() => {
  g.raf = 0;
  draftRef.current?.setAttribute('d', pathD(g.points));
});

// pointerup：先 addBoardItem（它会同步 setItems），再 setDrawing(null)，避免松手瞬间闪一下

// 渲染
{drawing && (() => { const s = strokeLook(drawing.tool, drawing.color, drawing.size); return (
  <svg id="draft" className={drawing.tool === 'highlighter' ? 'highlighter' : ''}>
    <path ref={draftRef} stroke={s.stroke} strokeWidth={s.width} strokeOpacity={s.opacity}
          fill="none" strokeLinecap="round" strokeLinejoin="round" />
  </svg>); })()}
```

同时修旧 P2-14：使用画笔、荧光笔或文字工具时，对象不应拦截 `pointerdown`。最简单的做法是在 CSS 里让对象在这些工具下不接收指针：
```css
#stage:is([data-tool='pen'],[data-tool='highlighter'],[data-tool='text']) .board-item { pointer-events: none; }
```
并删掉 `handleStagePointerDown` 开头对 `.board-item` 的提前返回中针对这些工具的分支。

**验收**：按下即出现笔迹并跟手；所选颜色/粗细与松手后一致；可以从便签、图片上起笔；在 300 个对象的白板上画线，帧时间不随对象数明显上升（Chrome Performance 面板中 `pointermove` 处理 < 4ms）。

### 问题 4　小组件大小与样式切换卡顿、不合理；移动「粘手」

**原因**

1. **只能用三档按钮切换形态，四角缩放锁死比例。** `board.js:123-127`：小组件缩放时 `h = w * base[1] / base[0]`，比例固定为当前形态，拖四角永远不会从正方形变成长方形。按钮切换 `handleChangeWidgetSize`（`Board.jsx:526-534`）把 frame 直接重置为基准尺寸，用户之前缩放过的大小会丢失。
2. **切换后画面不变或回跳**（旧 P2-8）：拖动/缩放时把本机中间帧写进 `remoteLive`（`Board.jsx:262,280`），松手后从不删除。之后点「小/中/大」，数据里的 w/h 变了，但画面仍按 `remoteLive` 里的旧帧渲染——这就是「切换卡顿/切了没反应」的主要来源。
3. **同伴 presence 会冲掉本机拖动帧**（新发现，见 N-4）：`Board.jsx:123-136` 每当 `peerPresences` 变化，就用同伴数据**整体替换** `remoteLive`。正在拖动的对象被排除在同伴数据之外，于是本机的拖动帧也被一并清掉，对象跳回原位，直到下一个 `pointermove`。多人在线时（每位同伴每 5 秒一次心跳）拖动会周期性抖一下。
4. **粘手**：拖动和缩放手柄都没有 `setPointerCapture`（旧 P2-2）。鼠标在工具栏、操作条或窗口外松开时 `pointerup` 到不了 `#stage`，手势残留，之后对象一直跟着鼠标走；`handlePointerMove` 也不检查 `e.buttons`。另外没有拖动阈值，单击选中时手抖 1px 也会生成一次 frame 修改并同步。
5. **整树重渲染**（旧 P2-6）：每帧 `setRemoteLive(new Map(...))` → `Board` 重渲染 → 所有可见 `BoardItem` 和小组件重算 `widgetModel()`；地图草图每次重新生成 SVG 字符串。`widgetDeps()` 已经写好，但没有任何地方调用。

**修改方案：形态随拖动自动切换**

交互规则（与 iPhone 小组件的 1×1 → 2×1 → 2×2 对应）：

| 手柄 | 位置 | 作用 | 何时显示 |
| --- | --- | --- | --- |
| 四角圆点 | 四角 | 等比放大缩小，**不改变形态**，范围为基准尺寸的 0.75–1.6 倍 | 始终 |
| 左右拉球 | 左右边中点，竖向胶囊 6×22px（热区 44px） | 横向拉长 → 长方形 M；横向缩短 → 正方形 S | 该类型同时支持 S 和 M |
| 下拉球 | 下边中点，横向胶囊 22×6px | 往下拉 → 大正方形 L；往上收 → 回到 M | 该类型支持 L，且当前为 M 或 L |

形态判定加滞回区间，避免在临界点来回闪：

```js
// board-widgets.js
const RATIO = { S: 1, M: 352 / 168, L: 1 };
export function pickWidgetSize(kind, liveW, liveH, prev, axis /* 'x' | 'y' */) {
  const allowed = WIDGET_KINDS[kind] || ['S'];
  const r = liveW / liveH;
  if (axis === 'x') {
    if (prev === 'S' && allowed.includes('M') && r > 1.65) return 'M';
    if (prev === 'M' && allowed.includes('S') && r < 1.35) return 'S';
  } else {
    if (prev === 'M' && allowed.includes('L') && r < 1.45) return 'L';
    if (prev === 'L' && allowed.includes('M') && r > 1.75) return 'M';
  }
  return prev;
}
```

拖动过程：

- 边手柄拖动时，按指针位置画一个**虚线外框**（跟手），框内的小组件实时以判定出的形态渲染，并以 160ms 过渡动画（`transition: width .16s, height .16s`，仅在形态切换的那一刻启用，平时拖动禁用）变到新形态的尺寸，内容同步换成 S/M/L 布局。
- 松手时提交 `{ style: { size }, frame }`，其中 `frame.w/h = WIDGET_SIZES[size] × 当前缩放倍数 wk`，**保留用户已有的缩放**。
- 尺寸标签（`.dim`）在拖动时显示「小 / 中 / 大」而不是像素。
- 操作条上的「小/中/大」分段按钮保留，作为键盘和无障碍入口，但同样保留 wk。

**修改方案：拖动顺滑与不粘手**

```jsx
// 1) 本机实况与同伴实况分开
const [localLive, setLocalLive] = useState(null);            // { [id]: frame } | null
const frameOf = (it) => localLive?.[it.id] ?? remoteLive.get(it.id) ?? it.frame;

// 2) pointerdown（对象和手柄都要）
e.currentTarget.setPointerCapture(e.pointerId);
gestureRef.current = { type: 'drag', pointerId: e.pointerId, startClient: [e.clientX, e.clientY], started: false, ... };

// 3) pointermove
if (!(e.buttons & 1)) return endGesture();                   // 防止残留手势
if (!g.started && Math.hypot(dx, dy) < 3) return;            // 3px 阈值，单击不产生修改
g.started = true;
// 用 rAF 合并，每帧最多 set 一次
g.pending = liveFrames;
g.raf ||= requestAnimationFrame(() => { g.raf = 0; setLocalLive(g.pending); sendPresence({ live: g.pending, selected: [...selectedIds] }); });

// 4) pointerup / pointercancel / lostpointercapture 都走 endGesture
for (const [id, f] of Object.entries(g.pending ?? {})) patchBoardItem(id, { frame: f }); // 不 await：patch 内部同步 setItems
setLocalLive(null);                                          // 与 setItems 同一批次提交，不会闪回
sendPresence({ live: null, selected: [...selectedIds] }, { immediate: true });
```

- `remoteLive` 只由同伴 presence 计算，删除 `Board.jsx:262,280` 两处写入。
- `BoardItem` 包 `React.memo`；回调用 `useCallback` 或改为传 `id` + 稳定的处理函数（`Board.jsx:790-800` 的内联箭头函数会让 memo 失效）。
- `BoardWidget` 内 `const model = useMemo(() => widgetModel(...), [widgetDeps(snapshot, item)])`；`MapSketch` 的 `mapSvg()` 用 `useMemo([seed, w, h])`。
- 选中对象时 `setSelectedIds` 用同一个 Set 实例判断是否真的变化，避免无意义重渲染。

**验收**：

- 拖右边拉球，正方形小组件在越过约 1.65 比例时变为长方形，往回拉到约 1.35 以下变回正方形；临界处不闪烁。
- 先等比放大 1.3 倍再切换形态，切换后仍为 1.3 倍。
- 在工具栏上、窗口外松开鼠标，对象停在松手位置，不再跟随。
- 两台设备同时在线时拖动对象，不再每隔几秒跳回原位。

### 问题 5　地图小组件只是一张图，不是实际位置

**原因**：`MapSketch.jsx` 用 `mapSvg(seed)`（`board.js:233-259`）按种子随机生成街区、河流、道路，与地点坐标无关；地点小组件上的图钉固定在中间。路线小组件同理，只是把站点投影到这张假地图上。

**修改方案（已确认：高德静态地图）**

在白板上同时显示几十个小组件，不适合每个都创建一个 JSAPI 地图实例（WebGL 上下文数量有限、内存大），静态图最合适：

1. 服务端代理放行静态图，并按二进制返回（现在的代理用 `upstream.text()`，会把 PNG 弄坏）：
   ```js
   // server/amap.mjs
   allowedPaths.add('/v3/staticmap');
   ...
   if (req.path === '/v3/staticmap') {
     const buf = Buffer.from(await upstream.arrayBuffer());
     if (buf.length > 2_000_000) throw new Error('UPSTREAM_SIZE');
     res.set('Cache-Control', 'private, max-age=604800');   // 一周；坐标不变图就不变
     return res.type(upstream.headers.get('content-type') || 'image/png').status(upstream.status).send(buf);
   }
   ```
   限流单独计数（静态图配额与搜索不同）。
2. 地点小组件：`<img src={`${BASE}_AMapService/v3/staticmap?location=${lng},${lat}&zoom=16&size=168*168&scale=2`}>`，不让高德画标记，我们自己的品牌图钉仍叠在中心（保持现有视觉）。M 形态请求 `size=176*168` 放在左半边。
3. 路线小组件：用 `paths=` 参数画当天站点连线（颜色取主题 accent 的十六进制值），站点序号仍由我们自己叠加；有覆盖物时可省略 `location/zoom` 让高德自动适配范围（以高德文档为准）。
4. 加载策略：只在小组件进入视口时请求（已有视口裁剪）；画布缩放到 < 40% 时不请求，继续用现有草图当占位；请求失败、离线或地点没有坐标时回退到现有草图，并在角落显示「离线」小标。
5. 缓存：图片 URL 稳定，浏览器 HTTP 缓存即可；如需行程中离线可用，再把已加载的图存进 IndexedDB（与素材缓存同一套）。
6. 深色模式：静态图没有深色样式，可在深色模式下给图片加 `filter: brightness(.8) saturate(.85)`，并保留小组件自身的暗色渐变遮罩。
7. 双击地点小组件 → 跳转地图页并选中该收藏（修旧 P2-10 的导航参数后即可），满足「想看详细地图」的需求，不必在白板里做可交互地图。

**需要先确认**：当前 `AMAP_KEY` 是 JSAPI 类型的 key，经安全密钥代理调用 Web 服务接口；静态地图是否接受同一个 key，需要在测试环境实际请求一次。如不接受，需要在高德控制台为同一应用另建一个「Web 服务」key，只给服务端使用。

### 问题 6　底部工具栏没有选中显示

**原因**（根因 A）：`board.css:487`
```css
.tool[aria-pressed='true'] { background: var(--primary); color: var(--on-primary); }
```
两个变量都未定义 → 两条声明都失效。`aria-pressed` 本身设置得是对的。同样失效的还有：标签页选中态（`board.css:636`）、操作条主按钮与「小/中/大」选中态、粗细按钮选中环、选择框与手柄描边（`board.css:264,325`）。

**修改方案**：修根因 A 后自动恢复。另建议：

- 选中态：`background: var(--accent); color: var(--on-accent)`，加 120ms 背景过渡。
- 当前工具是画笔/荧光笔时，按钮图标下方加一个当前颜色的小圆点，不用打开选项条也知道颜色。
- 选项条（颜色、粗细）改为**锚定在当前工具按钮正上方**的小气泡，而不是固定在工具栏中间上方，让「哪个工具的选项」一目了然。
- 工具栏左端加「撤销 / 重做」，右端加分隔线后的「贴纸」按钮（贴纸是打开面板，不是一种工具，不应与工具共用按下态）。

### 问题 7　文字工具打字时不会替换「新文本」

**原因**（旧 P3-6）：新建文字的内容就是「新文本」（`Board.jsx:198`），进入编辑时 `BoardItem.jsx:41-51` 用 `range.collapse(false)` 把光标放在末尾。便签的「新便签」同理（`Board.jsx:469`）。

**修改方案**

- 新建时内容为空字符串，用占位提示代替默认文字：
  ```css
  .text-inner:empty::before, .note-text:empty::before {
    content: attr(data-placeholder); color: var(--placeholder); pointer-events: none;
  }
  ```
  `<div className="text-inner" data-placeholder="输入文字" ...>`
- 进入编辑时：内容为空 → 光标放在开头；双击已有文字进入编辑 → **全选**（`range.selectNodeContents` 后不 collapse），与 Figma、Keynote 一致。
- 结束编辑时内容仍为空：直接删除该对象，不进入「最近删除」，避免产生看不见的空对象。
- 文字对象尺寸随内容自动增长：结束编辑时测量 `scrollWidth/scrollHeight`，写回 `frame.w/h`（最大宽度 480，超出自动换行）。现在固定 160×48，长文字溢出，选择框不跟着变（另见 N-2）。
- 编辑中按 Esc：提交并退出编辑（现在被 `Board.jsx:644` 的 `if (editingId) return` 吞掉，旧 P3-2）。
- 中文输入法：在 `compositionstart/compositionend` 期间不要触发任何快捷键或提交。

## 四、根因 A 的统一修法

两步走：先加映射立即止血，再逐步替换为正式 token 名。

**第一步（立即）**：在 `board.css` 顶部，把原型变量映射到正式 token，作用域限定在白板内：

```css
.board-container {
  --primary:    var(--accent);
  --on-primary: var(--on-accent);
  --panel:      var(--optical-panel);
  --edge:       var(--optical-edge);
  --page:       transparent;          /* 让外壳的 --page-background 透出来，与地图页、行程页一致 */
  --r-sm:       var(--radius-sm);
  --r-md:       var(--radius-md);
  --r-xl:       var(--radius-xl);
  --round:      inherit;              /* 原型的圆体字体栈，正式应用沿用全局字体 */
  --f-caption:  var(--fs-caption);
  --f-meta:     var(--fs-meta);
  --f-body:     var(--fs-body);
  --f-title:    var(--fs-title);
}
```

同时删除 `board.css:5-16` 在 `:root` 上重复声明的 `--f-*`、`--peer-*`（`--peer-*` 与 tokens.css 重复；`--f-*` 改由上面的映射提供）。`--ik` 保留，但要由 JS 按 `1 / view.k` 写入（旧 P2-4）。

**第二步（随本轮重构）**：`board.css`、`widgets.css` 直接改用正式名称，删除映射；加上 N-6 的检查脚本防止回归。

修完这一步后，请在 1280 宽度、森林绿/海图蓝 × 浅色/深色四种组合下各截一张图，确认面板底色、边框、选中态都正常；「减少透明效果」开启时面板应为不透明底（`--optical-panel` 在该模式下已由 token 覆盖）。

## 五、界面结构重设计

### 现状的空间问题（1280 宽度）

- 侧栏完整展开约 400px（含外边距），白板实际只用到右侧约 2/3。
- 顶栏 84px 是实体条，下面白板又有一行「合肥 · 白板」和两个按钮，画布顶部约 150px 都是界面元素。
- 贴纸面板浮在画布正中下方，打开后挡住最常用的中心区域。
- 工具栏只有 6 个按钮，缺少缩放、撤销等每天要用的功能，反而把「最近删除」这种低频功能放在显眼位置。
