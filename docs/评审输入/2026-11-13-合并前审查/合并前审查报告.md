## 三、P1（合并前应修）

### P1-1 两人同时删除（或恢复）同一个白板对象，后到的一方整段旅程的同步被卡住 —— 已修复

- 位置：`app/server/model.mjs` generation 校验；客户端 `app/src/sync.js:898-905`。
- 问题：服务端对 delete/restore 先比较 generation，不一致就报 `STALE_GENERATION`（409）。客户端 `flush` 对任何非网络错误都把该操作标记为 `blocked`，并暂停这段旅程后面的全部操作（包括行程、费用的修改），直到用户打开同步面板手动放弃或重试。
- 触发条件：两位成员在对方的变更还没同步过来之前擦掉同一条笔迹、删除同一张贴纸，或都点了撤销。白板是多人实时编辑，这种情况很容易出现。
- 后果：后到的一方状态变成「同步受阻」，之后的修改只留在本机。
- 修复：目标状态已达成的 boardItem 删除/恢复视为空操作。generation 过期且会改变状态的请求仍然是 409；其他对象类型不变。
- 测试：已覆盖（见第二节）。
- 没有覆盖的部分见 P2-3。

### P1-2 生产环境上传 2MB 以上的「我的表情」会被 nginx 拒绝 —— 已修复

- 位置：`app/ops/journey.nginx.conf`；服务端 `app/server/index.mjs:111`。
- 问题：服务端允许表情最大 5MB（GIF 原样上传），但 nginx 只给 `/api/trips/*/assets/` 放宽到 6m，`/api/me/stickers/` 仍是全站的 2m。
- 触发条件：在生产环境上传 2–5MB 的 GIF 表情。本地开发不经过 nginx，所以测试发现不了。
- 后果：nginx 返回 413 的 HTML 页面，界面只能显示笼统的失败提示。
- 修复：路由正则改为 `^/api/(trips/[^/]+/assets|me/stickers)/`。**服务器上的 nginx 配置需要用新版本更新**（见第七节）。
- 测试：已覆盖（见第二节）。

### P1-3 手机触屏：点一下便签或文字就会弹出软键盘 —— 未修改，待决定

- 位置：`app/src/components/Board.jsx:1921-1927`（`armTyping`）、`2565-2580`（隐藏的 `<textarea class="type-catcher">`）。
- 问题：「选中即打字」在选中单个便签/文字后立刻让隐藏输入框获得焦点，没有区分鼠标和触屏。松手时的调用（`endGesture` → `armTyping`）发生在用户手势之内，iOS Safari 和 Android Chrome 都会因此弹出软键盘。
- 触发条件：手机或平板浏览器里点一下便签/文字（只想选中、移动或缩放）。
- 后果：每次选中都弹键盘，挡住半个屏幕，视口高度变化还会带动布局。
- 依据：这是读代码得出的结论，**没有在真机上验证**。此前的浏览器验收只用了 390px 视口，没有模拟触屏和软键盘。
- 建议改法：记录最近一次 `pointerdown` 的 `pointerType`，为 `touch` 时 `armTyping` 直接返回；触屏仍然通过双击进入编辑。改动约 5 行。
- 测试：目前没有。建议加一条 `hasTouch: true` 的端到端测试，断言点选便签后 `document.activeElement` 不是 `.type-catcher`。
- 没有直接修的原因：这是界面行为修改，本环境无法运行浏览器测试，不想把没跑过的界面代码推到 dev。

## 四、P2（可以合并后再修）

### P2-1 用手柄缩放笔迹，选中框变了、线条不变（交付文档风险点 8，确认是缺陷）

- 位置：`app/src/board.js` `scaled()` 的默认分支（约 229 行）；`app/src/components/BoardItem.jsx:303-307`。
- 问题：笔迹的点是相对 frame 原点的固定坐标，SVG 没有 `viewBox`，路径也没有缩放。单选时四角手柄会显示，拖动后只改 `frame.w/h`。实测：100×50 的笔迹缩放 2 倍后 frame 变为 200×100，路径仍是 `M0 0L100 50`。多选整体缩放时笔迹同样不缩放，只是位置移动。
- 后果：框和线对不上，而且错误的 frame 会保存到服务端，影响对齐参考线、「适应全板」和导出范围。不丢数据。
- 这一条在 11-10 代码审查里已经列为 P2（「笔迹缩放不渲染」），之后几轮没有处理。
- 建议改法：渲染时按 `frame.w/h` 与点的自然范围之比缩放点坐标（线宽不变），`strokeHit` 用同一组缩放后的点。
- 测试：无。

### P2-2 白板增量轮询的响应乱序时，会用旧数据覆盖新数据

- 位置：`app/src/board-sync.js:376-421`（`onTripChange` 回调）。
- 问题：每个 SSE `change` 事件都发起一次拉取，互不等待。较早发出的请求如果较晚返回，会把较新的对象版本覆盖回去，并把 `cursorRef` 调回较小的值；之后要等下一次变更才能纠正。
- 触发条件：短时间内连续多次变更，且两个响应的到达顺序颠倒。服务端单线程顺序处理，概率低。
- 建议改法：同一 epoch 下丢弃 `res.cursor < cursorRef.current` 的响应，或把拉取串行化。
- 测试：无。

### P2-3 白板操作被服务端拒绝后不回滚，并且阻塞整段旅程的队列（已知遗留，现状未变）

- 位置：`app/src/board-sync.js` 的 add/patch/delete/restore；`app/src/sync.js:898-905`。
- 现状：P1-1 只解决了「目标已达成的删除/恢复」这一种最常见的情况。`VALIDATION`、`BOARD_FULL`、`INVALID_REFERENCE` 和真正冲突的 `STALE_GENERATION` 仍然会阻塞队列；本地对象不回滚，`Board.jsx` 里也没有任何针对被阻塞操作的提示，只能靠全局同步面板处理。
- 测试：无。

### P2-4 撤销不能还原「新增的样式字段」

- 位置：`app/src/components/Board.jsx:376`（`recordPatch`）与 `app/src/board-sync.js` `patchBoardItem` 的样式合并。
- 问题：撤销记录保存的是修改前的整个 style，但 `patchBoardItem` 把它与当前 style 合并（`{...target.style, ...patch.style}`），合并无法删除字段。
- 触发条件：对象原本没有某个样式字段，例如地图小组件第一次设置「地图外观」（`mapStyle`）后按撤销。
- 后果：撤销无效，外观不变。
- 依据：读代码得出，没有在浏览器里复现。
- 建议改法：撤销/重做时用记录的 style 整体替换，不做合并。
- 测试：无。

### P2-5 富文本只在 Web 客户端清洗，服务端只限制长度

- 位置：`app/server/model.mjs:30`（`html: z.string().max(8000)`）；`app/src/rich-text.js`；`app/src/components/BoardItem.jsx:92-103,139,188`。
- 现状：Web 端在渲染前和保存前都调用 `sanitizeRichText`。清洗器按白名单重新拼出标签和属性，文本一律转义，我没有找到绕过方式；`tests/board-rich.test.mjs` 有覆盖。当前 Web 端没有 XSS 风险。
- 风险：服务端原样保存任意 HTML。以后任何新的渲染端（原生白板、邮件、另一种导出）只要漏掉清洗就是存储型 XSS。
- 建议改法：`model.mjs` 已经从 `../src/` 引入模块，可以在 note 的 schema 里对 `html` 调用同一个 `sanitizeRichText`；同时把 `rich-text.js` 加进 `ops/package-release.mjs` 的复制列表。

### P2-6 离线超过 15 秒后重连，未同步的白板修改会短暂消失或闪回

- 位置：`app/src/board-pending.js:4`（`PENDING_TTL = 15000`）、`reconcilePending`。
- 问题：本地待确认修改只保护 15 秒。重连后第一次拉取返回的是服务端旧副本，此时保护已过期，离线期间新建的对象会从画面上消失、修改会闪回，等队列发送完再拉取才恢复。如果队列被阻塞（见 P2-3，或离线操作被判为 `CLOCK_UNCERTAIN`），就不会自动恢复。
- 依据：读代码得出，没有在浏览器里复现。
- 建议改法：对象还有未发送的队列操作时不让保护过期。

### P2-7 每次白板操作都会让所有在线成员重新拉取整份旅程快照

- 位置：`app/server/index.mjs` operations 路由（每次变更都推进旅程 cursor 并 `notify`）；`app/src/sync.js:620-641`。
- 问题：画一笔就是一次操作。旅程里所有在线成员（包括停在行程页、费用页的）收到 `change` 后都会 `refresh()` 拉取完整快照（不含白板对象）。
- 后果：只是多余的请求和重新渲染，不影响正确性；多人同时画图时请求量明显。
- 建议改法：`change` 事件带上变更种类，只有非白板变更才拉取快照。

## 五、P3（建议）

- **表情库的读改写用的是请求开始时读到的用户偏好**（`index.mjs:111` 等）：同一账号两个标签页同时上传表情，后完成的会覆盖前一个的列表项。界面内的多文件上传是逐个进行的，不受影响。
- **create 的幂等放宽适用于所有对象类型**（`model.mjs:167`）：同一 id、同一类型的第二次创建一律返回成功且不比较内容。id 是客户端生成的 UUID，实际碰撞只来自重试，可以接受；建议在 `CONTRACT.md` 写明。
- **`ORIGIN_REJECTED` 的提示文案里有 `APP_ORIGIN` 环境变量名和服务端配置的网址**（`index.mjs:60`），普通用户看不懂；11-10 审查已提过。
- **恢复备份时先替换数据库再安装素材**（`ops/backup.mjs:164`）：素材安装失败会留下「新库 + 旧素材」。建议先准备好再一起切换，或在失败时回滚数据库。
- **`ASSETS_PATH` 未配置时的实际表现与文档不同**：`journey.service` 设了 `ProtectSystem=strict` 且只允许写 `/var/lib/journey`，默认的相对路径 `data/assets` 落在发布目录里，结果是上传直接 500，而不是「下次发布丢失」。建议服务启动时检查目录可写并给出明确日志。
- **导出**：WebKit 把含 `foreignObject` 的 SVG 画到画布后会判定为被污染，代码已捕获并提示换用 Chrome/Edge；跨域的地图瓦片在导出图里是透明的。两者都符合文档描述，但 iPhone/iPad 上等于不能导出，建议在界面上提前说明。
- **迁移 4 没有自动化测试**：建议加一条「旧结构数据库打开后补列」的单元测试。
- **默认白板的懒创建在 GET 请求里写库且不推进 cursor**（`index.mjs:101`）：11-10 审查的 P3，现状未变。
