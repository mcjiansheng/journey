## 二、草案方案评估

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 顶部悬浮区 + 底部抽屉，`ResizeObserver` 计算上下留白，重算 `setFitView` 与选中居中（006） | 改造后采纳 | 方向正确。草案改动超过 1300 行，拖拽手势重复实现两套；精简后采用 |
| 恢复 `+` / `−` / 定位竖排按钮，随抽屉上移，抽屉过高时隐退（007） | 采纳 | 改动小、收益明确 |
| 手机图例收进顶部“图例”开关，弹层支持外部点击、`Esc` 关闭（008、019） | 采纳 | 同时释放左下角空间 |
| `.map-actions` 不折行、主按钮 1.25 : 1 : 1（018） | 采纳，但不改桌面字号 | 草案把全端按钮字号降到 `--fs-meta`，与“桌面保持不变”不符 |
| 收藏标记在手机端折叠为摘要行（019） | 采纳 | 桌面侧栏高度充足，保持内联 |
| 地图子视图隐藏底栏，左上角改为“返回地图总览”（021） | 采纳（2026-11-22 用户确认） | 抽屉改为**两段式**（半屏 / 全屏 + 把手拖动），不做草案的三段跟手拖拽与列表触顶接管 |
| 无 Key 时用 `temp-amap.js` 假地图替代（020、008 一部分） | **不采纳** | 假地图同时替换了搜索、地理编码与路线：任意地址解析为杭州、未收录目的地时区判为 `Asia/Shanghai`、路线时长按直线估算，且以 `provider: 'amap'` 写入共享行程；1372 行演示数据进入生产包；导致 `map-controls.spec.mjs` 无 Key 提示用例失败 |

草案中需要注意的其他问题（改造时一并避免）：

- 地点详情点“更多操作”后再点 `×`，`expanded` 未复位，会进入收藏列表而不是地图总览。
- `place-information.spec.mjs` 用了 Playwright `boundingBox()` 不存在的 `bottom` 字段，该断言恒为假。
- 实施记录把无 Key 提示用例的失败写成“与基线一致的环境差异”，实际由草案引起。
- `exitSubViewRef.current` 在渲染中赋值；760px 断点在 JS 中重复 5 次。
