## 三、动态复现（关键 P0/P1）

以下探针均使用 `app/server/index.mjs` 的 `createApp`（内存或临时 SQLite），不入库、不修改仓库文件。

### 3.1 P0：服务端重启后白板本机内容被清空且缓存被污染（已复现）

Playwright 脚本：注册 → 建旅程 → API 创建 1 个便签 → 进入白板（显示 1 个元素）→ 关闭并以同一 SQLite 数据库重启服务（epoch 1→2，页面保持打开）→ 等待 SSE 重连 → 统计页面元素并刷新。

```text
setup: boardId=default-board, item created (receipt changed:true, cursor:1)
items before restart: 1
new server snapshot: { cursor: 1, epoch: 2 }
items after reconnect: 0
items after reload: 0
server items after reload: { count: 1, cursor: 1, epoch: 2, states: ["active"] }
```

结论：服务端数据完好（1 个 active 对象），客户端在 epoch 失配时把“带 since 的增量结果”当成全量替换，随后刷新仍从被污染的 IndexedDB 缓存读取 → 本机视图持续为空，无法自愈。

### 3.2 P1：地点小组件「加入行程」提交被服务端拒绝（已复现）

```text
A. create activity with ordinal:99 => 422 {"code":"VALIDATION","message":"Unrecognized key: \"ordinal\""}
B. patch boardItem linkedActivityId to nonexistent activity => 422 {"code":"INVALID_REFERENCE",...}
```

客户端 `Board.jsx:582-607` 的 patch 含 `ordinal: 99`，而 `schemas.activity` 为 `.strict()` 且无该字段；第二步 `linkedActivityId` 指向未创建的活动。

### 3.3 P1：白板元素编辑后删除/恢复返回 409（已复现）

```text
create boardItem (note) => 200
patch boardItem (z)      => 200, receipt changed:true
server generation after patch: 0        # 服务端 patch 不递增 generation
delete generation:1 (client 本地自增后) => 409 STALE_GENERATION (details.generation=0)
delete generation:0                      => 200
restore generation:0 (删除后本地应为1)   => 409 STALE_GENERATION (details.generation=1)
```

客户端 `patchBoardItem` 每次本地 `generation+1`，delete/restore 又用本地值提交；服务端只在 delete/restore 时递增 → 任何“编辑过再删除”的序列都会被 409 拒绝并阻塞该旅程同步队列。

### 3.4 P1：倒计时/费用小组件读取 `visibleDays()` 层级错误（已复现）

```text
countdown: {"startDateLabel":"未定日期","startWd":"","endMd":"","days":3,"totalDays":3}
expense:   {"perDay":[0,0,0],"top":[{"title":"午饭钱","dayText":"未记日期",...}]}
```

`visibleDays()` 返回 `{payload:{date,ordinal}}`，而 `board-widgets.js` 直接读 `firstDay.date` / `d.date` / `d.ordinal` → 有日期的旅程仍显示「未定日期」，费用柱状全 0、支出条目永远「未记日期」（该笔费用已通过关联活动落在第 2 天）。
