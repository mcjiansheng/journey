## 一、审查范围与结论

范围（`Board.jsx` 857、`BoardItem.jsx` 262、`BoardStickerPanel.jsx` 299、`BoardToolbar.jsx` 168、`BoardActions.jsx` 116、`BoardRecentDeletions.jsx` 58、`board.js` 259、`board-sync.js` 678、`board.css` 783、`App.jsx` / `usePageNavigation.js` / `ui.jsx` 的白板接入、`tests/e2e/board.spec.mjs`、`tests/board.test.mjs`；为判断渲染/数据来源另读了 `widgets/*`、`board-widgets.js`、`sync.js`、`server/model.mjs`、`server/index.mjs`）。

**独立验证（本机实跑，非推断）**

```text
node /tmp/probe-board.mjs（直接起 server/index.mjs，按客户端真实参数序列操作）
create place widget                -> 200
schedule place activity(ordinal)   -> 422 VALIDATION: Unrecognized key: "ordinal"
patch boardItem linkedActivityId   -> 422 INVALID_REFERENCE
create note / patch frame          -> 200 / 200
delete with client generation=1    -> 409 STALE_GENERATION (details.generation=0)
delete with server generation=0    -> 200
node --test tests/board.test.mjs   -> 8 pass / 0 fail
```

E2E 未执行：DSH 沙箱不允许启动 Chrome/WebKit（与 README 二节的限制一致），以 `06-验证记录.md` 为准；`board.test.mjs` 只覆盖纯函数，不覆盖下列任何交互/同步缺陷。

**结论：不建议在修复前合并 main。** 有 3 个 P1：一个是**必现**的功能失败并会卡死该旅程的同步队列（点一次「加入行程」即触发），一个在**离线/同步回读窗口内**必现（编辑后删除被服务端拒绝），一个在**服务端重启或部署后**必现（白板大部分内容从本机视图且从本地缓存永久消失，服务端数据仍在）。P2 以交互（手势/缩放/操作条）、乐观更新一致性、在线提示、性能与可访问性为主。

## 四、测试与验证缺口

## 五、需复核项

1. **P1-3 的动态复现**：代码路径确定，但我未能在本机复现「服务端重启 + 页面保持」。建议 Lead 用 `createApp` 起两个先后进程、复用 sqlite 文件、页面保持连接验证一次（预期：一次 `change` 后 items 只剩变化项）。
