## 二、P0（合并前必须修复）

### P0-1｜服务端重启/部署后，白板本机内容被清空且无法自愈〔已动态复现〕

- **位置**：`app/src/board-sync.js:297-333`（306-314 行为核心）、`248-290`；`app/server/security.mjs:114-119`、`app/server/index.mjs:56,101`。
- **机制**：服务端每个进程生命周期 `epoch+1`。白板页面在 SSE 重连后收到 `change`，`onTripChange` 用本地 `since=cursor` 拉增量；当 `res.epoch !== epochRef.current` 时未丢弃 `since`，而是直接把**增量结果**当作全量替换 `items`，并 `writeBoardCache` 覆盖 IndexedDB。`loadData` 同样不比较 epoch，刷新后仍按被污染的 cursor 读缓存。
- **复现（本次实测）**：建旅程 → 白板 1 个便签 → 以同一 SQLite 重启服务（epoch 1→2）→ 页面不刷新等待 SSE 重连：

  ```text
  items before restart: 1
  new server snapshot: { cursor: 1, epoch: 2 }
  items after reconnect: 0
  items after reload: 0
  server items after reload: { count: 1, epoch: 2, states: ["active"] }
  ```

- **影响**：每次部署/重启，所有正在打开白板的用户会看到自己的白板变空；服务端数据虽在，但本机缓存已被污染，刷新/重进无法恢复，用户可能重建内容造成重复。按“用户可感知的数据丢失”定为 **P0**。
- **依据**：设计 `10-白板.md:198`「epoch 与本地缓存不同 → 清空本地缓存并全量重读」。
- **修复建议**：两个入口统一处理——epoch 失配时丢弃 `since` 全量重读并覆盖缓存；`loadData` 同样比较 epoch。补一条“重启服务 + 页面保持”的自动化回归（可参考本次 Playwright 复现脚本）。

## 四、P2（下一迭代修复）

### 4.1 白板客户端（01/02）

- **失败不回滚**：乐观写入后服务端拒绝（VALIDATION/BOARD_FULL/STALE_GENERATION/INVALID_REFERENCE）只标记 blocked，本地 items/缓存不回滚 → 本机永久保留“同伴看不到”的幽灵对象（`board-sync.js:440-539,265-283`）。
- **手势卡死**：拖动/缩放未 `setPointerCapture`，也不校验 `e.buttons`；在工具栏/窗口外松手后对象继续跟鼠标（`Board.jsx:373-429`）。
- **缩放不合规**：React 19 下 `onWheel` 的 `preventDefault` 无效（passive），Ctrl+滚轮触发页面缩放；触屏无捏合；范围 0.15–3.0 ≠ 规格 10%–400%（`Board.jsx:347-370`、`board.css:27-38`）。
- **手柄尺寸随 zoom 变化**：`--ik` 从未被 JS 写入（`board.css:15,264-357`）。
- **笔迹缩放不渲染**：只改 frame，SVG 无 `viewBox`/缩放（`BoardItem.jsx:184-198`、`board.js:133-136`）。
- **性能**：BoardItem/Widget 无 memo，`widgetDeps()` 全仓无调用（仅测试）；实测 2030 objects 下 20 个小组件 18ms/帧；拖动每个 pointermove 全量重渲染（`Board.jsx:743-783`、`board-widgets.js:69`）。
- **presence 抖动**：心跳（5s）用空值覆盖 selected/editing，同伴选中框每 5 秒消失；本地 live 帧提交后不清理导致“改数据画面不变”（`board-sync.js:374-430`、`Board.jsx:262,332-343`）。

- **缺功能**：撤销/重做（`undoStack/redoStack` 只声明未用）、删除 5 秒撤销、GIF 显示规则（同屏数量/减动静态帧）、thumb 变体从未使用、画笔不能从对象上起笔、键盘可访问性、面板预览未按 0.52 缩放、软占用/修改闪现/头像跳转（`Board.jsx`、`BoardItem.jsx`、`BoardStickerPanel.jsx`）。
- **小组件/标记**：正午日程小组件白字对比度 3.28:1（玻璃面板 ≈2.71:1），而对比度门禁校验的是另一色值 `#2f7abc`（4.53:1）→ **门禁假通过**；时钟时差四舍五入到整小时（印度 2.5h→2h）；日期区间 >365 天按钮静默禁用无提示；跨午夜「今天」不刷新（`board.js:221-222`、`check-design-contrast.mjs:23-36`、`board-widgets.js:447-457`、`DateRangePicker.jsx:38-50`、`Itinerary.jsx:430,444-459,599-605`）。

## 七、测试与门禁评估

**通过项**：143 项单测、43 项白板/后端/配置测试（审查员复跑）、33 项部署脚本测试、Token/时区/对比度（90 项）/Prettier、生产构建、白板 4 条 E2E 均通过；鉴权、CSRF/Origin、上传 magic bytes/nosniff/不可变缓存、路径注入防护等安全检查未发现越权或注入面（见 [03](03-服务端白板与协议.md) §一）。

**缺口**：

1. **关键路径无测试**：`board-sync.js` 客户端无单测；epoch 失配、generation 漂移、加入行程失败链、presence 全局限流耦合、跨端 mark 契约、KRW 币种、`visibleDays` 层级均无用例。
2. **E2E 只断言乐观 UI**：白板便签“删除/恢复”用例在服务端 409 时仍通过（本机状态先变）；即“E2E 全绿”不能证明操作被服务端接受。
3. **CI 不跑 E2E**（见 4.5）；对比度门禁值漂移且未进入 dev 触发路径。
4. **`dev` 的 E2E 套件本身不是全绿**：本次定向套件 **92 通过 / 13 失败**（14 个 spec，13.5 分钟）。与 `origin/main` 基线对照后：`itinerary-review` 的 2 条（活动菜单新增“贴到白板”未同步断言）与 `place-information` 的 1 条（活动名已改为 placeholder，测试仍期望地点名自动填入）可确认是 **dev 测试期望过期**；`map-retention`/`map-selection`/`place-information` 的“真实 AMap”类失败在 `origin/main` 上同样复现（同机 14 条失败），**不是本次 diff 引入**；`favorite-place-picker` 是 dev 新增 spec，其 390/320、空收藏、移动端占位名 4 条失败需 dev 侧修复或说明；`navigation` 的 WebKit 超时需干净环境复跑（对照见[08](08-验证记录.md) §2.5）。
5. **本轮 E2E 未能全量验证**：全量 216 项在 40 分钟内只完成 42 项，多项 WebKit/atlas 用例 60s 超时（WebKit 单独冒烟可启动），疑为测试环境（字体/动画等待、视图仿真）或既有用例稳定性问题，未取得可归因于本次 diff 的证据；建议 CI/干净环境复跑。
