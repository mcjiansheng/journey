### 04-01（P1）目的地定位失败静默降级到默认城市，无提示/重试

- **代码路径**：`resolveMapCamera` 在 geocode 抛错、返回空坐标或 `plan.source==='empty'` 时不再抛错，改为 `resolveFallbackCamera`（`map-camera.js:83-97`、`:62-82`）→ 取 `currentCityFromAmap(AMap)`，取不到就是硬编码 `DEFAULT_CITY_CENTER = [116.397128, 39.916527]`（北京天安门，`:10`）→ `MapView.jsx:370-375` 用它建图；`persistCamera('current-city')` 存盘（`:408-411`）。`mapError` 只在**地图初始化异常**时设置（`MapView.jsx:456-462`），geocode 失败不进该分支，因此 `:1124-1185` 的"地图暂时无法加载/重试"不会出现。
- **触发/复现**：旅程目的地填 `nju`（或英文/非标准地名，实施记录称为生产真实场景），或地理编码服务返回 `status:"0"` → 打开地图。项目自带证据 `.local/evidence/1110-map-geocode-fallback/fallback-390.png` 显示：无任何提示，底图为**北京天安门/北京西站**，搜索栏可用；新增 E2E 还断言 `.map-offline-message` 数量为 0（`map-search-picking.spec.mjs:233`）。
- **影响**：用户以为看到的是旅程目的地所在城市；在该视图里"地图选点/收藏/加入行程"会把无关城市的地点写进旅程（Place 带 GCJ-02 坐标，正式数据）。且"回退到用户当前城市"这一本轮用户需求在 `getConfig().defaultLocation` 缺失时并未满足，落成固定北京。
- **依据**：SRS `01-软件需求规格说明书.md:85`（C25"目的地查询失败提供重试，不自动显示其他城市作为目的地"）；`02-交互与界面设计稿.md:133`（"显示重试入口，不呈现无关城市的默认视野"）、`:188`（"查询失败就地提供重试"）；本轮用户需求原文（`docs/实施记录/2026-11-10-地图地理编码容错降级.md:3`）只要求"回退+保留搜索"，未取消重试要求。
- **建议**：降级时在面板给出可关闭状态条：「未能定位「nju」，已显示当前城市」+「重试定位」按钮（重跑 geocode，`cameraSource` 允许覆盖）；取不到 IP 城市时不要用固定北京冒充"当前城市"，改为空态提示或取旅程已有活动/收藏中心。保留搜索可用（已做到）。

### 04-02（P2）拖动/缩放结束全量重建标记

- **代码路径**：`moveend`/`zoomend` 里 `setMapRender(n=>n+1)`（`MapView.jsx:413-420`）→ 标记 effect（deps 含 `mapRender`，`:718`）先 `m.remove(markers.current)` 再对每个点重建 `AMap.Marker`+DOM+SVG+`AMap.LabelMarker`（`:489-533`）；CSS 给 `.favorite-marker` 加了 150ms 淡入（`map-markers.css:128-143`）。
- **触发/复现**：有 ≥1 个收藏时拖动地图松手——所有收藏标记重新创建，150ms 淡入全部重播一次；用 Tab 聚焦某个标记后按方向键平移，`moveend` 后旧按钮节点被移除，焦点回到 `body`。
- **量化**：`clusterPlaces` 在"点间距刚超过合并阈值"的常见形态是纯 O(n²)（每对都新建 `Set`/数组）。本机基准：200 点 8.8ms、300 点 17.3ms、500 点 32.7ms、800 点 79.2ms（单次，主线程），叠加 500 个 Marker/LabelMarker 的创建与销毁；移动端按 3–5 倍估算。另外每条路线都调用一次 `getComputedStyle(document.documentElement)`（`:686-688`）可提到循环外。
- **影响**：违反 2026-11-03 §2.3"合并、拆开时淡入淡出 150ms"（现在是无变化也淡入）与"只在结束后重算，过程中保持上一次结果"的精神；收藏多时每次平移/缩放都有明显抖动与掉帧；键盘用户每次平移丢失操作位置。
- **建议**：标记实例复用（只更新 position/内容），分组无变化时不动 DOM；淡入只作用于新建/新合并出的标记；`mapRender` 加 100–150ms 防抖；`clusterPlaces` 内把每组 markKey 集合缓存在组上，避免每对重建 `Set`。

### 04-03（P2）混合聚合标记超出命中区且与设计稿不符

- **代码路径**：混合组把最多 3 个 `<svg>`（各 26px）塞进 `.marker-graphic`（`map-marker.js:64-79`），`.mixed-marker .marker-graphic{width:auto;min-width:48px}`（`map-markers.css:118-123`）实际渲染约 78px 宽、`left:9px`，而外层 `.place-marker` 仍是 44×44（`map-markers.css:2-14`），AMap 偏移固定 `Pixel(-22,-22)`（`MapView.jsx:524`）。
- **触发/复现**：两个不同标记的收藏在屏幕上距离 <24px（或同坐标）→ 出现 3 图标混合聚合点；点最右侧图标（落在 button 之外）无反应，只触发地图点击；右上角数量角标还压在第 2 个图标上。
- **影响**：聚合点的可视中心偏离真实坐标约 +26px；30–40% 可见区域不可点，44px 触摸目标要求被破坏。另：设计稿要求"白色小胶囊"且同标记聚合"稍大一号"（§2.3 规则 2/3），实现没有胶囊底、尺寸未放大。
- **依据**：`02-交互与界面设计稿.md`§5（44px 目标、密集点聚合）；2026-11-03 §2.3 规则 2/3；`map-markers.css:1` 注释自述 44px 命中区。
- **建议**：混合标记用固定尺寸胶囊（如 56–64px 宽、白底、3–4px 内边距）并同步 AMap offset；数量角标改定位到胶囊右外侧；同标记聚合放大到 ~30–32px。

### 04-04（P2）图例/标记筛选只认活跃预设

- **代码路径**：`usedPresets` 只保留"有收藏使用且存在活跃预设"的组合（`MapView.jsx:107-118`）；图例（`:1098-1117`）与筛选面板的"标记"组（`:1268-1293`）都只遍历 `usedPresets`。收藏的 `mark` 是自存组合（CONTRACT 明确"不保存预设引用"）。
- **触发/复现**：① 给收藏选"三角+珊瑚红"但不点"存为预设"→ 地图上有珊瑚红三角，`.map-legend` 完全不出现、筛选面板无该项；② 删除某预设 → 使用它的收藏保留标记（服务端 `model.mjs:171-174` 按契约保留），但图例条目与筛选 chip 一起消失。E2E 把这两种偏差写成了预期（`map-layers.spec.mjs:124`、`:148`，且 `:131` 断言**不含**"未命名"）。
- **影响**：用户无法按自己实际使用中的标记筛选/统计；删除预设后"图例里变成未命名"的既定行为缺失；图例数量与地图上可见的标记种类不一致。
- **依据**：2026-11-03 §2.2「图例：列出本旅程用到的标记和数量，有名称的显示名称，没有的显示"未命名"」「删除预设：已收藏的地点保留原来的标记，只是图例里变成"未命名"」；`CONTRACT.md:65-67`。
- **建议**：图例/筛选改为按 `favorites` 中实际出现的 `markKey` 聚合（名称查预设，查不到显示"未命名"或 `markLabel`）；同步修正 `map-layers.spec.mjs:131/148` 的断言。

### 04-05（P2）聚合排序缺创建时间

- **代码路径**：`clusterPlaces` 按 `priority → createdAt → id` 排序（`map-clusters.js:5-11`），但 `MapView` 构造的点只有 `{id,x,y,name,mark,presetName,object}`/`{id,place,priority}`（`MapView.jsx:546-576`），从不传 `createdAt`；快照 Object 契约也不含创建时间（`CONTRACT.md:20` 只有 id/kind/payload/state/generation/clocks/expressions）。
- **影响**：排序实际退化为随机 UUID 字典序，决定同组首点（聚合点取的 payload 与名称顺序）、标签左右侧、混合图标次序。2026-11-03 §2.3 明确要求"三端用同一套合并算法…按优先级、再按创建时间排序（保证结果稳定）"，Web 与 iOS/Android 用同一份数据可能得到不同分组/文案。
- **建议**：协议补一个创建时间（如对象级 `createdAt`，或对 favorite/activity 用首个时钟时间）并在三端传同一值；若决定不补，则明确改为按 id 排序并同步文档与两端实现，避免"看似一致实则不一致"。

### 04-06（P2）城市兜底重试分支无有效测试

- **代码路径**：`searchCity` 把不含中文且不是 3–6 位数字的城市名归一化为 `''`（`amap.js:103-107`），因此目的地 `nju` 永远不会以 `city=nju` 发给高德；而新增 E2E 的 mock 恰以 `city==='nju'` 为条件构造 `USER_ABROAD_DAILY_QUERY_OVER_LIMIT`（`map-search-picking.spec.mjs:240-246`）—— 该分支不可达，`searchPlaces/suggestPlaces` 的 `isCityLookupError` 降级重试（`amap.js:108-109,115-123,131-139`）在测试中一次也没执行。
- **影响**：实施记录称"当携带 city 参数触发 ABROAD/INVALID 时自动降级重试"已被验证，实际未被覆盖；若空 `city` 时 SDK 仍自带 `city=全国`（该记录第 11 行称"全国"也会被判海外），重试请求与首次等价，线上仍会失败。
- **建议**：改用中文目的地（如"南京"）构造 INVALID/ABROAD 响应覆盖重试；或给 `amap.js` 抽一层可注入的 `placeSearch/autoComplete` 调用做单测；并实测空 city 请求实际发出的参数。

### 04-07（P3）地理编码依赖高德私有内部属性

- **代码路径**：`geocodeResponse` 探测 `geocoder._geocodingComplete/_onError/url/config.key/AMap.WebService.get` 后自行拼 REST 参数（`amap.js:147-184`）。这是为规避高德插件对 `status:"0"` 不回调的 15s 卡顿（实施记录已说明根因），但代价是与 SDK 内部实现耦合。
- **影响**：SDK 升级/压缩名变化时守卫失效→退回插件路径→回到 15s 超时；若方法名仍在但签名变化→回调不触发或空数据→`resolveMapCamera` 静默降级到当前城市（与 04-01 叠加，用户无感、无日志可查）。该分支产出的 `error.info` 目前也无消费者（`resolveMapCamera` 已吞错）。
- **建议**：集中封装并加注释/版本假设，给"守卫不成立"和"内部签名变化"两条路径各留一个单测（可注入假 geocoder）；换色板/升级 SDK 时作为回归项。
- **注**：该私有路径在新增 E2E 中经由真实 SDK 执行（该 spec 只 mock `_AMapService`），不会整体失效；风险在版本漂移。

### 04-08（P3）标记颜色硬编码未走地图 token

- `map-marker.js` 的 `#fffefa`（`:39,47,72,86`）与 LabelMarker 文本 `fillColor:'#1b3442'`（`:516`）、`map-markers.css` 的 `.marker-count` 白底/`#1b3442`（`:113-114`）、`.arranged` 白边（`:100`）都是字面值。2026-11-03 §2.1 已建立 `--map-accent/--map-accent-soft/--map-route/--map-route-marker` 并明确"颜色走 token、两色板各取浅色主色"，`--map-route-marker` 森林板是 `#294c68`、海图板是 `#1b3442`，所以森林板下标签/角标仍在用海图蓝墨色。
- **建议**：标签墨色、白边、角标底色改读 CSS 变量（或统一走 tokens），让对比度脚本能覆盖。

### 04-09（P3）管理预设的交互细节

- `MarkPicker.jsx:89-96` 删除预设一键执行，无确认（删除会影响全团队图例，虽按契约保留收藏标记）；`:72-88` "上移"用 N 次顺序 mutation 重写全部预设 order，中途失败会留下半新半旧顺序；`:70` 无名预设显示 `markLabel`（如"珊瑚红三角"）而不是设计稿的"未命名"。
- **建议**：删除加确认（复用现有 feedback/Modal 风格，避开 `window.confirm`，`:44`）；排序只 patch 相邻两条或改用一次批量；文字统一"未命名"。

### 04-10（P3）"贴到白板"失败无反馈

- `MapView.jsx:1556-1565` 直接 `pinWidgetToBoard(...)`，未 catch。`board-sync.js:632-662` 先写 IndexedDB 缓存再 `journey.mutate`，mutate 失败时会产生"缓存有、服务端无"的幽灵组件且界面无提示（同模式在 `Ledger.jsx:643`、`Itinerary.jsx:175/1394` 已存在，是否统一处理请 01/02 审查员裁定）。
- **建议**：调用处加 try/catch 并 `j.notify`/行内错误；pin 失败时回滚缓存写入。

## 三、需求一致性

**符合**（抽查确认）：目的地优先于收藏、按目的地绑定视口、活动/用户选择覆盖、AbortError 立即拒绝（`map-camera.test.mjs` 8 项）；相同标记 34/40px、混合 24/30px 双阈值与"悬浮后重算"（`map-clusters.js`、`map-markers.css` 淡入）；选中 > 当天活动 > 收藏的标签优先级与 8 字截断；聚合点击"能展开放大、18 级或近同点弹列表"；图例/筛选双主题取色（`--map-accent/--map-route*` 随 `data-palette` 由 MutationObserver 重绘）；`mark` 独立时钟、`mark=null` 显示黄星、新收藏恒为 null、预设按 icon+color 唯一、改组合服务端事务级联（`CONTRACT.md:65-67`、`model.mjs:128,171-174`）；reduced-motion 下 `setFitView/setZoomAndCenter` 立即到位；390 下键盘展开时隐藏主导航。

**不符合**：C25 的"失败重试 + 不呈现无关城市视野"（04-01）；"白色胶囊/稍大一号/2px 白边"视觉细则（04-03、04-08）；"图例未命名"（04-04、04-09）；"按创建时间排序保证三端一致"（04-05）；"自定义：选图标、选颜色，上方实时预览"——`FavoriteMarkEditor.jsx:91-100` 无预览区（MarkPicker 有），属实现细节偏差，归入 04-09 一并处理。

## 五、需复核项

1. **`AMap.getConfig().defaultLocation` 是否为公开/可用机制**：单测注入的是自造 `{getConfig:()=>({defaultLocation:[…]})}`（`map-camera.test.mjs:66,72-75`），E2E 未断言地图中心；项目自己的降级截图落到北京天安门（`DEFAULT_CITY_CENTER`），说明该环境下未取到 IP 城市。它决定 04-01 是"用户城市取不到时退回北京"还是"这条降级根本没生效"，也决定 04-01 是否维持 P1。
2. **`AMap.LabelsLayer({collision:true, allowCollision:true})`**（`MapView.jsx:697`）：`allowCollision` 的实际语义是否为"允许与底图文字重叠"；若是，则设计稿要的"名字与底图地名互相避让"失效。需真机截图确认。
3. **`LabelMarker` 的 `direction/offset` 与 `clusterPlaces` 返回的 `labelSide` 是否对应**（`MapView.jsx:509-518` vs `map-clusters.js:37-53`）：真 SDK 下左右侧偏移可能不按预期，需截图。
4. **空 `city` 时 SDK 实际下发的参数**：若仍为 `city=全国`（实施记录第 11 行称"全国"也判海外），`searchPlaces` 的一次重试等价于同一请求，线上仍会失败（04-06 相关）。
5. 11-10 用户需求「回退到当前城市 + 保留搜索」是否被视为**取代** C25 的"显示重试入口"：这是 04-01 定级的唯一判断分歧点，请 Lead 在合并报告中裁定。
6. `.map-legend`（`z-index:3`）与移动端详情面板（`.journey-map .map-panel{z-index:2}`）的层叠：我依据 390 截图判断不重叠，但截图里没有"有图例 + 详情面板"的组合，仍需 390/320 实机确认。
