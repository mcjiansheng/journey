## 三、分模块问题详情

### 模块 A：行程页（`Itinerary`）

#### <a id="mob-001"></a>MOB-001 · 日期选择 `<select>` 内残留矩形阴影框，下拉箭头偏右且与左右控件不齐
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/components/Itinerary.jsx`（`.mobile-day-bar`，1257–1315 行）
  - `app/src/components/itinerary.css`（145–172、321–343 行）
  - `app/src/styles.css`（844–856 行通用 `select` 规则；对比 `app/src/components/editor-ledger.css` 303–310 行）
- **问题现象与根因**：
  1. **隐约的矩形内边框**：通用规则 `styles.css:845-856` 为所有 `select` 设置了 `border-radius: var(--radius-sm)` 与 `box-shadow: inset 0 1px 2px ...`。`itinerary.css:158-168` 仅覆盖了 `border: 0; background: transparent;`，**遗漏了重置 `box-shadow: none` 和 `border-radius: 0`**，导致通透药丸工具条内部围绕 `<select>` 仍有一圈隐约的内阴影方框。
  2. **向下小箭头过度靠右且风格不一致**：`.editor-modal select` 已用 `appearance: none` + 自定义 SVG 箭头，但 `.mobile-day-bar select` 仍依赖浏览器原生外观且设置了 `flex: 1` 撑满中间宽度、左内边距仅 `5px`。结果文字 `"第1天 11/20"` 靠左，原生 `∨` 却被推到 `<select>` 最右边缘，中间留出大片空白并紧挨着 `>` 按钮，且原生箭头线条细度与两侧 `lucide-react` 的 `<`、`>` 图标不统一。
  3. **内部控件比例不协调**：`<` / `>` 按钮设为 `min-width: 40px`（`itinerary.css:170`），而右侧 `···` 使用 `.icon-button.compact` 为 `44×44px`（`styles.css:2443-2446`），外层 `.itinerary-toolbar` 又叠了一层 `padding: 4px` 与圆角底色，造成水平留白和圆形热区大小不均。
- **PC 端表现**：不复现（桌面端隐藏 `.mobile-day-bar`，改用 `.day-tabs` 横向标签）。
- **修复建议**：
  - 为 `.mobile-day-bar select` 补全 `box-shadow: none; border-radius: 0; appearance: none; -webkit-appearance: none;`。
  - 将移动端日期切换改用「文字紧跟小箭头（如 `ChevronDown`）」或居中紧凑排版（可用视觉展示按钮 + 透明覆盖 `<select>` 或自定义触发器，让箭头紧随日期文字右侧并统一 `lucide-react` 线宽）。
  - 统一 `<`、`>`、`···` 图标按钮宽高（建议均为 `44×44px`）与内外边距。

#### <a id="mob-002"></a>MOB-002 · 右侧 `···` 按钮与展开的 `.day-lifecycle` 面板不符合移动端交互逻辑
- **优先级**：P0
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/components/Itinerary.jsx`（1326–1418 行）
  - `app/src/components/itinerary.css`（321–330、363–369 行）
  - `app/src/styles.css`（140–142、1884–1897、1948–1950、2329–2335、2663–2668 行）
  - `app/src/components/date-expense-navigation.css`（159–162 行）
- **问题现象与根因**：
  1. **按钮自身无展开态，靠粘滞 `:hover` 显底色**：`Itinerary.jsx:1330` 输出了 `aria-expanded={dayMenu}`，但 CSS 中完全没有定义 `[aria-expanded='true']` 样式；展开时出现的浅绿圆形背景实际来自未限制设备的 `.icon-button:hover`，点完可能残留或突然消失，缺少明确的展开反馈。
  2. **展开在滚动流顶部，下滑后点击会“无可见反应”**：`.itinerary-toolbar` 设为了 `position: sticky; top: 0;`（`itinerary.css:322-324`），而 `.day-lifecycle` 写在 `.day-content` 内部最上方。用户向下滚动活动列表后再点吸顶的 `···`，菜单会渲染在页面顶部（当前视口之外），屏幕上看不到任何变化。
  3. **悬浮间隔与顺序冲突**：`styles.css:1893` 给 `.day-lifecycle` 写了 `margin: -6px 0 20px`，但 `itinerary.css:326` 给 `.itinerary-toolbar` 设了 `margin-bottom: 16px`，导致两者之间还隔出一条约 `10px` 的断层空隙；若当天存在 `.mobile-next-activity`（`下一项` 按钮），该面板甚至会出现在 `下一项` 的下方，逻辑割裂。
  4. **操作区混排如桌面文本链接**：移动端 `.day-menu-actions` 把 `调整顺序`、`与另一天交换`、`贴到白板`、`调整日期与天数`、`删除这一天` 以 `flex-wrap: wrap` 横向挤在卡片内，前三项无图标、后两项带图标，点按目标窄，且没有遮罩层或点击空白处关闭的能力。
- **PC 端表现**：部分复现。桌面端 `···` 同样缺少 `[aria-expanded='true']` 激活态，`.day-lifecycle` 同样无点击外部/按 `Esc` 关闭机制且按钮图标混排不一致，`.itinerary-toolbar`（`margin-bottom: 20px`）与 `.day-lifecycle`（`margin: -6px 0 20px`）之间仍有约 `14px` 断层空隙；区别在于桌面工具栏不吸顶且单行空间足够容纳所有按钮，不易出现手机端点击后视口外“无反应”的问题。
- **修复建议**：
  - 移动端点击 `···` 改为标准 **Bottom ActionSheet（底部操作面板）**（可复用白板 `.switcher-menu` 的底部抽屉形态或带透明遮罩的浮层），支持点击遮罩、按系统返回键关闭；桌面端同步改造为锚定 `···` 按钮的气泡菜单（Popover）并补齐点击外部与 `Esc` 关闭。
  - 操作列表采用「一行一项、全宽左对齐、`min-height: 48px`、统一前缀图标、危险操作（删除这一天）底部加分割线」的规范。
  - 为 `···` 按钮补充明确的 `[aria-expanded='true']` 激活态样式。

#### <a id="mob-003"></a>MOB-003 · 活动、账本与成员 `<details>` 更多菜单易被底栏遮挡且缺乏外部点击关闭
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/components/Itinerary.jsx`（1150–1187 行）、`app/src/styles.css`（2142–2196、2491–2505、3452–3478 行）
  - `app/src/components/Ledger.jsx`、`app/src/components/editor-ledger.css`（105–155、160–166 行）
  - `app/src/components/Settings.jsx`（132–148 行）
  - （对照参考：全站仅白板组件 `BoardContextMenu.jsx:52`、`BoardStickerPanel.jsx:154`、`BoardSwitcher.jsx:52` 实现了外部 `pointerdown` 关闭）
- **问题现象与根因**：
  - `.activity-more-panel`、`.expense-more-panel`、`.member-more-panel` 均采用 `position: absolute; right: 0; top: 45px~48px` 固定向下展开，而移动端底部存在悬浮的 `.bottom-nav`（`z-index: 10`）与 `.itinerary-add-fab`（`z-index: 8`），列表靠下条目展开后容易被底栏盖住或压在卡片层级下。
  - 基于原生 `<details>` 实现，全站未挂载任何点击空白处或滚动收起的事件监听（且需 `margin: 0 !important` 对抗全局 `details` 规则），展开后只能再次点回原图标关闭。
- **PC 端表现**：**100% 复现**。桌面端同样无法点击页面空白处或滚动列表时自动收起 `<details>` 菜单，且位于滚动区域底部的卡片/账目/成员点开后依然固定向下展开，容易贴近或溢出滚动视口底边。
- **修复建议**：
  - 移动端统一将列表项“更多操作”改为 Bottom ActionSheet；桌面端将 `<details>` 替换为可控气泡菜单，统一补充 `pointerdown` 外部点击关闭、`Esc` 关闭以及底部空间不足时向上翻转的边界检测。

#### <a id="mob-004"></a>MOB-004 · 行程卡片路程槽与辅助图标触控热区偏小
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/components/itinerary.css`（113–130、220–246、359–362、501–504 行）
  - `app/src/components/date-expense-navigation.css`（129–138 行）
  - `app/src/styles.css`（2201–2215、2506–2515 行）
- **问题现象与根因**：
  - `.itinerary-page .route-add`（`28px`）和 `.itinerary-page .route-row`（`28px`）选择器优先级（`(0,2,0)`）高于 `styles.css:2508` 的 `.route-row { min-height: 48px; }`（`(0,1,0)`），导致手机端路程点击条实际高仅 `28px`，低于 `44px` 触控门槛。
  - `.activity-navigation` / `.activity-place-icon` 为 `40×40px`、`.mobile-today-jump` 为 `32×32px`，同样低于建议热区。
  - `itinerary.css:359-362` 将未设置路程的 `.route-add` 隐藏，而 `501-504` 行在同一断点内又重新设为可见，存在死代码与逻辑矛盾。
- **PC 端表现**：部分复现。桌面端虽不要求 44px 手指热区，但 `itinerary.css:113-126` 同样通过更高权重把 `.route-row` 从 `styles.css:2203` 的 `48px` 压扁到 `32px`、`.route-add` 压到 `24px`，且 `.route-add` 与拖拽手柄 `.drag-handle` 默认 `opacity: 0` 依赖 `:hover` 浮现，普通桌面发现性偏低，在 `> 760px` 的触屏笔记本或横屏平板上更难以直接触控唤出。
- **修复建议**：
  - 将手机端 `.route-row` / `.route-add` 恢复至 `min-height: 44px`，移除重复覆盖的隐藏规则；`.activity-navigation`、`.activity-place-icon`、`.mobile-today-jump` 热区扩大或通过伪元素/内边距补足 `44×44px`；同时评估对不支持悬停的触屏设备直接保持 `.route-add` / `.drag-handle` 可见或提供显式入口。

#### <a id="mob-005"></a>MOB-005 · 行程工具栏在多处 CSS 文件中存在重复与反向覆盖

- **涉及位置**：

- **修复建议**：扩大 `.sheet-grabber` 响应区域至 `36–44px`（或支持在面板标题栏上下滑动展开/收起），提升手机端 `#actions` 按钮高度。

### 模块 D：全局交互、弹层与系统兼容性

#### <a id="mob-013"></a>MOB-013 · 全局多数 `:hover` 规则未限制在精细指针设备，触屏点击产生粘滞高亮
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/styles.css`（103、110、140、2101、2165、2194 等行）
  - `app/src/components/editor-ledger.css`（126、153 行）、`app/src/map.css`（56、535 行）、`app/src/components/board.css`（568、626、2362 行）、`app/src/navigation.css`（280、359 行）
- **问题现象与根因**：仅光晕特效（`styles.css:3006`）包裹了 `@media (hover: hover) and (pointer: fine)`，其余按钮、卡片、列表项 `:hover` 直接暴露在触摸屏下。在 iOS Safari / Android Chrome 上点击后 `:hover` 不会及时消退，造成截图 2 中 `···` 按钮停留在绿底的错觉。
- **PC 端表现**：仅触屏 PC 复现。纯鼠标设备离开元素后 `:hover` 正常消退；但视口 `> 760px` 的触屏笔记本（Surface / 二合一设备）或横屏平板仍会因缺少 `@media (hover: hover) and (pointer: fine)` 隔离而残留悬停高亮。
- **修复建议**：将纯桌面鼠标悬停效果统一包进 `@media (hover: hover) and (pointer: fine)`，仅保留 `:active` 和语义化 `[aria-expanded='true']` / `[aria-pressed='true']` 状态样式在触屏生效。

#### <a id="mob-014"></a>MOB-014 · 编辑弹窗（`.editor-modal`）移动端顶部锚定与触屏失焦保存竞争
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/App.jsx`（65–71、188–190 行，`wideEditor` 使用 `min-width: 1280px` 断点）
  - `app/src/components/editor-ledger.css`（191–196 行）
  - `app/src/styles.css`（3067–3097 行）
  - `app/src/components/ActivityEditor.jsx`（394–398 行）
- **问题现象与根因**：
  - 普通弹窗在 `≤760px` 紧贴底部/软键盘上方定位（`bottom: calc(var(--keyboard-inset, 0px) + ...)`），而 `.modal.editor-modal[open]` 单独覆盖为 `top: calc(var(--visual-top, 0px) + 8px); bottom: auto;`，交互形态与其它弹窗不一致。
  - `完成` 按钮只对 `e.pointerType === 'mouse'` 调用 `e.preventDefault()` 阻止默认失焦；手机触摸点击 `完成` 时，会先触发当前输入框 `onBlur`（提交一次自动保存并可能增删校验提示/收起键盘），紧接着再触发 `complete()`，偶尔造成界面高度或滚动位置瞬时跳动。
- **PC 端表现**：**`761–1279px` 中等桌面与触屏 PC 复现**。`≥ 1280px` 大屏改用右侧滑出面板 `.activity-editor-panel`，不会命中 `.editor-modal`；但在常见 13 寸笔记本或半屏分屏窗口（`761–1279px`）中仍使用 `.editor-modal` 居中弹窗，且触屏笔记本手指点「完成」同样不满足 `e.pointerType === 'mouse'`。
- **修复建议**：统一编辑器 `完成` 在触屏点击下的提交防抖/失焦收口逻辑，并梳理编辑态与浏览态弹窗在键盘弹出时的统一安全高度策略。

#### <a id="mob-015"></a>MOB-015 · 扫码加团浏览器兼容性缺失，全站 3 处操作使用原生 `confirm()` 弹窗
- **优先级**：P1
- **状态**：`待修复`
- **涉及位置**：
  - `app/src/components/Entry.jsx`（317–328 行，`JoinTrip` 扫码）
  - `app/src/components/Settings.jsx`（140 行移除成员 `confirm`、475 行归档旅程 `confirm`）
  - `app/src/components/MarkPicker.jsx`（44 行批量更新地点标记预设 `window.confirm`）
- **问题现象与根因**：
  - `JoinTrip` 扫码直接检测 `window.BarcodeDetector`，而 iOS Safari（含微信/内置浏览器）及移动版 Firefox 均不支持该 API，点击扫码只会直接报错退回文本输入。
  - 移除成员（`Settings.jsx:140`）、归档旅程（`Settings.jsx:475`）与批量修改地图标记预设（`MarkPicker.jsx:44`）共 3 处直接使用浏览器原生 `confirm()`，在移动端网页和 iFrame 预览环境体验割裂且存在被拦截风险。
- **PC 端表现**：**100% 复现**。macOS Safari 与桌面端 Firefox 同样不支持 `window.BarcodeDetector`；上述 3 处 `confirm()` 在 PC 端同样弹出浏览器原生阻塞确认框。
- **修复建议**：将全部 3 处原生 `confirm()` 统一替换为应用内 `<Modal>` 确认框；扫码入口对不支持 `BarcodeDetector` 的浏览器补充图片识别或仅展示提示引导而非先打开失败报错。

#### <a id="mob-016"></a>MOB-016 · `styles.css` 中 `@media (max-width: 760px)` 规则多段分散且存在覆盖冲突
- **优先级**：P2
- **状态**：`待修复`
- **涉及位置**：`app/src/styles.css`（1299、2391、3062、3132、3297、3380、3540 行共 7 处同断点声明）
- **问题现象与根因**：历史多轮设计迭代均直接在文件末尾追加新的 `@media (max-width: 760px)` 区块，导致 `.page`、`.bottom-nav`、`.activity-card`、`.modal-body` 等属性被反复覆盖，维护人员阅读前面段落容易误判实际生效值（如 `MOB-004`、`MOB-005` 即由此诱发）。
- **PC 端表现**：间接影响 PC 端（散落在文件尾部的补丁规则若未严格限定断点边界，容易覆盖桌面端既有样式，加大双端维护成本）。
- **修复建议**：按页面/组件逐步将分散断点归并到对应组件 CSS 或单一权威段中，清理失效或被覆盖的旧声明。

#### <a id="mob-017"></a>MOB-017 · 旅程设置内联输入框缺少编辑反馈，窄屏水平空间偏紧
- **优先级**：P2
- **状态**：`待修复`
- **涉及位置**：`app/src/components/trip-settings.css`（1–10 行）、`app/src/components/Settings.jsx`
- **问题现象与根因**：`.trip-inline-setting input` 设置了 `width: min(65%, 420px); border: 0; background: transparent; text-align: right;`，在窄屏手机端看起来像纯展示文本，缺少“此处可点击修改”的视觉暗示，且长名称时最多仅占行宽 65%。
- **PC 端表现**：**100% 复现**。PC 端同样渲染为无边框、透明背景、右对齐输入框，缺少可编辑视觉提示；仅因桌面行宽充足，空间截断不如手机端明显。
- **修复建议**：在移动端改为上下堆叠，并在双端为可编辑控件增加浅底/悬停框线或右侧编辑铅笔图标暗示。
