# 2026-11-22 原生 N0：共享用例与兼容修复

依据：[11-原生端功能对齐](../设计文档/11-原生端功能对齐.md) 第 4 节与 N0 工作包。分支：`dev`。

## 修改

- **共享用例**：新增 `mobile/tools/generate-fixtures.mjs`，直接调用网页端函数，生成 `mobile/fixtures/` 下四个文件：
  - `rich-text.json`（65 条）：`sanitizeRichText`、`richTextToPlain`、`plainToRichText`，覆盖白名单内外标签、颜色、对齐、勾选清单、脚本与事件属性、交叉嵌套、实体。
  - `board-geometry.json`（169 条）：`board.js` 的视口换算、内容范围、适应全板、层级、`simplify`、各类型 `scaled`、样式清洗；`board-geometry.js` 的旋转、包围盒、锚点、角度吸附、比例吸附、笔迹收尾与缩放、参考线吸附、对齐分布、橡皮命中。
  - `board-widgets.json`（217 条）：一份含已删除日、已删除活动、错配路程、带 / 不带预设标记的收藏、外币与已删除费用、白板对象的快照；8 种小组件在 4 个时刻下的 `widgetModel`，以及 `widgetDeps`、`widgetSize`、`widgetScale`、`widgetEdgeHandles`、`placeGroups`、`pickWidgetSize`。
  - `itinerary.json`（77 条）：排序、日期标签、时间标签、金额、日期计算、路程签名、出发建议、排序计划，费用的关联活动、日期与标题。
- `app/package.json` 增加 `fixtures:check` 并接入 `npm run check`。
- **兼容修复**：快照里有 `board` 对象，原生「已删除的内容」原先列出所有已删除对象，会把网页端删掉的白板显示成「计划内容」。两端改为与网页相同，只列 activity / favorite / expense / day / route：Android `Domain.kt` 的 `deletedContent`，iOS `Models.swift` 的 `DeletedContent`。
- **测试骨架**：Android `SharedFixturesTest.kt`、iOS `SharedFixturesTests.swift` 提供读取、按函数取用例、深比较的工具，并已对 `orderedActivities`、`routeSignature`、已删除列表过滤与网页结果比对。iOS 工程生成脚本改为自动收录 `JourneyTests/*.swift` 与 `mobile/fixtures/*.json`，已重新生成工程（只新增条目）。
- **接口文档**：`app/CONTRACT.md` 的 boardItem content 按 `server/model.mjs` 补全（todo、section、gallery、places 等及各自字段）。
- **网页端修复**（`685f3de`）：生成用例时发现日程、这一天、路线小组件的来源不在快照中时 `widgetModel` 抛错，小组件没有错误边界，会导致页面崩溃。改为按 10-白板 第 8、13 节显示「已移除」，补单测。此问题在 `main` 上同样存在，随下次发布修复。
