# 2026-11-11 审查问题修复（P0/P1 与 dev E2E 阻塞项）

依据：[dev vs main 代码审查报告](../评审输入/2026-11-10-代码审查/代码审查报告-2026-11-10.md)（2026-11-10，基线 `origin/main` `26edb6b` → `dev` `6685e41`）。本次在 `dev` 上修复报告中判定为 P0/P1 的问题、`dev` 自身 E2E 的阻塞失败，以及修复过程中暴露的一个移动端布局回归；未合并 `main`。

## 一、修复内容

### 1. 白板同步（P0：服务端重启后本机白板被清空）

- `app/src/board-sync.js`：`loadData` 与 SSE `onTripChange` 在 `epoch` 与本地缓存不一致时，丢弃 `since` 全量重读并覆盖 IndexedDB 缓存；同一 epoch 才做增量合并。
- 新增 `app/tests/e2e/board-epoch.spec.mjs`：真实文件 SQLite + 同端口重启进程（epoch 1→2），断言页面元素与刷新后均保留、服务端仍有 1 个 active 对象。修复前该用例会在 SSE 重连后掉到 0 个元素。

### 2. 白板元素生命周期与「加入行程」（P1）

- `app/src/board-sync.js`：`patchBoardItem` 不再本地自增 `generation`（服务端 patch 不递增，只有 delete/restore 递增）。delete/restore 继续使用与服务端一致的 generation；修复了「编辑后删除/恢复 409 STALE_GENERATION → 暂停整条旅程队列」。
- `app/src/components/Board.jsx`：地点小组件「加入行程」不再提交协议外的 `ordinal`；从收藏 payload 取完整 Place（去掉 `mark`）写入 activity；用 `order: 999` 参与排序；失败时提示。
- `app/tests/e2e/board.spec.mjs`：便签用例在编辑→删除→恢复后通过 API 断言服务端状态为 `active`；新增「地点小组件加入行程」用例，断言服务端生成带经纬度的 activity 且白板项 `linkedActivityId` 已写入。

### 3. 小组件数据口径（P1）

- `app/src/domain.js`：新增 `currencyFactor(currency)`（按 `Intl` 的 `maximumFractionDigits`，KRW=1、JPY=1、CNY/USD=100、KWD=1000），`money()` 不再只特判 JPY。
- `app/src/components/widgets/ExpenseWidget.jsx`：主数字按 `currencyFactor` 换算，KRW 不再缩小 100 倍。
- `app/src/board-widgets.js`：倒计时/费用小组件读取 `visibleDays()` 的 `{payload:{date,ordinal}}` 层级修正；倒计时 `days` 映射为 `{id,ordinal,date}` 以恢复进度点。
- 单测：`board-widgets.test.mjs` 新增 KRW/JPY/CNY、countdown 起止日期、expense perDay/top 断言；`expenses.test.mjs` 新增 currencyFactor/money 断言。

### 4. presence 限流、资源上限与素材路径（P1）

- `app/server/index.mjs`：
  - presence 请求不再计入全局 `ip` 500次/分桶；presence 路由保留 15次/秒/设备，并新增 60次/秒/用户（含 leave）。
  - `live` 键数上限 200（超限 422）；单旅程 presence 条目上限 200（429）；SSE 每用户/每旅程 ≤4、全局 ≤200（429）。
  - 新增与 SSE 无关的 15s presence 清理定时器（`unref()`，`drainStreams` 清除）；清理过期条目并广播 leave。
  - SSE 写入统一走 `sendStream()`：检查已关闭/背压，异常时不崩溃并移除连接；logout/revoked/心跳路径同步修正。
  - 素材上传/下载/purge 改用 `options.assetsDir || config.assetsPath`。
- `app/server/config.mjs`：新增 `assetsPath`（`ASSETS_PATH` 环境变量，默认 `data/assets`）。
- `app/ops/journey.env.example`：新增 `ASSETS_PATH=/var/lib/journey/assets`。
- `app/ops/journey.nginx.conf`：为 `/api/trips/*/assets/*` 增加 `client_max_body_size 6m`（其余路径仍 2m）。
- `app/tests/board-server.test.mjs`：新增「持续 presence 后普通 API 仍 200」「live 201 键 422」两条；原 5 条保持通过。
- `app/CONTRACT.md`：补充 default-board、epoch 全量重读、presence/SSE 上限与新错误码。

### 5. 素材纳入备份/恢复（P1）

- `app/ops/backup.mjs`：备份时若 `ASSETS_PATH` 目录非空，打包为 tar 后用同一 AES-256-GCM/AAD 加密为 `assets.enc` 并记入 manifest；恢复时解密到临时目录、校验后再原子替换 assets 目录（保留旧目录回退）。无 assets 的旧备份保持兼容；有 assets 的备份在未提供 `assetsPath` 时明确报 `ASSETS_PATH_REQUIRED`。CLI 读取 `ASSETS_PATH`。
- `app/tests/backup.test.mjs`：在原 6 条测试基础上新增 2 条（5MB 素材备份→破坏→恢复一致性；无 assetsPath 拒绝），原有测试全部保留。

### 6. 移动端底部导航回归（修复过程中发现，P1）

- `app/src/styles.css`：手机底部导航改为 5 列（新增「白板」后仍是 4 列，第 5 项换行导致导航变高，遮住「添加活动」浮动按钮，390/320 宽度下 Playwright 无法点击）。该问题同时是 `favorite-place-picker` 4 条 E2E 失败根因。

### 7. dev 自身 E2E 过期断言

- `app/tests/e2e/itinerary-review.spec.mjs`：活动更多菜单断言同步新增「贴到白板」并允许图标前导空白。
- `app/tests/e2e/place-information.spec.mjs`：活动名称改为「地点名仅作 placeholder、不自动填值」的既有行为（与 `map-search-picking.spec.mjs` 一致）。

## 三、发布与运维注意

- 本次改动只在 `dev`，**未合并 main**；线上需部署时：
  1. `/etc/journey/journey.env` 写入 `ASSETS_PATH=/var/lib/journey/assets`，确保目录可写（`ReadWritePaths=/var/lib/journey` 已覆盖）；
  2. 更新并 `nginx -t && nginx -s reload` 仓库内 `journey.nginx.conf`（assets 路由 6m）；
  3. 若旧实例已在 `/opt/journey/current/data/assets` 存有素材，需要一次性迁移到 `ASSETS_PATH`；
  4. 备份目录将多出 `assets.enc`，恢复需要同等磁盘空间；旧备份（无 assets.enc）仍可正常恢复。
- 新增的 presence/SSE 上限（200 live、4/用户/旅程、200 全局、60次/秒/用户）为硬编码常量，未下放到环境变量；同账号同旅程打开 >4 个页面时第 5 条 SSE 会被 429，前端表现为实时连接不可用但轮询/操作不受影响。
