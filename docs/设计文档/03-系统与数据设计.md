# 03｜系统与数据设计

版本 v0.9｜2026-10-12｜团队权限、离线同步与可恢复业务数据

## 1. 架构目标与模块责任

本稿落实[01需求](01-软件需求规格说明书.md)、[02交互](02-交互与界面设计稿.md)和[05决策](05-小组设计决策工作坊.md)。响应式Web由3人团队在2026年12月底交付完整实现与验证，不要求公网发布。本次只修改设计，原型、API与数据库完成度由各自验证记录说明。

当前共享行程是日常使用对象，支持可选空值；没有强制定稿或发布。一次完整修改结束自动保存，断网持久编辑、刷新重开恢复、联网自动补传。普通同字段竞争按操作发生时间取较新值。删除/恢复为独立生命周期，删除后有效编辑仍保留在隐藏内容中。

建议采用一个响应式前端、模块化服务端与关系数据库，另在浏览器提供按账号隔离的持久输入和待传操作存储。地点供应商采用高德；前后端框架、认证组件、数据库和实时协议按团队经验与实际验证选择。Git类比不指定Git存储、分支或用户命令。

| 模块 | 责任 |
|---|---|
| 认证与团队 | 手机号/邮箱登录；原始创建记录、当前创建者继任、管理员、成员、团队模式与当前操作授权 |
| 邀请 | 编码/二维码/链接邀请加入同一团队；用户选择期限、撤销、重复兑换去重 |
| 行程/地点 | 稳定计划日、活动、路线、星标、空值及外部来源隔离 |
| 最小账本 | 预计/已支付同条替换，分开汇总，幂等记账 |
| 生命周期 | 日常软删除、显式恢复、意见去重、当前全团队计数及轮次隔离；最后一人退出永久清除及恢复排除 |
| 同步 | 完整操作、本机持久队列、发生时间定序、回执、重连和授权再验 |
| 继续旅程 | 页面、日期、滚动、选中对象、未完成编辑的本机与已上传状态恢复 |

删除/恢复对象上的轻量表达不扩展为聊天、留言或通用投票。对外分享就是邀请加入，不设匿名只读、固定副本或独立分享令牌模型。

## 2. 团队权限与生命周期

### 当前创建者继任与两种团队

创建时由创建者明确选择teamMode，不设置暗默认；Trip分别保存原始创建人createdBy和当前管理者ownerId。原始创建记录保留，权限依据当前ownerId；创建者离开时按规则继任。当前创建者可管理管理员、切换团队类型及逐成员设置canInvite，成员默认可邀请。创建者和管理员可移除其他成员，管理员无权移除当前创建者。管理员团队所有成员可增改，创建者/管理员可直接删除；普通成员只能表达本人不参加或希望删除。平等团队所有成员可增改，创建者可直接删除，普通成员的集体删除按下式判定。

设当前全部有效团队成员集合为M（包含创建者），N=|M|；当前“不参加”集合为A，有效“希望删除”集合为D，均先与M取交集：

`集体删除 = teamMode为平等团队 AND |D|≥1 AND |A∪D|≥floor(N/2)+1`

同一成员两种意见只计1人。5人团队3人只表达不参加时不删除；其中至少1人明确希望删除后，满足集体删除。创建者直接删除不受阈值约束；管理员团队普通意见不自动触发删除。不适用参与含义的业务对象仅使用希望删除表达。

两种模式均允许创建者/管理员直接恢复；普通成员可表达明确恢复意愿。恢复集合R仅计当前成员，`|R|≥floor(N/2)+1`生效；不参加或希望删除不算恢复票。“不参加”“希望删除”“支持恢复”均可修改或撤回。只在有效表达变动时按当时M重算条件；成员加入、离开或teamMode变化本身不触发计算。相同值提交、重复补传或未胜出的旧意见不算有效变动。切换团队类型保留管理员任命；管理员团队中管理员可直接删除，平等团队中只有当前创建者可直接删除。管理员直接恢复、移除其他成员及撤销邀请等已定权限在切换后延续。

### 内容与生命周期分离

日常旅程业务对象软删除、可恢复，包含旅程、计划日、活动、收藏关系、路段和账目等；最后一位成员退出后的永久清除为例外，适用下述清除规则。认证、成员撤权及邀请过期按授权生命周期处理，不把“可恢复内容”误作为继续访问权。

每个对象保存独立的payload和lifecycle。删除只将生命周期置为deleted，保留payload；其他成员之后的合法修改继续合并payload，对象仍隐藏。恢复只将生命周期置为active，不复制删除时旧值。例如A删除活动、B后来改时间，恢复后采用B的有效时间。引用的父对象删除时，子内容不级联销毁；恢复入口需要保留对象及关联上下文。

个人参与状态独立持久保存，删除和恢复活动都不重置“不参加”。删除意愿与恢复意愿分别记录，恢复仅统计明确的R。建议使用服务端生命周期代次控制重复或迟到的删除/恢复命令，避免同一指令再次执行；具体代次字段不进入UI。恢复清除上一轮删除意愿，保留个人参与状态；下一轮删除仍要求新的明确删除意愿。清理旧轮表达及生命周期变更本身不作为新的投票变动再次触发阈值计算。普通payload编辑可继续合并到隐藏内容。

当前创建者离开管理员团队时，从其余当前管理员中按加入团队顺序选最早者继任；没有剩余管理员时，从其余全体成员中选加入最早者。离开平等团队时，从其余当前成员中选加入最早者。加入顺序由服务端记录的稳定入组序号确定，时间戳相同仍有确定先后。离开、加入及ownerId更新须在同一旅程事务边界序列化，重读候选人当前资格，旧创建者不再保有当前创建者权限。账号注销流程另行明确。

最后一位成员退出时永久清除旅程及其业务内容、关联成员、邀请、意见、回执正文与继续上下文。该操作应先原子提交不可逆的旅程清除状态，再完成关联数据清理；不得在清除过程中开放加入或允许补传重建。建议单独保留仅含旅程标识、清除序号/时间及必要处理状态的最小清除凭据，不含行程、收藏、账目等业务内容，作为重试和备份恢复的排除依据。客户端收到成功确认前保留本机输入与待传操作，失败或回执不明时查询结果；确认永久清除后清理对应本机缓存和待传操作。离线设备下次连接必须先获取清除结果，不能将旧快照、补传或邀请兑换当成新旅程。

结束的旅程使用归档属性保留，归档后仍可编辑并按当前团队权限自动同步；归档与业务删除生命周期分别表达。日常软删除的物理保留期限和账号隐私处理另行明确；最后一人退出适用上述永久清除，不进入可恢复内容入口。

## 3. 逻辑数据模型与不变量

以下为逻辑设计和工程候选字段，尚未迁移。操作时钟、版本和生命周期代次仅用于实现；日常界面呈现可理解的内容与状态。

| 实体 | 关键字段 | 约束 |
|---|---|---|
| User / Session | userId、手机号/邮箱认证主体、显示名、会话 | 成熟认证；注销、过期可撤销；不自制密码算法 |
| Trip / Membership | tripId、createdBy、ownerId、teamMode、名称、日期?、时区、币种、archivedAt?；userId、joinedAt、joinOrder、管理员标记、canInvite、成员状态、lastRemovalOrder? | 原始创建人记录与当前创建者权限分开；canInvite默认true，由当前创建者管理；joinOrder用于继任顺序，joinedAt记录加入时间；归档可编辑；移除顺序记录保留至所需旧邀请均无效，以阻止旧邀请重入；当前成员去重与权限服务端核验 |
| Invite / Redemption | tripId、issuedBy、issuedOrder、tokenHash、用户选择的expiresAt、revokedAt；inviteId+userId | 生成核验canInvite；资格取消永久作废此前邀请；创建者/管理员可撤销；被移除者不能使用issuedOrder早于其lastRemovalOrder的邀请；重复兑换仍核验当前状态 |
| TripPurgeRecord | tripId、purgedOrder、purgedAt、必要清理状态 | 无业务内容；永久清除凭据独立保留，阻止补传、旧邀请及备份复活 |
| PlanDay | id、tripId、ordinal、date? | 稳定ID；有日期的计划日保留日期映射；旅程范围外的计划日仍保留；未定日期时按日序安排 |
| Place / Favorite | 稳定placeId、名称、地址?、坐标/coordSystem?、provider/providerPlaceId?、类别?、来源/时间；Favorite关联tripId/placeId、创建人 | 全体成员共享旅程收藏；类别与是否关联有效活动分别表达，安排状态从活动关系派生；同源标识去重，手工重名仅提示；收藏与活动独立 |
| Activity | id、tripId、dayId、title、orderKey、时间模式、时段?、当地起止?、跨日偏移?、地点?、到场缓冲?、结束后预留?、备注/链接? | 灵活时间与具体时间分别表达；精确活动彼此按时间排序，灵活活动可插入其间且不补钟点；每日有效总序统一用于显示和路段；结束可空；范围外安排保留对象与必要日期；不存固定锁或改期跟随属性 |
| RouteLeg | 起终对象、指定出发地?、方式?、耗时?、出发条件?、来源、inputSignature、fetchedAt? | 通勤与到场缓冲分别记录；人工值可维护，旧响应不覆盖新输入 |
| LedgerEntry | id、tripId、activityId?、名称?、status、amountMinor?、currency、备注? | 预计/已支付同ID；支付原子替换，不保存旧预计对照字段 |
| ObjectLifecycle | objectId、state、generation、删除/恢复操作依据 | 独立于payload；软删除保留内容；恢复不回滚payload；generation为建议字段 |
| Participation | activityId、userId、notParticipating | 独立持久保存个人参与状态；活动删除与恢复不重置该状态 |
| ObjectExpression | objectId、generation、userId、wishDelete、wishRestore | 删除与恢复表达分别记录、可修改撤回、按成员去重；恢复清除旧删除意愿；generation为建议字段 |
| LocalDraft / PendingOperation | accountId、tripId、对象/编辑上下文、operationId、操作内容、发生时间证据、提交状态 | 本机持久保存；未完成输入与完整操作分开；刷新重开保留，联网自动补传 |
| OperationReceipt / ChangeRecord | actor、operationId、requestHash、结果、服务端游标、必要时间/依据 | 幂等；同ID异内容拒绝；游标用于传输补取，不充当操作发生时间 |
| NavigationState | accountId、tripId、page、dayId、滚动位置、选中对象、未完成编辑引用 | 本机完整恢复；已上传部分可跨设备获取；从未上传状态留在原设备 |

操作ID、发生时间证据与所见生命周期代次在操作生成时一并持久保存，补传与重试不得改写；操作发生时刻证据与服务端receivedAt分开。发生时刻用于业务合并，收到时间用于传输排障；客户端随意填写的墙上时钟不能直接成为可信排序依据。选定的时序方案必须验证其精度和失效范围，见第6节。

不变量：

1. 每次读写、补传、意见表达、删除与恢复都校验当前授权，同旅程引用不可跨空间替换。
2. 仅在有效表达变动时按届时当前成员去重计数，包含当前创建者；删除须至少1人明确希望删除且A∪D严格过半，恢复须独立R严格过半。成员或模式变化本身不触发，重复回放不触发。
3. 生命周期不被普通编辑覆盖；恢复不复制历史payload；重复或旧代次删除/恢复指令不在新轮重新执行；个人参与状态独立保留。
4. 时间、地点、费用空值正常；null不作0，灵活时段不补虚假时刻。
5. 完整操作、当前结果、幂等回执与变更通知依据一致提交；支付转换只汇总一次。
6. 同字段按发生时间选值，较早离线补传不覆盖较晚在线操作；异字段/组有效内容按选定拆分保留。
7. 删除关联对象不抹除独立收藏、账目或子内容；归属与引用完整，恢复后继续使用。
8. 本机输入与待传操作隔离不同账号，持久化失败不得显示“已保存在此设备”。
9. 最后一人退出的永久清除不可通过软删除恢复、补传、旧邀请或备份重新建立；清除成功前保留客户端唯一输入；加入、退出与继任按同一事务序列处理。
10. 取消邀请资格永久作废此前令牌；被移除者兑换时核验其最近移除边界；幂等兑换回执不能越过当前授权与清除状态。

## 4. 保存、离线与完整继续

| 阶段 | 真正行为与显示 |
|---|---|
| 未完成编辑 | 本机持久保存输入与表单上下文，保留修改前后关系；尚未完成的非法中间值不写入共享业务对象 |
| 一次完整修改结束 | 自动生成唯一操作并本机持久保存；在线上传，离线进入待传队列；无额外保存/发布步骤 |
| 设备保存完成、等待上传 | 持久存储提交后可显示“已保存在此设备，等待同步”；刷新重开仍能继续 |
| 云端确认 | 服务端已验权并处理操作，返回权威结果/回执；可显示已同步，向同伴推送更新 |
| 发生时间较早的补传 | 按操作发生时序合并后返回当前胜出值和该操作处理结果；不把接收较晚当作内容较新 |
| 永久清除确认 | 客户端收到清除成功或核实已清除后清理对应缓存与待传操作；确认前保留本机输入，离线补传不能重建已清旅程 |
| 错误/权限失效 | 保留本机输入与操作，准确反馈；重新登录/重试不能重复创建内容 |

本机持久层可采用IndexedDB作为候选，正式实现验证存储配额、事务失败、浏览器清理、账号隔离、刷新重开和设备环境。主动清理和存储耗尽须提供准确反馈与保留可处理内容，不能承诺浏览器已删除的数据仍在本机。

联网恢复后自动鉴权、拉取当前团队与对象状态、上传待传操作、获得回执并处理更新。对请求已发出但回执丢失的操作以同operationId查询或幂等重试；无论尝试次数多少，活动、账目、意见与生命周期只执行一次。

继续旅程恢复页面、日期、滚动、选中对象与未完成编辑。客户端记录并持久保存完整上下文，已联网上传的部分可供另一个设备恢复；从未上传的本地数据只能从原设备恢复。删除或无权访问的选中对象不得借恢复导航绕过访问规则；在可用入口保留能处理的上下文。

普通同字段竞争自动合并，不常态要求人工逐项比较。无法建立可信时序、格式不合法、权限失效和内部结构关系无法成立时才返回针对性处理；保留未处理操作，不以人工对比替代已确定的普通自动规则。

## 5. 接口责任草案

路径为候选，最终随选型形成可校验合同。服务端从会话获取主体，不能相信客户端声明的管理员身份或投票人数。

| 责任 / 候选接口 | 关键校验 |
|---|---|
| 创建/读取旅程：/trips、/trips/:id | 名称与明确选择的teamMode；初始化createdBy与ownerId；有效成员读取；创建幂等；归档后可编辑 |
| 管理员管理：/trips/:id/administrators | 当前创建者授权；管理员任免及团队类型切换留痕；原始创建记录保留 |
| 邀请：/trips/:id/invites、/invites/accept | 生成核验canInvite及期限；创建者/管理员可撤销；资格取消永久失效旧邀请；兑换重读旅程/邀请/最近移除边界及当前成员状态；重复回执不能绕过当前校验 |
| 成员管理：/trips/:id/members | 当前创建者设置邀请权限；创建者/管理员移除其他成员，管理员不能移除当前创建者；创建者离开原子继任，无剩余管理员则从剩余全体选最早；最后一人退出永久清除，与加入共同序列化；成员变更不触发阈值重算 |
| 业务操作：/trips/:id/operations | operationId、目标、完整payload/逻辑组、发生时间证据；当前成员增改授权；同旅程引用 |
| 删除：/objects/:id/delete | 当前直接删除权限；对象当前代次；业务软删除；幂等 |
| 删除表达：/objects/:id/deletion-expression | 本人不参加/希望删除可修改撤回；仅有效表达变动后事务重读M/A/D并计算条件，同成员去重 |
| 恢复：/objects/:id/restore | 创建者/管理员直接恢复；只改生命周期；旧代次请求不复活后续删除 |
| 恢复表达：/objects/:id/restoration-expression | 独立恢复票可修改撤回；仅有效表达变动后当前成员去重并计算严格过半；恢复清除旧删除意愿、保留不参加 |
| 账本：/ledger、/ledger/:id/pay | 最小预计/已支付同条替换；沿用团队增改/删除/恢复；幂等 |
| 地点/路线：/places/search、/route-legs/:id/refresh | 实际供应商、当前输入签名、延迟响应隔离；失败保留输入 |
| 同步：/trips/:id/changes、操作回执查询 | 当前授权、连续游标、缺口补取、重复确认 |
| 继续状态：/me/last-journey-state | 账号隔离、已上传上下文；本机未上传部分不伪造云端结果 |

不用匿名分享和固定副本接口。手机号/邮箱登录、注销、恢复采用选定认证组件；邀请分享复用邀请接口。

返回权威结果、操作处理结果、回执与必要错误字段。401重新登录，403/404不可访问，422当前结构错误；409仅用于不能按既定规则处理的状态/代次问题，普通同字段竞争直接自动处理。时钟或存储异常提供针对性恢复入口，UI不显示内部时钟、代次、SQL或堆栈。

## 6. 合并、时序与事务建议

### 同字段发生时间规则与工程边界

产品规则已确定：以操作发生时间取较新修改。A10:30离线修改、B10:40在线修改、A10:50补传时保留B。服务器接收顺序、回执顺序和事件游标不能替代这一规则。

建议采用字段或逻辑字段组的latest-wins：互不依赖的值独立合并，组成同一合法状态的字段原子比较/应用。例如当地起止与跨日偏移、账目支付状态与金额须保持一致，不能各自获胜拼成用户从未提交过的组合。字段组如何划分尚需按实际模型确定；顺序移动与跨对象引用需额外结构校验，不先承诺任意操作都能逐字段合并。

跨设备离线的真实发生先后存在时钟不确定性。任意设备Date.now可能被修改、漂移；HLC可表达因果与提供一致定序，也不能单独证明互不相见的离线操作的真实先后。工程上需设计可信时间证据及不确定性处理，验证设备休眠、重启、改时钟和长期断网后仍满足规则；无法判定时保留操作并报告时间依据不足，不能退化为“谁最后上传谁赢”。相同时刻的确定性定序也待选，不能宣称已解决真实时序。

### 生命周期与意见事务

业务编辑事务验权后，只更新payload及其合并依据，不写lifecycle。删除/恢复事务独立核验当前角色和所引用对象代次，修改state并推进代次；原payload继续保留。建议将意见统计、阈值判断、状态改变、代次推进、幂等回执与变更记录原子提交。

集体删除事务必须重读当前有效M、参与状态A与有效删除意愿D，检验`|D|≥1 AND |A∪D|≥floor(N/2)+1`；管理员团队普通表达不触发状态转移。恢复事务重读当前M和本恢复轮R，严格过半才恢复。表达修改或撤回在合并后确实改变有效值才触发该对象重算；成员变更、团队模式切换和相同值重放均不触发。下次有效表达变动使用届时M、teamMode及有效表达。恢复清除旧删除意愿，个人参与状态保持原值；生命周期转换和旧轮清理不递归触发下一轮投票。离线意见引用哪一轮的细节及与直接操作的并发处理继续在实现方案中确定。

同一操作重传只返回原结果；旧代次删除/恢复命令不能删除或恢复新一轮状态。晚到的普通编辑可以合并到隐藏payload，不自动改写生命周期。完整对象保存也不得把客户端默认deleted=false、清空删除字段或旧state当作恢复命令；恢复必须显式引用当前删除代次。创建者/管理员撤任或成员被移除后，补传时按当前权限重新核验。

### 重连、失序与供应商响应

先鉴权，再补取权威状态和连续事件；读取与订阅间不漏更新。候选实现为先订阅缓冲、读取当前状态、再应用后续游标，或支持连续游标的补取协议。游标过期/缺口全量刷新；通知失序不回退权威值，重新计算以操作合并依据为准。

业务写入、回执和必要变更记录原子提交，提交后通知；SSE+HTTP或WebSocket均可候选。撤权中断订阅、重连重新验权，通知仅服务已授权客户端。

外部路线请求在数据库事务之外完成，应用响应前核验当前inputSignature和授权；旧端点、出发条件或方式结果不能覆盖当前值。通知与供应商回执的收到时间不参与用户编辑先后判断。

## 7. 时间、外部数据与可靠性

### 时间与路段

计划日未映射日期时保留当地时刻意图，不生成虚假的UTC日期。日期确定后按IANA时区解析；跨午夜用明确的结束日偏移，避免两套时间互相矛盾。精确区间使用半开区间，已知重叠条件为`start < other.end && other.start < end`；同时提供起止时才检验完整区间；只填开始合法。修改开始保持已有时长，修改结束改变时长；切回灵活时间后旧精确值停止参与计算。跨日结束日期显式选择，次日延续信息引用同一活动。

目标活动开始为19:30、到场缓冲10分钟、通勤25分钟时，到达目标19:20、建议出发18:55。上一活动19:00结束，按已有数据提示晚5分钟到场；同样允许保存。缺少开始时间、出发地或通勤耗时则不计算确定出发时间、不生成待补提醒。

通勤归属路段，到场缓冲与结束后预留归属活动；最早离开为活动结束加结束后预留，开始减到场缓冲和前往耗时得到建议出发。缺少所需值不补值计算。自动路程随相关输入更新，手动耗时仅在用户重新估算时替换；起终点改变建立新路段，不继承旧手动耗时。日常只呈现可用的方式和时长。

旅程改期操作携带本次选中的活动标识和目标日期，选择不持久化为活动跟随属性。按目标日期复用或创建PlanDay，再更新选中活动的dayId，保留钟点、时长及跨日跨度；同一天未选活动保留原dayId及日期。同日部分改期不得直接改写共享PlanDay.date，日期互换以操作开始时的映射计算，避免二次移动。原日期已超出新旅程范围的计划日和活动进入行程外安排，原始内容保持不变；其显示日序与稳定ID分开计算。操作对旅程范围及所选活动的更新应作为一次完整修改处理，验证并发和重试后不重复、不漏项。无具体时间的活动采用手动顺序，具体时间活动按时刻排序。灵活活动可手动插在精确活动之间或其前后，精确活动彼此按开始时刻排序；灵活活动不产生虚构钟点。前后路段和地图路线必须使用与显示一致的有效总序。精确时间修改后的混排重排算法属于实现选择，应保持精确活动相对时序、已有手动位置意图和一个有效总序，在实际模型中验证。单项跨日移动保留时间意图。缩短旅程保留范围外活动及稳定标识，在“行程外安排”展示；没有批量顺延或时间锁。营业数据如后续用于提示，只对实际已知条件给建议，缺失值留空。

### 查询、地点和共享收藏的数据流

输入建议与正式结果分开处理。建议项可能是区域、关键词或缺少有效坐标的地点，选择后补查具体POI，校验坐标后才落点。按返回地点标识识别选中对象，避免同名分店被再次按名称查询替换。键入期间合并短间隔请求，中文输入法组词结束再查询；请求携带当前关键词、城市和本地请求序号，仅最新有效查询结果可进入当前列表。清空、取消或切换旅程后，迟到结果不得重新打开列表。

选择结果或地图位置只产生本地临时选中状态；点击“收藏”才创建团队Favorite，点击“加入行程”才进入活动编辑并在完成后创建Activity。直接加入行程不自动建立收藏。选择地点给已有活动时，只回填当前编辑中的地点，沿用该次活动编辑的完成与保存边界。

Place使用稳定内部ID，保存名称、地址、可选坐标及coordSystem、provider=amap、可选providerPlaceId、类别、来源与获取时间。经纬度成组更新，名称/地址等来源字段与用户自行维护的内容分开，刷新供应商信息不覆盖用户修改。同一旅程内以供应商和地点标识识别同源地点；坐标相近或名称相同的手工地点只提示可能重复。外部字段按所用服务授权保存必要数据，缓存与刷新期限在接入时核定。

Favorite以tripId和placeId关联共享收藏，参与现有幂等操作、权限和软删除流程；重复点击或两人同时收藏同一个POI只形成一条有效收藏关系。已有软删除关系不通过重新创建绕过恢复权限，应进入恢复路径。Activity独立关联Place；安排状态由有效活动关系派生，多次到访保留多个活动。取消收藏不删除地点引用或活动。

地图内使用高德约定的坐标体系；外部GPS或其他地图坐标在明确来源后转换，存储时保留坐标体系。缺坐标的地点进入辅助列表，保留输入，不生成虚假标记。地点名称和备注作为文本渲染，外部返回的文本不能拼接为可执行HTML。

### 路线、离线与浏览状态

按当前计划日的有效活动总序取得相邻起终点及交通方式，调用高德相应路线规划服务；保存路径、距离、耗时、获取时间和实际支持的出发条件。不向高德提交未填写的活动精确时刻，也不通过直线距离编造路程。前后路段只连接相邻且已定位的活动；中间活动缺坐标时保持路径缺口，不跳过该项伪造连续路线。到场/结束缓冲归活动，通勤归RouteLeg。

自动路线的输入签名包含端点、交通方式及服务实际支持的日期时间条件，迟到响应不得覆盖新输入。手动耗时在端点不变时保留，用户选择重新估算后才替换；端点改变视为新路段。未来出发条件不受支持时，在路线详情中简要说明适用范围。请求超时、限流、配额不足和无结果分别处理，有限重试，保留已有安排与手工编辑入口。

收藏先写本机持久队列，在线上传并同步团队，离线后按既有发生时间与生命周期规则合并。首次离线进入地图可能无法加载底图，搜索和新路线查询需要网络；此时提供已保存地点列表及本地编辑，不能把离线业务保存等同于离线底图下载能力。地图加载失败不影响行程浏览和已保存地址。

NavigationState扩展地图中心、缩放、选定计划日、收藏筛选、选中地点、详情展开程度及搜索草稿。浏览状态按账号隔离；团队变更不改变其他成员的视角。选中点自动移入扣除搜索栏、详情面板、导航和署名区域后的可见地图范围；成员更新不触发整图fitBounds。首次进入可适配全部有坐标的收藏，之后优先恢复用户视角。

### 全视口地图与悬浮层

地图页根容器覆盖应用可用视口，AMap容器绝对定位铺满；导航、搜索、面板与地图工具位于独立悬浮层，不参与底图的行列分配。悬浮层空白区域允许指针穿透，实际控件接收交互，面板内滚动和拖动不传给地图。

手机使用动态视口尺寸与系统安全区；键盘打开时按可视区域布局临时搜索任务。面板展开通过遮挡测量调整可见区域与镜头，不逐帧改变AMap容器尺寸；仅应用视口尺寸实际变化时执行地图尺寸适配。桌面侧栏、手机面板及供应商署名均参与镜头避让计算。用户主动拖地图时取消自动镜头运动。

玻璃样式使用背景模糊、透色与边缘高光，内容底色按可读性调整；减少透明效果或不支持背景模糊时使用更实底色，减少动态时直接切换。运动期间不丢失输入、选中点与焦点。

### 地图筛选与共享边界

地图收藏归tripId，全员共享，默认显示全部。类别与安排状态独立筛选，界面明确命名为“筛选收藏”；选择一天时，保留当天完整有效路线及其活动标记作为背景上下文，筛选只改变收藏层。取消当天路线后回到筛选后的收藏视图。搜索结果作为独立临时层，不被收藏筛选吞掉；切换路线和筛选均不修改团队数据。

来源链接仅接受http/https，保存与打开不自动触发服务器抓取。自动解析网页若另行加入，需要明确重定向、内网访问和字段来源边界；外部正文不能作为操作指令。

接口依据（2026-10-12核对）：[SDK加载](https://lbs.amap.com/api/javascript-api-v2/guide/abc/load)、[安全密钥与代理](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[输入提示与POI搜索](https://lbs.amap.com/api/javascript-api-v2/guide/services/autocomplete)、[地理编码](https://lbs.amap.com/api/javascript-api-v2/guide/services/geocoder)、[自定义标记](https://lbs.amap.com/api/javascript-api-v2/guide/amap-marker/custom-marker)。

### 最小账本

以币种最小单位整数存储和累计；已支付与预计已知小计分开，空预计金额不作0。预计转已支付将同一条目的状态和实际金额原子替换；操作去重防止补传重复记账。名称/金额/简短备注足够辨识条目，不展开付款人、类别、分摊、结算和预算算法。账目删除同样软删除可恢复。

### 访问与数据保护

每次业务操作、补传与订阅先核验旅程是否已永久清除，再核验当前团队成员及所需角色。邀请令牌不可预测、存摘要、用户选期限；创建者和管理员可撤销邀请。取消某人邀请资格，在同一事务作废其此前全部邀请；重新开启canInvite也不能使旧令牌恢复有效。成员被移除后，用服务端顺序记录最近一次移除边界lastRemovalOrder；其兑换issuedOrder早于该边界的邀请须拒绝，移除后新生成的邀请仍可按当前规则接受。移除使其不再具有成员邀请资格，其已生成邀请同步失效。

未加入者只能看到接受邀请所需的最少信息，不能读取私有行程。兑换、撤销、移除、邀请资格变化和最后一人退出在事务中重查当前有效性。已存在Redemption仅用于幂等处理，不直接认定仍已入组：必须重新核验当前Membership、邀请是否有效、移除边界及旅程清除状态，避免旧成功回执使被移除者重新入组。

身份、会话、CSRF/来源检查、参数化查询、文本编码、限流和依赖检查纳入验证。秘密凭据不入仓库、前端bundle或工具输出；日志只记必要请求ID、操作类型、脱敏错误与时延，不记录密码、令牌、私有正文或完整位置查询。

备份加密并限制访问；恢复到隔离环境后核对成员授权、软删除状态、操作回执与意见代次。恢复上线前应用独立保存的最新永久清除凭据，将已清旅程及关联业务内容排除；恢复流程同时重放邀请作废、最近移除边界和当前授权，不能以旧备份回滚清除或撤权事实。旧备份中的已清旅程内容不得通过产品或人工业务恢复接口提供，备份轮换及清除执行必须覆盖该规则。身份隐私处理及日常软删除备份保留期限另行明确。

交付含配置样例、构建启动、迁移、备份、恢复、健康检查和回滚步骤，并实际演练。离线持久化、发生时间合并、意见阈值、删除晚编辑恢复、撤权补传、断线重连与外部迟到响应分别留存测试证据。
