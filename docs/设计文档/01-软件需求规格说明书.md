# 01｜软件需求规格说明书

版本 v0.9｜2026-10-12｜当前产品需求与待决边界

## 1. 目标与范围

本产品帮助同伴共同记录、修改和查看旅行安排。正式交付为响应式 Web，覆盖电脑、iOS Safari 和 Android Chrome；由3人团队在2026年12月底完成实现与验证，不要求公开上线。PWA安装与移动安装包留作后续扩展。

本版把[05本轮决策](05-小组设计决策工作坊.md)和[02正式产品设计原则](02-交互与界面设计稿.md)统一写入需求正文。现有原型的实现和测试状态见本地 `prototype-v2/README.md`；本稿规定后续开发及验收，不记为已实现。

当前共享行程直接用于规划和出行。只写“下午逛逛”即可保存、同步和使用；时间、地点、通勤和费用可以留空。日常使用没有补齐资料、强制核对、填写保留原因或“草稿—定稿—修订”的前置流程。

旅程主导航为**行程 / 地图 / 费用**。取消内置聊天、讨论、对象留言、议题、提案和通用投票；删除与恢复保留对象上的轻量表达机制。取消独立出行手册入口。协作围绕共同编辑、自动保存、云端上传、自动同步与编辑冲突处理展开。

| 术语 | 本版含义 |
|---|---|
| 旅程 | 行程、地图收藏、账本和授权成员的共同空间 |
| 当前共享行程 | 服务端已接受、成员日常共同查看和修改的安排 |
| 计划日 | 稳定标识的第1天、第2天等；可在具体日期未定时存在 |
| 活动 | 安排到某一天的条目，可采用灵活时间或精确时间，地点和费用可空 |
| 收藏地点 | 在地图上以星标表示的地点；收藏与加入行程是独立操作 |
| 到场缓冲 | 用户为目标活动设置的提前到场时长，与通勤分别计算 |
| 预计 / 已支付 | 同一账目条目的支付状态；支付后用实际金额替换预计金额 |
| 同字段竞争 | 多人修改同一内容时，按操作实际发生时间取较新的值；自动处理普通竞争 |
| 临时删除 | 从日常视图隐藏业务对象，保留其内容和恢复能力；后续编辑不自动恢复 |
| 可行性提示 | 根据已有事实给出的时间重叠、通勤不足等建议，允许继续保存 |

## 2. 团队模式、权限与加入分享

旅程可采用管理员团队或平等团队，由当前创建者管理管理员及切换团队类型。成员均可增加、修改旅程业务内容，删除和恢复使用以下规则。原始创建记录保留；当前创建者离开后按本节规则继任。切换团队类型保留管理员任命，直接删除权限随模式变化，管理员恢复、移除成员和撤销邀请等已定权限继续有效。

| 操作 | 管理员团队 | 平等团队 |
|---|---|---|
| 增加、修改业务内容 | 所有当前成员 | 所有当前成员 |
| 直接临时删除 | 创建者及管理员 | 创建者 |
| 普通成员表达删除意愿 | 可表达自己不参加或希望删除；不直接删除 | 可表达自己不参加或希望删除；至少1人明确希望删除且去重人数达全团队严格过半时临时删除 |
| 直接恢复 | 创建者及管理员 | 创建者及管理员 |
| 成员共同恢复 | 全团队严格过半表达恢复时生效 | 全团队严格过半表达恢复时生效 |

平等团队删除阈值按当前团队全部成员计算，包含创建者。设成员数为N，阈值为`floor(N/2)+1`，并须至少1位当前成员明确希望删除；“本人不参加”与“希望删除”按成员去重，同一人表达两者仍只计1人。恢复在两种团队模式中均使用全团队严格过半，采用独立的恢复表达；删除意见不算恢复票。

日常旅程业务删除均为可恢复的软删除；最后一位成员退出后的旅程永久清除，按本节例外处理。删除改变对象的可见生命周期，保留内容；删除后其他成员的时间等修改仍保存于隐藏对象，编辑不触发恢复。例如A删除活动、B随后修改时间，活动保持删除；显式恢复后采用B的有效修改。删除、恢复按轮次隔离意见，恢复成功不会再次套用上一轮删除意见；“不参加”“希望删除”“支持恢复”均可修改或撤回。仅在相关表达发生有效变动时，按当时全部当前成员重新计算条件；成员加入、退出或团队类型变化本身不触发计算。重复请求、相同值提交及被合并规则淘汰的旧操作不算有效变动。恢复时清除上一轮删除意愿，保留个人不参加状态；新的删除仍须有人重新明确希望删除。

对外分享就是邀请加入同一团队。编码、手机二维码和链接使用同一邀请授权；接收者登录并加入后按团队模式协作。产品不设置独立的匿名只读访问或固定副本分享。

默认每位成员可邀请，当前创建者可逐成员调整是否允许邀请他人。创建者和管理员可移除其他成员；管理员不能借移除当前创建者获得继任资格。创建者离开管理员团队时，由仍在团队的管理员中加入时间最早者继任；若无剩余管理员，则由其余全体成员中加入最早者继任。离开平等团队时，由其余当前成员中加入时间最早者继任。加入先后由服务端记录的稳定入组顺序判断。最后一位成员退出时永久清除旅程及其业务内容。退出、加入和继任由服务端原子判定，避免并发操作误清仍有成员的旅程；服务端确认成功前保留本机输入和待传操作。清除后的旧邀请、离线补传和备份恢复均不得重新建立该旅程；可保留不含业务内容的最小清除凭据。账号注销流程另行确定。

结束的旅程归档，归档后仍可打开和编辑，成员权限与同步规则继续生效。服务端对每次读取、增加、修改、删除、恢复、意见表达和实时订阅核验当前成员与角色；撤权后停止后续访问，离线操作上传时重新鉴权。

## 3. 核心使用路径

| 用例 | 主路径 | 正常空值与恢复 |
|---|---|---|
| UC-01 启动与继续 | 登录 → 继续上次旅程，或创建、加入、选择其他旅程 | 完整恢复页面、日期、滚动、选中项及未完成编辑；旅程已不可访问时回到选择页 |
| UC-02 创建与邀请 | 输入名称、选择团队类型 → 创建 → 开始安排或邀请同伴 | 目的地、日期可稍后填写；邀请失败保留操作上下文 |
| UC-03 地图收藏与安排 | 搜索/选点 → 收藏，或直接加入行程 → 选择计划日 | 添加活动也可直接选址；取消收藏不删除活动 |
| UC-04 编辑行程 | 添加名称 → 选计划日 → 按需设时间、地点、到场缓冲与通勤 | 灵活时间、空地点和空费用正常保存；有真实维护入口 |
| UC-05 共同编辑 | 自动保留输入 → 上传 → 同伴自动看到更新 | 离线持久保留并自动补传；同字段竞争按操作发生时间自动取较新值 |
| UC-06 记账与出行 | 查看当前行程并导航 → 记一笔 → 修改或标记已支付 | 费用可独立于活动；导航当下缺地点才请求补充 |

## 4. 功能需求

编号保留用于跨文档追踪；交互细节见[02](02-交互与界面设计稿.md)，数据和同步设计见[03](03-系统与数据设计.md)，验证计划见[04](04-研究验证与实施计划.md)。本节是当前确定范围，待议能力单列于第7节。

### FR-01 旅程创建与基础设置

- 创建要求旅程名称、目的地、出发日期、结束日期，并由创建者明确选择团队类型。计划天数由起止日期按自然日自动计算，包含首尾两日；结束日期不得早于出发日期，最多365天。按2026-10-13用户最新决定（C24/C26），时区默认目的地当地时区，在“更多设置”中可调整；币种也放在该设置内。
- 新建不自动填写出发日期；用户选择完整日期范围后建立对应计划日。既有未定日期旅程保留，继续支持编辑和补充日期。
- 修改日期范围或计划天数须保留已有活动，取消修改仍可回到原安排。缩短后多出的内容保留在可收起的“行程外安排”，可稍后移回；所有活动保留已有日期、钟点和时长；原本未定日期的保留原计划日及时间意向。调整旅程日期时，用户在当次操作中选择哪些活动跟随，选中项移动日期并保留钟点和时长，未选中项保留原日期；活动没有常驻跟随开关。
- 旅程设置变更不得静默删除活动、地点或账目；涉及关系变化时保持引用一致。
- **验收**：未填写目的地或起止日期时不能创建；设备设为洛杉矶且目的地为南京时，默认时区为北京时间；同日往返为1天，跨夏令时仍按自然日计数；已有旅程日期调整和取消不误配或删除活动。

### FR-02 团队模式、加入、删除与恢复

- 创建旅程时选择管理员团队或平等团队。当前创建者指定管理员、切换团队类型，并逐成员控制邀请权限；默认全员可邀请。创建者和管理员可移除其他成员，管理员不能移除当前创建者。创建者离开按第2节加入顺序继任。全体成员可增加、修改业务内容，直接删除与恢复权限按第2节执行。
- 平等团队普通成员的删除意愿按当前全部成员去重，严格过半且至少1人明确希望删除时触发临时删除；管理员团队普通成员可表达不参加或希望删除，由有权限者直接删除。活动外不适用参与含义的对象使用“希望删除”。
- 两种模式中，创建者/管理员可直接恢复；成员可通过当前全团队严格过半的恢复表达恢复对象。恢复以N=4为例，3人达到阈值，2人未达到；创建者也计入N。5人中3人仅不参加时活动保留，其中至少1人同时希望删除才满足集体删除条件。
- 日常业务对象软删除可恢复，最后一人退出的永久清除除外；删除状态与内容修改独立；恢复只恢复可见状态，不退回删除时的旧内容。每轮删除与恢复意见隔离，恢复清除旧删除意愿并保留不参加状态。三种表达均可修改或撤回，仅在有效表达变动时重新计算，成员或团队类型变化本身不触发；下次表达变动使用届时的成员总数。
- 提供编码、手机扫描二维码和邀请链接三条加入路径。未登录保留邀请意图，手机号或邮箱登录后继续；扫码不可用可改输编码或打开链接。
- 生成邀请时核验该成员当前邀请权限，并由用户选择有效期；创建者及管理员可撤销邀请。取消某人的邀请资格时，其此前生成的邀请全部永久失效，之后重新赋予资格也不恢复旧邀请。被移除成员不能通过其最近一次被移除之前生成的邀请重新加入；可接受移除后新生成的有效邀请。是否为旧邀请按服务端事件顺序判定。重复接受时仍核验旅程、邀请和当前成员状态；既有兑换回执不能绕过移除或永久清除。人数限制另行评估。
- **验收**：两种模式的直接删除/恢复权限真实生效；同一成员两种删除表达只计一次；4人团队3人达到计数阈值，删除还须至少1人明确希望删除；5人中3人仅不参加不删除；删除后修改保持隐藏，恢复显示有效修改；重复兑换与重复意见不重复执行；模式切换保留管理员并正确更新直接删除权；无管理员时按全员加入顺序继任；最后一人退出与并发加入互斥判定，永久清除后旧邀请、补传和备份均不能复活；邀请资格重开不复活旧邀请，被移除者只能使用移除后新生成的有效邀请重入。

### FR-03 地图收藏与地点维护

- 首次进入地图通过真实高德查询定位旅程目的地。暂离返回恢复有效的上次视野；修改目的地后重新定位。从活动打开地图时聚焦该活动地点。目的地查询失败提供重试，不自动显示其他城市作为目的地。（C25，2026-10-13）

- 地图提供地点搜索、选点与星标收藏，并有辅助收藏列表；地点可手动填写名称/地址，坐标未确定仍保留输入。所有收藏归当前旅程、全体成员共享；旅程业务删除遵循FR-02。
- 地图默认展示全部收藏，可选择突出某一天的活动地点与路线，未定位活动不虚构坐标或连线。餐饮、景点等地点类别与已安排/未安排状态分别表达，可组合呈现在标记上，也可手动筛选只看所选类别或安排状态；选中一天突出路线不改动共享收藏。
- 收藏与活动分开。可从收藏加入行程，也可搜索后直接加入；直接添加不要求先收藏。地点已安排时可查看安排日期。
- 取消团队收藏属于共享内容删除，按FR-02执行；删除生效后保留活动。删除一次活动保留此前独立收藏的地点。地点资料更新不得无提示地改写用户已确认填写的活动地点。
- 可保存http/https攻略或地图来源链接。链接作为用户提供的来源，不要求自动解析订单、价格或网页内容。相同服务商地点标识去重，手工重名或同篇攻略URL仅提示可能重复。
- **验收**：不同成员看到同一旅程收藏；首次进入默认全部收藏，可突出当天路线并按类别、安排状态筛选；收藏、加入行程和删除各自影响正确；同名不同地址可分别保存；地点无图、无价格、无营业数据时仍可正常操作。

### FR-05 每日行程与活动编辑

- 行程是进入旅程后的默认页面；“继续旅程”恢复上次位置。按天展示活动，日期未定时使用第1天等标题。
- 活动名称和所属计划日是基本信息；时间、地点、备注、链接和费用按需填写。灵活时间可仅记录日内顺序、上午/下午等意向与可选时长；具体时间可只填开始，结束或时长选填；切回模糊时段后原精确时间停止参与计算。跨午夜时明确选择结束日期，活动归开始日，次日延续信息引用同一活动。
- 活动编辑支持直接搜索地点、地图选点、手工地址或从收藏选择。空地点正常保存；坐标失败不能清空地址输入。
- 提前到场和结束后预留均选填，归属活动；前者用于倒推出发，后者用于计算最早离开，均不改变活动本身起止。通勤归属路段。两者在各自编辑入口维护，不能把演出开始时间改成提前到场时间，也不重复计算通勤。
- 无具体时间的活动可调整顺序，插在精确活动之间或其前后，保留时间意向，不补具体钟点；精确活动彼此按开始时间排列，先后通过编辑时间改变。每日显示、地图路线和前后通勤采用同一有效行程顺序。单项跨日移动保留钟点、时长或模糊时段。修改开始时间默认保持已填时长，修改结束时间改变时长；只填开始的仍只保留开始。所有活动均可手动编辑，无时间锁、批量顺延或后续安排自动调整。拖拽须有按钮、日期选择或键盘等价操作。
- 无图活动使用完整文字布局；常态卡片显示必要的时间、名称、地点和到场信息，其他内容按需展开。通勤如显示“步行约20分钟”，点击可真正修改交通方式/时长或重新估算。
- **验收**：只填名称和计划日可使用；灵活与精确时间切换保持用户意图；无拖拽、手机、键盘均可完成核心编辑；无图片、短标题、长文本布局正常。

### FR-06 时间、通勤与到场提示

- 只根据足够的已知事实给出具体提示，例如“两项安排重叠15分钟”或“按当前安排会晚5分钟到场”；提示贴近相关活动且可忽略，用户仍可保存和使用。
- 缺少日期、时刻、地点、营业信息或路线时保持空值；不因未知生成待办、核对清单、红点、完成率或原因表单。执行导航等具体操作需要信息时，就地询问。
- 通勤方式和耗时可由路线服务提供或用户设置。自动估算随相关地点、交通方式或出发时间变化更新；手动耗时保留，用户点击重新估算才替换；起终点改变视为新路段，重新估算，不沿用旧路段的手动值。输入变化后更新相关路段，旧异步结果不能覆盖新输入；外部结果的来源和适用条件供内部正确刷新，普通界面不常态重复“手动估计”等过程标签。
- 可行性提示与保存失败、权限错误、编辑冲突分别处理。格式合法的已知重叠安排允许保存；格式无法成立的时间需就地纠正。
- **验收**：19:30开始、提前10分钟到场、通勤25分钟时可给出18:55出发和19:20抵达；上一项19:00结束则提示晚5分钟到场；只写“下午逛逛”无待补提醒。

### FR-07 最小旅程账本

- 费用独立于行程页面，以“记一笔”为主要入口，以已支付条目和合计为主体；可用名称、金额与简短备注辨识条目，也可关联活动。途中费用无需先建活动。
- 尚未支付的条目可记为“预计”，金额可暂空；预计额外列出，不计入已支付合计。活动未记费用正常留白。
- 支付后在同一条目输入或确认实际金额，将预计改为已支付并替换金额；不复制第二笔，不保留预计对照或旧预计查询。
- **验收**：“门票·预计200元”更新为“门票·已支付180元”，已支付合计增加180元、预计清单移除原条目；重复补传不重复记账。记账细节保持最小范围。

### FR-09 完整修改自动保存与离线同步

- 用户完成一次编辑即自动保存；在线自动上传，云端确认后同步给同伴，不设额外手动保存或发布步骤。编辑中的未完成输入持续保留；上传中、已同步和本机待上传分别表达。
- 断网可继续编辑，本机持久保存内容、未完成输入和待传操作。刷新或关闭后重开仍可恢复；联网后自动上传、获取同伴更新并完成同步。
- 普通同字段竞争按操作发生时间取较新修改，不按服务器接收时间。A在10:30离线修改、B在10:40在线修改，A在10:50补传后仍保留B的值。互不影响的修改应保留各自有效内容，具体字段/逻辑组拆分见03技术建议。
- 自动处理普通竞争，不把逐项人工对比作为日常步骤。格式无法成立、时序无法判定或权限失效时，保留输入/操作并给出针对性处理；不得用接收顺序悄悄代替发生顺序。
- 删除状态与内容独立合并。删除后时间、地点等有效编辑继续存入隐藏内容，恢复只改变生命周期。
- 重试具有幂等性，不重复创建活动、账目、意见或删除/恢复动作。同伴更新保留输入、焦点、阅读位置；撤权后的离线操作不能绕过当前服务端授权。
- **验收**：在线完整编辑自动共享；离线编辑刷新重开不丢失并自动补传；10:30/10:40/10:50场景保留B；重复请求、失序通知不产生重复内容或回退；删除后晚编辑不复活对象。

### FR-11 当前行程查看与邀请分享

- 旅途中直接查看当前共享行程，按计划日浏览活动、时间与地址，提供外部导航和复制地址；无需先定稿或另建出行手册。
- 分享通过邀请同伴加入当前团队；不要求补齐可选内容、处理可行性提示或填写原因。接收者按FR-02登录、加入并取得团队对应权限。
- 导航缺地点时在当前操作询问。删除对象从日常视图隐藏，在恢复入口仍可按权限查看和表达恢复。
- **验收**：稀疏行程正常查看；分享链接进入邀请流程，未加入者不能读取私有行程；过期/撤销邀请停止后续兑换；已加入成员按团队权限访问。

### FR-15 真实地点与路线集成

- 采用高德地图JS API 2.0及配套地点/路线服务，验证目的地覆盖、坐标体系、出发条件支持、授权、配额和费用；来源、获取时间与字段映射在内部保留。
- 查询无结果、超时、限流与配额不足有可恢复反馈，保留已有输入；用户可继续手动设置地点或路程。人工内容不得伪装为供应商返回。
- 端点、交通方式、日期/出发时刻变化使相应自动路线结果失效并重新估算。手动耗时在端点不变时继续保留，点击重新估算才替换；端点改变按新路段处理。服务不支持未来出发条件时准确表达估算适用范围。真实供应商要求的署名按条款呈现。
- 浏览器受限地图Key与服务端秘密凭据分开管理，详见03。
- **验收**：脱敏真实查询证据、断网/限流恢复、迟到结果隔离、坐标与路线条件验证；开发样例与真实集成分别记录。

### FR-17 账户、完整继续与数据生命周期

- 启动页提供登录、继续上次旅程、创建、加入和其他旅程；无最近旅程时不显示空的继续卡片。支持手机号或邮箱登录，登录后恢复邀请或原访问意图。
- “继续旅程”完整恢复上次旅程状态，包括页面、日期、滚动位置、选中对象和未完成编辑；刷新、关闭重开均保留本机内容及待传操作。
- 本机恢复涵盖本设备持久保存的状态；跨设备只能恢复已经上传的内容与状态。尚未上传的数据仍保存在原设备，不从云端虚构其副本。
- 恢复前核验访问权。会话失效保留本机输入并引导重新登录；注销、账号切换、本机存储清理的具体处理需保护不同账号的内容。
- 旅程业务软删除按FR-02恢复；成员撤权与账户身份处理独立。结束的旅程归档，仍可编辑。当前创建者离开按第2节自动继任；管理员团队无剩余管理员则从其余成员继任，最后一人退出永久清除。永久清除后的恢复、旧邀请及补传一律不能复活旅程。账号注销流程另行确定。
- **验收**：手机号/邮箱登录与邀请续接；同设备完整继续含未完成表单；另一设备仅取得已上传状态；注销后旧会话失效；猜测其他旅程ID不能访问。

## 5. 统一业务规则

| 编号 | 当前规则 |
|---|---|
| BR-01 保存与结构 | 服务端确认共享状态；本地保留和云端保存分别表达。名称等当前操作必需字段、合法时间格式、同旅程引用与权限须校验。可选空值、灵活安排和可行性提示不阻止保存。 |
| BR-02 时间语义 | 计划日使用稳定ID。未定日期不构造UTC日期；精确时间保留当地时间、跨日偏移与IANA时区，日期确定后解析。灵活时段不暗定小时。重叠按半开区间计算；到场缓冲与通勤分别建模。 |
| BR-03 提示边界 | 已知可行性问题就地提示并允许保存。未知信息不触发补充义务；系统写入冲突与可行性问题独立。格式错误和授权错误只针对当前操作。 |
| BR-04 金额 | 按币种最小单位的整数存储与累计，null与0不同。已支付与预计分别汇总；空预计金额不作0。金额与币种一致，不扩展费用分析。 |
| BR-08 并发与重试 | 普通同字段竞争按操作发生时间取较新值；服务器到达时间只用于传输记录。业务更新、操作去重与同步回执原子提交。字段/逻辑组及可信时序方案见03建议，所有补传重新核验当前授权。 |
| BR-11 地点与外部数据 | 区分服务商、用户填写和测试数据；保留来源及更新时间。缺失营业、价格、路线不补为全天开放、免费或零分钟。输入变化后的旧响应不得成为当前结果。 |
| BR-12 预计转已支付 | 同一账目使用同一标识完成状态与金额替换；原预计不再作为业务字段或产品查询目标。记录必要的变更主体、时间和幂等结果；增改、删除和恢复沿用团队规则。 |
| BR-13 邀请分享 | 对外分享即邀请加入同一团队；编码/二维码/链接不绕过授权。令牌不可预测、服务端保存摘要，生成时由用户选择期限，创建者/管理员可撤销；邀请资格撤销使旧邀请永久失效，被移除者不能用移除前旧邀请重入；没有匿名只读或固定副本访问。 |
| BR-14 软删除与恢复 | 日常旅程业务对象保留可恢复内容；最后一人退出则永久清除旅程及业务内容，并保留最小清除凭据阻止旧邀请、补传或备份复活；生命周期与payload独立，删除后编辑不复活，恢复采用最新有效payload。创建者/管理员直接恢复，两种模式成员均可全团队严格过半恢复。意见可修改/撤回且按轮次隔离；恢复清除旧删除意愿、保留不参加，旧删除意见不再次触发。撤权与身份删除另行处理，备份恢复重放当前授权与生命周期。 |
| BR-15 团队计数 | 创建者计入当前全部成员N；阈值floor(N/2)+1。同一成员不参加/希望删除只计1，恢复采用独立表达。管理员团队普通成员删除意见不自动执行，平等团队须至少1人明确希望删除且去重人数严格过半才触发删除；两种模式严格过半均触发恢复。仅在有效表达变化时按当时成员重算；成员或团队类型变化本身不触发，重复请求不触发。 |
