# 06｜完整用户旅程与交互流程

版本 v0.9｜2026-10-12

本稿描述从启动到旅行途中修改安排、记账与同步恢复的连续流程。[01-软件需求规格说明书](01-软件需求规格说明书.md)规定行为，[02-交互与界面设计稿](02-交互与界面设计稿.md)规定页面和控件，[04-研究验证与实施计划](04-研究验证与实施计划.md)规定后续验证。当前内容为正式设计，能力实现情况需由对应版本的验证记录确认。

## 1. 用户任务与整体路径

小林和小周准备一起去一座城市过周末。创建时选定目的地和起止日期，具体活动逐步补充。小林用电脑集中整理，小周主要用手机添加地点、调整活动和记账。小林为当前创建者，小周为团队成员。团队采用管理员或平等模式，所有成员都能新增和修改业务内容；删除与恢复按团队规则执行。

用户围绕同一份当前共享行程工作：按天记录安排，在地图收藏地点并看每天路线，在费用页记已支付与预计费用。只写“下午逛逛”就能成为一项安排，后续可逐步补充，也可到现场再决定。查看、分享和出行都直接使用当前行程。

```text
打开产品
  → 登录，或登录后继续原邀请
  → 继续上次编辑旅程 / 创建旅程 / 加入旅程 / 其他旅程
  → 进入旅程：行程 · 地图 · 费用
  → 直接添加与调整活动，按需收藏和记账
  → 自动保存、上传云端、同步同伴修改
  → 出行时仍看行程，随时改安排、导航、记支出
```

这些入口可以往返使用。添加活动无需先收藏；补时间、记费用无需等其他内容填齐；途中修改无需生成新草稿或等待组织者发布。沟通由用户在已有沟通工具中进行，产品内取消聊天、评论、议题和提案；删除与恢复使用对象旁的轻量表态机制。

## 2. 启动、登录与旅程选择

### 2.1 第一次打开

未登录时提供手机号或邮箱登录入口。用户从邀请链接或二维码进入时保留目标，登录后回到该邀请。认证失败留在当前步骤，说明可采取的动作。

已登录但没有旅程时，以“创建旅程”和“加入旅程”为主要动作。有最近编辑旅程时突出“继续旅程”，显示真实名称和已有日期；创建、加入仍可直接找到。“其他旅程”列出已加入但并非最近编辑的旅程。

小林点“继续旅程”回到上一个编辑旅程界面。完整恢复上次旅程上下文，包括页面、日期、滚动位置及编辑草稿。本地未上传草稿只能在原设备恢复；其他设备看到已同步内容。最近旅程失去访问权限时返回旅程列表，说明无法继续访问，并保留其他可用入口。

初始界面右上建议提供头像与个人设置，进入个人资料、通知、显示与动效等页面；旅程内使用同一套个人设置。

小林在当前旅程点击“返回首页”，保留本机草稿、浏览位置和待同步修改，继续拥有团队身份。首页可继续当前旅程，也可选择其他旅程编辑。进入另一旅程后，它成为新的最近旅程；再次打开原旅程恢复原有上下文。暂离不触发退出、继任、归档或清除，完整保存失败时先保留输入供重试或明确放弃。

### 2.2 创建一个空白旅程

1. 小林点“创建旅程”，输入“周末城市游”，填写目的地并选择出发与结束日期，明确选择“管理员团队”或“平等团队”。时区默认目的地当地，可在“更多设置”中调整。
2. 创建成功进入行程页，显示真实空状态和“添加活动”，同时可进入地图或邀请同伴。
3. 小林在第1天添加“下午逛逛”，可选“下午”，也可仅保留名称和第1天，地点、精确时间和费用留白。系统自动保留编辑并上传，云端确认后显示“已同步”。
4. 再次打开旅程，刚才的活动仍在。卡片正常呈现已有文字，未填的字段自然省略。

历史未确定真实日期的旅程继续使用第1天、第2天。后来设置日期时保留原有天和活动的对应关系；缩短日期范围时让用户看清受影响安排并保留原内容；多出内容放入可收起的“行程外安排”，可稍后移回，避免静默删除。设置日期不要求补齐活动时刻。

### 2.3 同伴加入

三种方式进入同一加入流程：

| 入口 | 用户动作与反馈 |
|---|---|
| 编码 | 打开“加入旅程”，输入编码，查看可公开的邀请信息并确认加入 |
| 手机扫码 | 在加入入口开启摄像头并扫描；拒绝授权、设备不支持或扫码失败时可返回输入编码或打开链接 |
| 邀请链接 | 直接进入邀请页；未登录先登录，返回后确认加入对应旅程 |

加入成功后进入该旅程。重复接受有效邀请返回已有成员身份。失效、撤销或无权接受时在当前步骤给出结果与下一步，保留必要输入。邀请有效性以服务端确认；成员加入同一个旅程团队。

具备邀请权限的用户在生成邀请时选择有效期限，再复制编码、二维码或链接；分享就是邀请对方加入同一团队，实际发送由用户自行完成。默认全员可邀请，创建者可逐人设置是否允许邀请他人；创建者和管理员可移除成员，团队类型由创建者切换。切换团队类型保留管理员任命。管理员在平等团队仍可移除成员、直接恢复和撤销邀请；直接删除权按团队类型变化，切回管理员团队后恢复该模式的直接删除权限和继任候选资格。创建者和管理员可以撤销邀请。取消成员邀请资格时，该成员此前生成的邀请同时失效，之后重新允许邀请也不会恢复旧邀请。被移除成员不能使用其被移除前生成的旧邀请重新加入，编码、二维码和链接采用同一规则。

## 3. 旅程内的界面与返回

主导航为**行程、地图、费用**。新进入旅程默认打开行程，继续旅程恢复上次位置。设置从侧导航独立进入；顶部成员头像直达成员与邀请，设置提供完整管理。手机第四个底部设置入口为本轮提案，见02的P12。

| 页面 | 主体与主要动作 |
|---|---|
| 行程 | 日期切换、按天活动列表、添加活动；活动详情按需展开 |
| 地图 | 收藏星标、日期与每日路线、选点、收藏和加入行程 |
| 费用 | 已支付明细与合计、额外标明的预计条目、“记一笔” |

电脑以有阅读宽度的行程正文为中心，点击活动可在侧面打开详情。手机使用单列列表和三个底部入口；较长编辑表单使用独立页面，短选项使用面板。行程页不常驻小地图、账本或额外仪表盘。

从详情返回保留日期、活动和滚动位置；从地图回行程恢复原位置。搜索详情返回保留关键词与筛选。浏览器返回与页面返回保持同样目标。已保存内容切页面不被清空，尚未同步的输入按其状态保留；需要放弃输入时动作含义明确。

导航、日期选择器、地图浮动控件和短操作面板采用类Liquid Glass材质；行程正文和长表单使用稳定易读的背景。无图稀疏列表本身具有完整布局，图片作为后续可选内容，不占空框。日期切换、详情展开和重排用简洁连续动画表达关系；快速操作可以中断衔接，输入与焦点保持。减少动态或透明效果时采用直接状态变化与更实背景。

## 4. 添加、选址与地图收藏

### 4.1 活动直接进入行程

小林在第1天点“添加活动”，填写“城市博物馆”，可直接搜索名称或地址、打开地图选点，也可选已有收藏。选定地点后回到当前活动继续编辑，无需先建立候选再加入。

搜索无结果时保留关键词，允许换词、地图选点或人工填写地点。地点暂未决定时只保存活动名称也可以。导航需要坐标或地址时，在打开导航的当下提供补充地点的入口。

选址后活动显示有用的地点信息，详情内可修改。真实服务提供的署名按要求展示；数据来源、刷新与人工更正的细节按需在维护入口提供。外部服务更新保留用户修改，不静默替换现有安排。反复访问同一地点可以建立多项活动。

### 4.2 地图收藏与每日路线

1. 首次进入地图时定位旅程目的地，展示团队全部共享收藏。暂离返回恢复上次视野，修改旅程目的地后重新定位；从活动进入则聚焦该活动地点。小周搜索一家餐厅，点星标收藏，全员可见；暂时没有安排到某一天。
2. 小周从地点详情点“加入行程”，选第1天晚上，添加成功后详情可见已安排日期。
3. 选择第1天，地图用顺序标记当天活动并突出路线，其他收藏弱化显示；切换第2天对应展示第2天安排。
4. 从行程点“在地图查看”带入日期和当前活动；返回恢复原日程位置。
5. 按团队删除权限取消餐厅收藏或表达希望删除，收藏删除生效后仍保留已安排活动；删除一次活动保留此前独立收藏的餐厅。

收藏星标与路线序号表达不同含义。餐饮、景点等类别和是否已安排分别标记，用户可按类别和安排状态筛选只看；筛选仅改变当前浏览视图。密集标记可通过辅助收藏列表与筛选查找，不靠图标堆叠区分全部状态。路线服务失败时保留已有地点与活动，指出当前请求失败并提供重试；缺少时长的路段保持留白。

手机布局提案的任务路径：底部搜索条 → 同一面板向上展开搜索结果 → 选择地点并收起键盘 → 面板切为摘要 → 收藏或加入行程。底部主导航在普通浏览和详情状态保持可达。取消搜索恢复原视角和详情。桌面对应使用悬浮侧栏旁的搜索/详情共用面板。地图始终铺满视口，面板变化只改变遮挡范围。具体层级和待评审项见02第5节。

## 5. 灵活时间、精确时间与到场安排

小林先将博物馆安排在第1天上午，暂不填精确起止。卡片按上午和顺序呈现，不自动生成09:00。晚餐已经约好时，可以填写18:30–20:00。活动支持之后在灵活和精确安排之间调整。

去看演出时，小周在活动里填写开始时间和提前10分钟到场，前往场馆的通勤单独设置。路段可选交通方式，使用真实路线结果或用户输入的时长。例如用户将步行时长从18分钟改为15分钟，编辑和常态展示同步更新；没有输入或服务结果时不补默认时长。常态界面显示交通方式和时长，维护细节放在设置入口。

| 操作 | 系统响应 |
|---|---|
| 调整一项活动顺序或日期 | 灵活活动可排序，具体时间活动按时间排列；单项移动到另一天保留钟点、时长或时段，提供非拖拽入口 |
| 已知两项精确时间重叠 | 在关联活动旁说明具体重叠，用户可以调整或继续保存 |
| 通勤与提前到场可能赶不上 | 给出具体时间差及相关活动，保留当前安排和编辑入口 |
| 时间、通勤或营业资料未定 | 对应内容留白，编辑入口可补充；不生成全局待核对清单 |
| 时间格式无法成立 | 在当前字段说明问题，保留其他输入，等待修正 |

活动可以只填开始；修改开始保持已有时长，修改结束改变时长。时间详情可填写结束后预留，用于计算最早离开。跨午夜显式选择结束日期，次日延续打开同一活动。

修改旅程日期时，小林在本次面板中选择要跟随的活动；选中项移动日期并保留钟点和时长，其余保持原日期。活动平时没有跟随改期设置。范围外内容仍可找到并移回；所有活动都能手动编辑，不提供时间锁或批量顺延。灵活活动可以插在精确活动之间；精确活动彼此按时间排序，灵活项不补造钟点；列表和通勤采用同一顺序。手动路程耗时保留，点击重新估算才替换；起终点改变时按新路段估算。

旅行可行性建议帮助用户选择安排。保存仍须正确处理格式、权限与真实写入竞争，界面分别表达这些情况，不要求填写接受原因。

## 6. 自动保存与共同编辑

### 6.1 完成修改即保存并共享

小林完成博物馆名称修改，小周完成餐厅地址修改，每次修改完成后自动保存。在线时自动上传并共享，其他成员自动更新；自己的输入、焦点、日期与阅读位置保持。云端确认前区分“已保存在此设备，等待同步”和“已同步”，无需手动发布。

离线时继续编辑，内容和待上传操作持久保存在设备上。刷新或重开后恢复草稿及队列，联网后自动上传和同步。换设备可以继续已同步内容，原设备尚未上传的编辑留在原设备等待同步。

### 6.2 普通修改按实际操作时间更新

同一内容的普通修改以真实操作发生时间较新的值为准。例如小林10:30离线把晚餐改为19:00，小周10:40已同步改为19:30；小林10:50联网上传后，晚餐仍为19:30。上传到达时间不改变这次先后关系。

不同对象的修改独立保留，重复或失序上传不重复产生内容，也不让较早操作覆盖较新结果。同步在相关对象上更新，保持正在编辑的草稿和焦点；存在无法可靠判定的异常时保留操作并给出处理入口，具体技术约束见03。

### 6.3 删除与恢复

创建者可设置和撤销管理员。创建者离开时，管理员团队优先从剩余管理员中选加入团队最早者；没有剩余管理员时，从剩余全体成员中选最早者继任。平等团队从剩余全体成员中选加入团队最早者。最后一人退出后，旅程永久清除。

| 团队模式 | 新增和修改 | 删除 |
|---|---|---|
| 管理员团队 | 全体成员可增改 | 创建者和管理员可直接删除；普通成员可表达“不参加”或“希望删除” |
| 平等团队 | 全体成员可增改 | 至少一名成员希望删除，且当前团队全部成员中，去重后的“不参加或希望删除”人数严格超过一半时软删除；创建者保留单独删除决定权 |

常规业务删除可恢复；最后一人退出永久清除旅程，不进入恢复流程。两种模式下，创建者、管理员可直接恢复；普通成员可以发起对象恢复表态，当前团队全部成员去重后的赞成恢复人数严格超过一半时恢复。删除与恢复入口围绕对象本身呈现，不扩展成讨论页或通用议题。

例如5人团队中，3人仅表达“不参加”时仍保留活动；其中至少1人再表达“希望删除”，才满足集体删除条件。2人不参加加另1人希望删除也满足条件。1人同时两种表达加另1人不参加只计2人，继续保留。同一成员重复表态只计一人。恢复使用独立的赞成恢复表态，全部5人中需3位不同成员赞成，删除表态不计入恢复票。

删除状态与普通字段修改分别处理。小林先删除活动，小周之后改时间，活动仍保持删除；时间修改保存在该活动中。满足恢复条件后重新显示活动，使用小周修改后的时间。时间修改不会触发复活，删除也不抹去字段内容。

“不参加”“希望删除”“支持恢复”均可修改或撤回。仅在有效表态发生变动时重新计算条件，使用届时的当前成员总数；成员进退或团队模式切换本身不触发表态阈值判断，重复提交同一表态也不触发重算。恢复后清除旧删除意愿，保留个人“不参加”状态。邀请和团队管理沿用第2节及本节权限规则。

## 7. 提前支出与途中记账

小周提前买好门票，在费用页点“记一笔”，记录已支付金额，可填写账目名称与备注，也可关联活动。名称留空时以状态和金额辨识。旅途中用餐或打车同样直接记账，无需先添加对应活动。行程卡不常驻费用统计。

预计支出可单独记录并明确标为“预计”。例如门票先记预计200元，付款后点“标记已支付”，输入实付180元。原条目更新为“门票180元 · 已支付”，从预计清单移出，已支付合计计入180元；页面不保留旧预计或差额对照。

账本主体为已支付明细与合计，预计额外标明。留空费用不当作零元，不生成补充费用任务。金额格式错误在当前字段说明，保存失败保留输入，重复重试不新增第二笔。账本保持已支付和预计支付的最小流程。

## 8. 查看、分享与旅途中使用

出发当天，小林直接打开行程，切到当天查看活动、地址、通勤与已有到场时间。灵活活动按时段或顺序显示，未设定的信息继续留白。无需另开出行手册，也无需先核对或生成定稿。

点击活动的导航入口打开外部地图，回到产品保留当天和活动位置。目标缺少定位信息时，在当前动作提供补充地址入口；外部地图打开失败时保留地址并提供复制或重试。

下雨后，小周直接把户外活动换成室内地点。修改经自动保存与同步进入同一份当前行程，小林看到更新时不被强行跳页。之后小周去费用页记一笔车费，继续返回当天安排。

用户从当前行程进入分享，生成邀请时选择有效期限，受邀者登录后加入同一团队，共同查看和修改当前旅程。分享不要求补齐未定内容，也不生成匿名只读页面或固定副本。

结束的旅程归档，用户仍可打开、编辑并与团队同步。业务删除按团队恢复规则找回。创建者离开时，管理员团队优先从剩余管理员中选加入团队最早者；没有剩余管理员时，从剩余全体成员中选最早者继任。平等团队从剩余全体成员中选加入团队最早者。最后一人退出后，旅程永久清除。最后一人退出时明确显示永久清除结果，确认退出成功后移除该旅程，不能通过恢复入口、旧邀请或离线补传找回。账号注销流程另行设计。

## 9. 失败恢复贯穿全过程

| 情况 | 保留什么、显示什么 | 下一步 |
|---|---|---|
| 首次加载失败 | 保留旅程目标，显示加载失败，避免假空列表 | 重试或返回可访问旅程 |
| 搜索/路线服务失败 | 保留搜索词、活动和已有地点，说明对应请求失败 | 换关键词、人工补充或重试 |
| 保存失败或断线 | 本地持久保留输入与待上传操作，持续表达尚未同步 | 恢复连接后自动上传并按实际操作时间同步 |
| 保存响应丢失 | 保留输入，显示结果待确认 | 查询提交结果或受控重试，避免重复活动和费用 |
| 会话过期 | 保留未同步编辑，显示重新登录入口 | 登录后回原目标，复核权限与内容再继续 |
| 权限被撤销 | 停止私有数据读取、订阅与写入，明确当前访问结果 | 返回可访问旅程；保留必要未提交输入供用户处理 |
| 普通编辑竞争 | 按实际操作时间保留较新修改，保持当前编辑上下文 | 接收同步结果，用户可继续修改 |
| 已删除对象收到修改 | 保留删除状态及新字段值 | 由有权用户直接恢复或按过半表态恢复 |
| 收到他人更新 | 保持自己的输入、焦点和阅读位置 | 更新安全区域，必要时就地查看变更 |

离线编辑、本地持久化、刷新重开恢复及联网自动上传均纳入正式验证。提示围绕具体结果与下一步，不把未知资料变成日常待办。

## 10. 连续验收与需求对应

演示及验证从空白账号开始，使用电脑与手机的独立会话：

1. 登录，填写旅程名称并明确选择团队类型，添加仅有名称和日序的“下午逛逛”，等待真实云端确认后重新打开。
2. 第二位用户通过编码、扫码或链接加入；验证手机号/邮箱认证返回目标、生成邀请选期限与重复接受。
3. 直接搜索地址或地图选点新增活动，再收藏地点并加入另一天，检查收藏与路线关系。
4. 设置灵活与精确时间、到场缓冲和通勤；非拖拽移动活动，保留一组重叠与一项留白并继续保存和分享。
5. 手机直接看当天安排、导航、临时改地点；另一端观察真实更新。
6. 记已支付餐费，将预计200元门票替换为已支付180元，检查明细与合计。
7. 两端先改不同活动，再按不同真实操作时刻修改同一内容；离线端晚上传不能覆盖后发生的修改。断线编辑后刷新重开，联网自动上传；检查队列、草稿、焦点及状态。
8. 在两种团队模式验证删除权限、全部成员严格过半去重、直接恢复与过半恢复；先删除后修改时间，恢复后保留新时间。
9. 用真实录入的稀疏无图、密集长文本完成上述路径，检查玻璃控件可读性和连续可中断动画。
