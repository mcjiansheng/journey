## 讨论依据

### 第一轮：整体方向与启动流程

用户认为原型像后台管理系统，信息和按钮较多，希望有旅行感、简洁、首要动作明确，复杂功能按需出现。提出自动保存、上传云端、自动同步和冲突处理，并明确启动后的五类入口。

### 第二轮：页面职责与活动编辑

用户倾向原型中按天呈现活动的主布局，要求移走右侧地图和账本；以苹果日历截图说明编辑方式，以高德星标截图说明地图收藏；要求考虑通勤与提前到场，支持直接选址。费用需要记录提前订票及旅途中开销；讨论和出行手册独立页面没有必要。

### 第三轮：沟通与费用取舍

用户进一步明确不需要沟通系统。费用以已支付为准，预计额外表明；支付后只保留已支付。此前提出的对象留言、预计与实际对照建议已删除。

### 第四轮：正式产品的设计原则

用户要求类Apple Liquid Glass效果和简洁流畅的动画；指出每项活动插画、没有编辑入口的“约20分钟”、冗余“手动估计”、自动旅行感言、补零日序和待核对清单脱离真实使用。未确定内容允许留白，正式版应从规则与开发方法上避免这些问题。

本轮材料包括用户消息中的苹果日历编辑、高德地图星标及本地原型截图；截图仅作为设计输入，不向正式数据中复制示例地点、金额或账号内容。

### 第五轮：团队权限、自动合并与离线恢复

用户当时明确管理员团队与平等团队的区别，创建者固定并控制管理员；离开后的继任规则已由第七轮补充。普通成员均可添加、编辑；删除权限和集体删除条件按下节执行。

每次修改完成即自动保存并在线共享，同伴自动更新。普通竞争取修改发生时间最新值；删除优先于普通编辑，删除期间的新修改保留到恢复后使用。断网时本地持久保存，联网后自动上传。

用户进一步确认：过半按当前团队全部成员计算；创建者和管理员可直接恢复，普通成员可通过过半支持恢复。用户随后补充：只有不参加人数过半而无人希望删除时，活动保留。

分享即邀请加入同一旅程团队；手机号或邮箱登录；生成邀请时选择期限；继续旅程完整恢复计划和使用上下文。记账细节本轮不再展开。

## 团队、删除与恢复规则

### 两类团队

| 操作 | 管理员团队 | 平等团队 |
|---|---|---|
| 添加、编辑共享内容 | 所有成员 | 所有成员 |
| 直接删除 | 创建者与管理员 | 创建者 |
| 普通成员对活动表达不参加/希望删除 | 可表达，由有删除权的人处理 | 可表达，满足集体删除条件后自动临时删除 |
| 直接恢复 | 创建者与管理员 | 创建者与管理员 |
| 集体恢复 | 当前全体成员中明确支持恢复者严格过半 | 当前全体成员中明确支持恢复者严格过半 |
| 指定、撤销管理员 | 创建者 | 创建者保留管理员管理权和团队模式切换权 |

创建者离开时，管理员团队优先从剩余管理员中选加入团队最早者；没有剩余管理员时，从剩余全体成员中选最早者继任。平等团队从剩余全体成员中选加入团队最早者。最后一人退出后，旅程永久清除。原始创建记录保留，当前管理职责由继任者承担。管理员与创建者对内容的编辑仍遵守同一按修改发生时间合并的规则。

### 平等团队集体删除

须同时满足：

1. 至少一位当前团队成员明确希望删除该活动。
2. 当前团队成员中，表示不参加或希望删除的人数去重后，严格超过全体成员的一半。

同一人同时表示不参加和希望删除只计一次；创建者也计入团队总人数。创建者的直接删除权独立于集体条件。管理员团队的普通表态不自动触发集体删除。

| 5人团队的表达 | 结果 |
|---|---|
| 3人只表示不参加，无人希望删除 | 保留活动 |
| 上述3人中有1人同时希望删除 | 去重3人，满足两项条件，临时删除 |
| 2人不参加，另1人希望删除 | 去重3人，临时删除 |
| 1人同时不参加且希望删除，另1人不参加 | 去重2人，保留活动 |

“我不参加”表达个人参与情况，“希望删除”表达对共享安排的处理意愿，界面分别呈现。对没有参加含义的共享内容，只能通过删除意愿进入对应流程，沿用团队权限和过半条件，不计入不参加人数。

### 临时删除与恢复

常规旅程业务删除采用可恢复状态，最后一人退出永久清除旅程除外，日常列表隐藏对象，恢复入口仍能找到。普通内容编辑不会取消删除。

A先删除活动，B随后修改时间：对象仍为已删除，B的时间修改参与内容同步；有权恢复或集体恢复成功后，显示合并后的最新时间。恢复只解除删除状态，不把内容回滚到删除时刻。

创建者、管理员可以直接恢复；普通团队成员可以表达支持恢复，当前团队全部成员中的明确支持人数严格过半后恢复。删除意愿、不参加和恢复意愿分开记录，不能把一类表达推算成另一类。恢复活动清除旧删除意愿，保留个人参与状态；再次删除需要新的删除意愿。

旧的删除与恢复消息不能反复推翻已完成的新一轮处理。对象生命周期代次、幂等和多数条件由03给出工程方案；“不参加”“希望删除”“支持恢复”均可修改或撤回。仅在有效表态发生变动时重新计算条件，使用届时的当前成员总数；成员进退或团队模式切换本身不触发表态阈值判断，重复提交同一表态也不触发重算。恢复后清除旧删除意愿，保留个人“不参加”状态。

## 保存与离线时序

| 场景 | 已确定结果 |
|---|---|
| 完成一次修改且在线 | 先可靠保存操作，自动上传，云端同步后同伴自动更新 |
| 完成一次修改但断网 | 内容和待上传操作保存在本地，重开可继续；联网自动上传并同步 |
| A10:30离线修改，B10:40修改并同步，A10:50才上传 | 同一内容保留B10:40的修改，A的上传时间不改变原操作时间 |
| 删除后收到较新内容编辑 | 保持删除，新内容保存在对象中，恢复后可见 |
| 点击继续旅程 | 恢复同一计划、页面、日期、位置、所选对象及未完成编辑；同步云端变化并保护本地输入 |

普通编辑按内容发生的时间比较。字段或逻辑字段组的拆分、设备对时、同时间操作的确定顺序等属于03需要验证的实现问题，不再把普通冲突默认交给用户人工比较。

“全部恢复”覆盖可取得的本机及云端状态；某设备从未上传的离线修改仍在该设备，回到它后恢复并补传。其他设备先恢复已同步的计划和上下文。

## 交互问题状态与剩余讨论

### Q01｜编辑完成与冲突：已确定

完成一次修改自动保存并共享；普通竞争按修改发生时间取最新；删除为独立状态。正常编辑操作结束即为完成一次修改，不再作为待确认的产品问题；未完成输入仍在本机保留。

### Q02｜成员权限：已确定

两类团队的增改、删除和恢复权限按上表。默认全员可邀请，创建者可逐人设置是否允许邀请他人；创建者和管理员可移除成员，团队类型由创建者切换。成员变化本身不触发集体条件重算。切换团队类型保留管理员任命。管理员在平等团队仍可移除成员、直接恢复和撤销邀请；直接删除权按团队类型变化，切回管理员团队后恢复该模式的直接删除权限和继任候选资格。创建者和管理员可以撤销邀请。取消成员邀请资格时，该成员此前生成的邀请同时失效，之后重新允许邀请也不会恢复旧邀请。被移除成员不能使用其被移除前生成的旧邀请重新加入，编码、二维码和链接采用同一规则。非活动内容仅有删除意愿，不使用“不参加”。

### Q03｜离线工作：已确定

本地持久编辑、重开恢复、恢复连接后自动上传同步均纳入正式范围。对时误差、当前权限变化、队列重试和跨设备收敛属于实施验证，不继续作为是否支持离线的功能选择。

### Q04｜日期、顺序与时间联动：已确定

| 场景 | 已确认行为 |
|---|---|
| 时间精度 | 可留白、仅时段或具体时间；可只填开始；切回模糊时段后旧精确值停止参与计算 |
| 修改起止 | 改开始保持已有时长，改结束改变时长；不补默认时长 |
| 保护与批量工具 | 去掉时间锁、批量顺延及自动调整后续安排；所有活动可手动编辑 |
| 同日顺序 | 灵活活动可手动插在精确活动之间；精确活动彼此按时间排列，编辑时间改变先后；不为灵活项补造钟点 |
| 单项跨日 | 保留钟点、时长或模糊时段，更新相关路段 |
| 旅程改期/两天交换 | 在当次修改日期时手动选择跟随活动，选中项移动日期并保留钟点和时长；未选项保留原日期。选择不成为活动常驻设置 |
| 缩短旅程 | 多出内容保留在可收起的行程外安排；所有活动保留已有日期、钟点及时长，未定日期的保留原计划日及时间意向；可稍后移回，不触发删除 |
| 通勤更新 | 自动估算随相关输入更新；手动值点击重新估算才替换；起终点变化按新路段估算，不沿用旧手动值 |
| 缓冲 | 提前到场与结束后预留均选填，分别用于倒推出发和计算最早离开，默认不设置 |
| 后续安排 | 活动延长或路程改变不顺延其他活动，需要时手动修改 |
| 跨午夜 | 明确选择结束日期；归开始日，次日延续引用同一活动 |

第六轮确认以上规则。用户进一步明确：跟随活动在修改日期时临时选择，不在活动上增加“随旅程改期”开关。

第八轮确认混排规则：灵活项可以插在精确项之间，精确项彼此保持时间顺序，不给灵活项补造钟点；列表与前后通勤使用同一有效行程顺序。

### Q05｜地图收藏：已确定

收藏由当前团队全体成员共享。默认展示全部收藏，可突出选定某天的路线；标记区分餐饮、景点等类别及未安排等状态，也可手动筛选只看相应内容。类别与安排状态独立，突出路线不自动隐藏其他收藏；主动筛选仅改变个人浏览视图。取消收藏不删除已安排活动。

### Q06｜记账：本轮不展开细节

保留已支付为主、预计单独标明、支付后替换的最小账本。付款人、分摊、预算分析、部分支付等不作为本轮待回答清单；账目增改删除与恢复遵循已确定团队及同步规则。

### Q07｜删除恢复与分享：已确定

分享统一邀请加入团队，常规删除后的内容可以恢复；最后一人退出永久清除旅程。不提供匿名只读副本或固定版本分享。“不参加”“希望删除”“支持恢复”均可修改或撤回。仅在有效表态发生变动时重新计算条件，使用届时的当前成员总数；成员进退或团队模式切换本身不触发表态阈值判断，重复提交同一表态也不触发重算。恢复后清除旧删除意愿，保留个人“不参加”状态。恢复列表从次级“已删除”入口进入。通用修改历史、多方案与复杂导出暂不展开。

### Q08｜登录与继续：主要规则已确定

手机号或邮箱登录，邀请生成时选择有效期，继续完整恢复旅程上下文。结束旅程归档后仍可编辑。创建者离开时，管理员团队优先从剩余管理员中选加入团队最早者；没有剩余管理员时，从剩余全体成员中选最早者继任。平等团队从剩余全体成员中选加入团队最早者。最后一人退出后，旅程永久清除。旅程存续时，管理职责按此继任并保留原始创建记录。永久清除后不进入恢复列表，旧邀请和离线补传不得重新创建该旅程。账号注销的账户流程单独设计。

## 第七轮：共享地图与团队管理

共享收藏、邀请资格管理、成员移除和团队类型切换按Q02/Q05确定。“不参加”“希望删除”“支持恢复”均可修改或撤回。仅在有效表态发生变动时重新计算条件，使用届时的当前成员总数；成员进退或团队模式切换本身不触发表态阈值判断，重复提交同一表态也不触发重算。恢复后清除旧删除意愿，保留个人“不参加”状态。结束的旅程归档但继续可编辑。创建者离开时，管理员团队优先从剩余管理员中选加入团队最早者；没有剩余管理员时，从剩余全体成员中选最早者继任。平等团队从剩余全体成员中选加入团队最早者。最后一人退出后，旅程永久清除。这条离开后的继任规则取代此前创建者身份永久不转交的限制。用户要求不再拆解讨论“完成一次修改”。

## 第八轮：审查问题确认

用户采纳灵活活动插入精确活动之间、模式切换保留管理员任命及其他已定管理员权限的建议。管理员团队无剩余管理员时从剩余成员选加入最早者；最后一人退出永久清除旅程，作为常规软删除的明确例外。取消邀请资格使其以前生成的邀请失效；被移除成员不能用旧邀请重入；创建者和管理员可撤销邀请。上述规则已直接同步正文及验收。
