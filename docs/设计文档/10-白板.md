## 0. 范围

白板是旅程里的自由画布。成员可以贴便签、文字、表情、图片（含 GIF），可以手绘，也可以贴**小组件**。小组件像手机桌面小组件，有固定的小、中、大规格，显示行程、收藏、费用里的真实数据并随之变化。便签和地点小组件可以反向「加入行程」。

不做：评论串与投票、字符级协同编辑、像素级橡皮、跟随贴纸的连线、网页预览抓取、第三方 GIF 搜索、天气小组件（无数据源）、按天自动排版。

对已确认基线的改动，实现时同步更新对应文档：

| 改动 | 涉及文档 |
|---|---|
| 主入口变为「行程 / 地图 / 白板 / 费用」，手机底栏加设置共五项 | 00、02 第 1、3 节 |
| `boardItem` 的删除与恢复不走表态，任何成员可直接执行 | 01 业务规则、05 |
| 新增不入库的在线状态通道（presence） | 03、`app/CONTRACT.md` |

## 1. 架构总览

```
服务端 SQLite objects 表
  ├─ board, boardItem（新增 kind）
  └─ day, activity, favorite, route, expense（已有）

GET /api/trips/:id            主快照：已有对象 + board，不含 boardItem
GET /api/trips/:id/boards/:boardId/items?since=   白板对象增量
POST /api/trips/:id/operations                    所有写入（含白板）
PUT/GET /api/trips/:id/assets/:assetId            图片与 GIF
POST /api/trips/:id/boards/:boardId/presence      在线状态上行（不入库）
GET /api/trips/:id/events                         SSE：change（已有）+ presence（新增）

客户端
  useJourney()（已有）── snapshot ─────────┐
  board-sync.js ── boardItems、peers ────────┤
                                            ▼
  Board.jsx ── 视口、手势、z 排序渲染 ── BoardItem.jsx
                                            └─ 小组件：widgetModel(snapshot, item) → WidgetView 组件
```

关键原则：

1. **小组件不存数据，只存指向。** 显示内容每次由纯函数从主快照现算（第 4 节）。所以行程、收藏、费用一改，白板自动跟着变；后端不需要为小组件做任何计算或推送。
2. **白板对象走现有操作协议。** 合并、离线队列、临时删除与恢复全部复用；只加三项后端能力：增量加载、图片存储、在线状态。
3. **所有白板对象共用一个 z 序。** 贴纸、小组件、图片、笔迹、形状之间可以任意互相遮挡。

## 2. 数据模型（服务端）

`operationSchema.objectType` 增加 `'board'`、`'boardItem'`。两者存进现有 `objects` 表，沿用 `state`、`generation`、`clocks`。

### 2.1 schema

放进 `app/server/model.mjs` 的 `schemas`，写法与现有条目一致（`id`、`url`、`place`、`number` 是该文件已有的基础类型）。

```js
const noteColor  = z.enum(['yellow','green','blue','pink','purple','gray']);
const inkColor   = z.enum(['default','accent','red','orange','blue','purple']);
const hlColor    = z.enum(['yellow','green','blue','pink']);
const coord      = z.number().finite().min(-1e6).max(1e6);
const frame = z.object({
  x: coord, y: coord,
  w: z.number().min(0).max(8000), h: z.number().min(0).max(8000),
  rotation: z.number().min(-180).max(180).default(0),
  scale: z.number().min(0.3).max(8).default(1),        // 只有文字贴纸使用：字号倍率
}).strict();

const WIDGET_KINDS = {                                   // kind → 允许的规格；第一个是默认
  activity: ['S','M'], day: ['S','M','L'], place: ['S','M'], route: ['M','L'],
  countdown: ['S','M'], clock: ['S','M'], expense: ['S','M'],
};

const boardContent = z.discriminatedUnion('type', [
  z.object({ type: z.literal('note'),  text: z.string().max(500) }).strict(),
  z.object({ type: z.literal('text'),  text: z.string().max(500) }).strict(),
  z.object({ type: z.literal('emoji'), char: z.string().min(1).max(16) }).strict(),
  z.object({ type: z.literal('image'), assetId: id,
             mime: z.enum(['image/jpeg','image/webp','image/png','image/gif']),
             width: z.number().int().positive(), height: z.number().int().positive(),
             animated: z.boolean().default(false), caption: z.string().max(60).default('') }).strict(),
  z.object({ type: z.literal('link'),  url, title: z.string().max(80).default('') }).strict(),
  z.object({ type: z.literal('widget'),
             kind: z.enum(Object.keys(WIDGET_KINDS)),
             activityId: id.optional(), dayId: id.optional(), favoriteId: id.optional(),
             place: place.optional() }).strict()
     .superRefine((v, ctx) => {
       const need = { activity: ['activityId'], day: ['dayId'], route: ['dayId'] }[v.kind] || [];
       for (const k of need) if (!v[k]) ctx.addIssue({ code: 'custom', message: '小组件缺少目标', path: [k] });
       if (v.kind === 'place' && !!v.favoriteId === !!v.place) ctx.addIssue({ code: 'custom', message: '地点小组件须且只能指定收藏或独立地点' });
       const allowed = { activity: ['activityId'], day: ['dayId'], route: ['dayId'], place: ['favoriteId','place'] }[v.kind] || [];
       for (const k of ['activityId','dayId','favoriteId','place']) if (v[k] !== undefined && !allowed.includes(k)) ctx.addIssue({ code: 'custom', message: '多余的目标字段', path: [k] });
     }),
  z.object({ type: z.literal('stroke'), tool: z.enum(['pen','highlighter']),
             points: z.array(z.tuple([z.number(), z.number()])).min(1).max(1000) }).strict(),   // 相对 frame 左上角
  z.object({ type: z.literal('shape'), kind: z.enum(['rect','ellipse','line','arrow']), filled: z.boolean().default(false) }).strict(),
]);

schemas.board = z.object({
  title: z.string().trim().min(1).max(30),
  order: z.number().finite().default(0),
  background: z.enum(['dots','grid','plain']).default('dots'),
}).strict();

schemas.boardItem = z.object({
  boardId: id,
  frame,                                                  // 逻辑组：位置、尺寸、旋转、字号倍率
  z: z.number().finite().default(0),                      // 逻辑组：层级
  content: boardContent,                                  // 逻辑组：内容（type 与 widget.kind 创建后不可变）
  style: z.object({                                       // 逻辑组：外观
    color: z.string().max(12).optional(),
    size: z.union([z.enum(['title','body','small']), z.enum(['S','M','L']), z.number().min(1).max(32)]).optional(),
    frameStyle: z.enum(['none','polaroid']).optional(),
    locked: z.boolean().optional(),
  }).strict().default({}),
  linkedActivityId: id.nullable().default(null),          // 逻辑组：「加入行程」后指向生成的活动
  createdBy: id,                                          // 服务端写入
}).strict();
```

`style` 的取值再按 `content.type` 校验一次（zod 之后、写库之前，在 `validateBoardItem()` 里做）：

| content.type | style.color | style.size | style.frameStyle |
|---|---|---|---|
| note | noteColor，必填 | 不允许 | 不允许 |
| text | 不允许（用 `text` 色） | title / body / small，必填 | 不允许 |
| stroke（pen） | inkColor，必填 | 2 / 4 / 8 | 不允许 |
| stroke（highlighter） | hlColor，必填 | 16 | 不允许 |
| image | 不允许 | 不允许 | none / polaroid |
| widget | 不允许 | `WIDGET_KINDS[kind]` 中的一个，必填 | 不允许 |
| 其余 | 不允许 | 不允许 | 不允许 |

### 2.2 合并

五个顶层键 `frame`、`z`、`content`、`style`、`linkedActivityId` 各是一个逻辑组，整组替换、各自带时钟。这正是 `applyOperation` 对普通对象的默认路径（按顶层键比较 `clocks[k]`），不需要像 favorite、route 那样加 `$group`。客户端 patch 只发送变动的组，并且每组发**完整的新值**。

### 2.3 层级与缩放

- 同一块白板上所有对象共用一个 `z` 序，没有「笔迹层」「贴纸层」。新建对象（包括新画的一笔）取当前最大 z + 1。「置顶」取最大 z + 1，「置底」取最小 z − 1；多选时按原有相对顺序依次加减 1。
- 荧光笔与其他对象的区别只在混合方式（浅色 multiply、深色 screen），不在层级。
- 缩放只改 `frame`：小组件改 `w/h`（等比，见 7.4）；文字改 `scale`；笔迹改 `w/h`，点坐标不变。

### 2.4 服务端校验步骤

在 `applyOperation` 里，`objectType` 为 `boardItem` 时按顺序执行：

1. **create**：`payload.createdBy = userId`（覆盖客户端值）；`schemas.boardItem` 解析；`validateBoardItem()`。
2. **patch**：拒绝 patch 中出现 `boardId`、`createdBy`（`VALIDATION`）；若 patch 含 `content`，新旧 `content.type` 必须相同，`widget` 的 `kind` 也必须相同；合并后整体重新解析与 `validateBoardItem()`。
3. **references()** 增加：
   - `boardId` 是本旅程 `kind='board'` 的对象（`deleted` 也允许，便于恢复）。
   - widget：`activityId` → 本旅程 activity；`dayId` → 本旅程 day；`favoriteId` → 本旅程 favorite。`linkedActivityId` → 本旅程 activity。
   - 目标处于 `deleted` 时**允许**，不拒绝、不级联。跨旅程或类型不符返回 `INVALID_REFERENCE`。
4. **容量**：每段旅程 active board ≤ 20；每块 board 的 active boardItem ≤ 2000。超出返回 `BOARD_FULL`（409）。恢复操作同样受容量约束。
5. **delete / restore**：对 `boardItem` 任何成员都可直接执行；`express` 返回 `VALIDATION`。`board` 保持现有规则（管理员团队由管理员删，平等团队走表态）。
6. **游标**：写入或改变状态后，把该对象的 `changedCursor` 设为本次递增后的 `trips.cursor`（见 3.1）。

删除 board 时其下 boardItem 不改状态；客户端在 board 为 `deleted` 时不显示它的内容，恢复 board 后原样出现。

### 2.5 错误码

| code | HTTP | 场景 |
|---|---|---|
| VALIDATION | 400 | schema 不符；patch 改 boardId / createdBy / type / kind；对 boardItem 表态 |
| INVALID_REFERENCE | 400 | 目标不属于本旅程或类型不符 |
| BOARD_FULL | 409 | 白板数或对象数超出上限 |
| ASSET_TYPE | 415 | 文件头不是 JPEG / PNG / WebP / GIF |
| ASSET_TOO_LARGE | 413 | 静态图超过 1.5MB，GIF 超过 5MB，缩略图超过 300KB |
| ASSET_CONFLICT | 409 | 同一 assetId 再次上传但内容不同 |
| ASSET_QUOTA | 413 | 仅在配置了 `ASSET_QUOTA_BYTES` 时 |
| PRESENCE_RATE | 429 | presence 上行超频 |

## 3. 服务端接口

除下列新增项，白板读写全部走现有 `POST /api/trips/:id/operations`。

### 3.1 白板对象增量加载

主快照在每次 `change` 后都会被客户端重读；用久的白板有几百条笔迹，不能放进主快照。

- 迁移：`objects` 增加 `changedCursor INTEGER NOT NULL DEFAULT 0`，索引 `(tripId, kind, changedCursor)`。`migrations` 表登记新版本号。
- `snapshot()` 增加 `WHERE kind != 'boardItem'`；`board` 留在主快照。
- 新接口 `GET /api/trips/:id/boards/:boardId/items?since=<cursor>`，成员可读：
  - 无 `since`：返回该白板全部 boardItem（含 `deleted`，供「最近删除」）。
  - 有 `since`：只返回 `changedCursor > since` 的对象。
  - 响应 `{ items: [Object], cursor, epoch }`，`Object` 与快照中的对象格式相同。
- SSE `change` 事件不变。客户端在白板页收到后调用增量接口；不在白板页不调用，进入时再取。`epoch` 与本地缓存不同 → 清空本地缓存并全量重读。
- 操作回执：`objectType` 为 `boardItem` 时 `POST /operations` 的响应省略 `snapshot`，只返回 `receipt`；客户端随后取增量。
- 离线：IndexedDB 按 `tripId/boardId` 存 boardItem 和本地 `cursor`；写入队列与现有队列是同一个，保持顺序。

### 3.2 图片与 GIF

- `PUT /api/trips/:id/assets/:assetId?variant=full|thumb`，请求体为二进制。`assetId` 由客户端生成（同 object id 格式）。
  - 只挂 `express.raw({ type: () => true, limit: '5mb' })` 在这一个路由上，不改全局 `express.json`。
  - 按文件头判定类型，不信任 `Content-Type`；只接受 JPEG、PNG、WebP、GIF。
  - 体积上限见 2.5。同一 id 再次上传：内容 SHA-256 相同返回 200，不同返回 `ASSET_CONFLICT`。
  - 限流：每用户每分钟 60 次，写法同 `security.mjs`。
- `GET` 同路径：仅成员；`Cache-Control: private, max-age=31536000, immutable`；`X-Content-Type-Options: nosniff`；`Content-Type` 用落盘时判定的类型。
- 落盘：`app/data/assets/<tripId>/<assetId>.<variant>`（写临时文件再 rename）。纳入 `ops/backup.mjs`；旅程永久清除时删除整个目录。
- 本期不设每段旅程的总量上限（2026-11-10 确认）。保留配置项 `ASSET_QUOTA_BYTES`，默认不启用。

客户端处理：

| 类型 | full | thumb |
|---|---|---|
| JPEG / PNG / WebP | 压缩到长边 ≤ 2048px，重新编码为 JPEG 或 WebP（同时去除 EXIF），≤ 1.5MB | 长边 400px |
| GIF | **原文件上传，不重新编码**（重编码会丢动画），≤ 5MB | 第一帧，长边 400px，静态 WebP |

先上传两个文件，成功后再提交 `create boardItem`。离线时文件存 IndexedDB，贴纸本地先显示并带「待上传」角标，联网后按顺序补传再提交。

GIF 显示规则：贴纸在视口内且屏幕显示宽度 ≥ 48px 时播放 `full`，否则显示 `thumb`；同屏最多同时播放 12 个，按离视口中心远近取舍；系统开启「减少动态效果」时一律显示 `thumb`，中央叠播放按钮，点一次播放一轮；导出图片取第一帧。

### 3.3 在线状态（presence）

现有 SSE 是单进程内存里的 `streams`，足够承载，不需要 WebSocket。

上行：

```
POST /api/trips/:id/boards/:boardId/presence
{ deviceId, selected: [itemId],        // 最多 20 个
  editing: itemId | null,              // 正在编辑其文字的贴纸
  live: { [itemId]: frame } | null,    // 拖动或缩放中的临时位置
  leave?: true }
→ 204
```

下行：在现有 `GET /api/trips/:id/events` 上新增事件，只发给同旅程的**其他**连接：

```
event: presence
data: { boardId, userId, deviceId, displayName, colorIndex, selected, editing, live, at }
data: { boardId, userId, deviceId, leave: true }
```

服务端：

- 只存内存：`Map<tripId, Map<userId:deviceId, state>>`。不写库、不改 cursor、不触发 `change`。
- 15 秒没有某设备的上行即视为离开，向其他连接发 `leave`；该设备的 SSE 连接关闭时同样处理。
- 新 SSE 连接建立后，立即补发当前全部在线状态。
- 每设备每秒最多 15 次上行，超出返回 `PRESENCE_RATE`；客户端丢弃这一条，不重试。
- 校验 `selected`、`editing`、`live` 中的 id 属于该白板；`live` 的值走 2.1 的 `frame` 模式。
- `colorIndex = (joinOrder - 1) % 4`，同一成员在所有人屏幕上颜色一致。

客户端：

- 选中变化、进入或退出文字编辑时立即上行；之后每 5 秒心跳。
- 拖动、缩放中以 ≥ 60ms 间隔上行 `live`；松手时**先**提交 `patch frame`，**再**上行 `live: null`。
- 收到他人 `live`：本机临时覆盖该对象位置，不写数据；收到对应 `frame` 操作或 `live: null` 后撤销。本机正在操作的对象忽略他人 `live`。
- 显示与软占用见 7.6。不显示鼠标光标，不显示笔迹绘制过程（抬笔后整笔出现）。
- 降级：SSE 断开或上行连续失败 3 次 → 头像栏显示离线，隐藏所有他人框；数据同步不受影响；重连后自动恢复。

## 4. 小组件数据口径

所有小组件的显示内容由 `app/src/board-widgets.js` 中的纯函数从主快照算出，不依赖 DOM，三端照同一口径实现。原型脚本第 2 段的 `*Model()` 与渲染函数可逐行对照。

### 4.1 入口

```js
export function widgetModel(snapshot, item, { now = Date.now(), deviceTimeZone } = {})
// → { kind, size, gone: boolean, ...各 kind 的字段 }
export const WIDGET_SIZES = { S: [168,168], M: [352,168], L: [352,352] };
export const WIDGET_KINDS = { /* 同 2.1 */ };
export function widgetSize(item)        // style.size 不在允许列表时回退到该 kind 的默认规格
```

### 4.2 共用规则（必须复用现有函数，不得另写）

| 需要的值 | 用什么 |
|---|---|
| 当天活动顺序与序号 | `orderedActivities(snapshot, dayId)`；序号 = 下标 + 1 |
| 时间文案 | `timeLabel(activity.payload)` |
| 第 N 天 | `dayLabel(day, trip)` |
| 两项之间的路程 | 与行程页相同：`fromId === (前一项?.id ?? null) && toId === 本项.id` 的 route，优先 active |
| 建议出发时间 | `travelAdvice(prev, activity, route).depart` |
| 交通方式文案 | `{ walking:'步行', driving:'驾车', bicycling:'骑行', transit:'公共交通' }` |
| 金额 | `money(amountMinor, currency)`；小组件里整元时省略「.00」 |
| 费用日期、名称 | `expenseDate()`、`expenseTitle()`（`app/src/expenses.js`） |
| 收藏标记 | `marks.js` 的 `markPaths`、`markColors`；`mark` 为 null 时用 `{ icon:'star', color:'amber' }` |
| 「今天」 | 目的地时区 `trip.timezone` 的日历日期（`Intl.DateTimeFormat('en-CA', { timeZone })`） |

时段（用于配色，见 5.4）：`hourOf(activity)` = 精确时间取开始时刻的小时数（含分钟小数）；灵活时间 `morning` 9.5、`afternoon` 15、`evening` 20；其他为 `null`。

### 4.3 activity（日程）

```
target = activities[activityId]
gone   = !target || target.state === 'deleted' || 所在 day 为 deleted
{ title, dayLabel, dateLabel(M/D), index, time: { text, start, end, precise }, placeName,
  bufferBefore, legText /* 「公共交通约 22 分钟 · 建议 11:53 出发」，无路程为 '' */, notes, hour }
```

- `index`：在 `orderedActivities` 里的位置 + 1；gone 时为 null，不显示序号。
- `time.text`：`timeLabel()`；为空时显示「时间待定」。精确时间拆成 `start` 与 `end`（「至 11:30」）。
- `legText` 只在中号显示；有 `legText` 时不显示备注。

### 4.4 day（这一天）

```
target = days[dayId]；gone = !target || target.state === 'deleted'
{ dateNumber /* 日期中的「日」，无日期时为 dayLabel 的序数 */, weekday, dayLabel, count,
  items: orderedActivities(...).map(a => ({ id, title, timeText, placeName, hour, legIn })) }
```

- `legIn`：到达这一项的路程文案「公共交通约 22 分钟」，无则 null。
- 小号显示前 2 项、中号前 3 项、大号前 4 项；超出显示「还有 N 项」。没有安排显示「这天还没有安排」。
- 无日期的计划日：`dateNumber` 显示序数，`weekday` 显示「未定日期」。

### 4.5 place（地点）

```
fav = favorites[favoriteId]（或 content.place 的独立地点）
gone = favoriteId 时 !fav || fav.state === 'deleted'；独立地点永不 gone
{ name, address, category, mark: { icon, color }, lng, lat, scheduled: { dayLabel } | null }
```

- `scheduled`：`linkedActivityId` 指向的活动存在、active 且所在 day active 时为 `{ dayLabel }`。
- 操作条：未安排显示「加入行程」，已安排显示「再加一次」；独立地点额外有「收藏」。

### 4.6 route（当日路线）

```
acts    = orderedActivities(dayId)
located = acts 中 place.lng / place.lat 都非空的项
legs    = 相邻两项 (acts[i], acts[i+1]) 与其 route（规则同 4.2）
{ dayLabel, dateLabel, stops: acts.map(a => ({ n, title, timeText, located, lng, lat, hour })),
  legs: legs.map(l => ({ fromN, toN, mode, minutes, path, hasRoute })),
  minutes: 有 minutes 的段求和, missing: 无 route 或无 minutes 的段数,
  distance: 全部已知段都有 distance 时求和（米），否则 null }
gone = day 不存在或 deleted
```

- 地图只画 `located` 的站点。相邻两站都已定位才画连线；`route.path` 有 2 个以上点时按 path 画，否则画一条略弯的二次曲线；没有 route 记录的段画虚线。
- 文案：`minutes > 0` →「路上约 N 分钟」；有段但都未估算 →「路程未估算」；只有一项 →「只有一站」。大号底部再附「· X.X 公里」（distance 非空时）和「· N 段未估算」（missing > 0 且 minutes > 0 时）。
- 没有任何定位站点：地图区居中显示「这天的安排还没有地点」或「这天还没有安排」。
- 投影：等距圆柱投影，经度乘以 cos(平均纬度)，按外接框等比缩放后居中放进规定矩形（中号 182,26,146,116；大号 34,46,284,100，单位为基准像素）。只有一个点时放在矩形中心。

### 4.7 countdown（倒计时）

```
diff = startDate − today（按目的地时区，单位天）
出发前 diff > 0           → { label:'距出发', number: diff, unit:'天', progress: 0 }
旅途中 0 ≥ diff > −dayCount → { label:'旅途中', number: 1 − diff, unit:`/ ${dayCount} 天`, progress: 1 − diff }
结束后                     → { label:'已结束', number: −diff − dayCount + 1, unit:'天前', progress: dayCount }
startDate 为 null          → { label:'出发日期', number:'—', unit:'', progress: 0 }，副文案「还没定出发日期」
```

中号另有：起止日期与星期、每天一格的进度（已过的格亮起）、「共 M 天 · 已排 N 项安排」（N = active activity 数）。

### 4.8 clock（当地时间）与 expense（费用）

clock：`trip.timezone` 的时、分、秒；中号另有「HH:mm」和与本机的时差（「比你这里慢 1 小时」/「与你这里同一时区」）。时区未设置时显示本机时间并在中号写「旅程未设置时区」。

expense：

```
list  = active expense
paid  = list 中 status==='paid'；main = paid 中 currency === trip.currency
total = Σ main.amountMinor；count = paid.length
per   = members.length > 1 ? round(total / members.length) : null
est   = Σ(list 中 status==='estimated' 且 currency===trip.currency 的 amountMinor)
others= { 其他币种: 该币种 paid 合计 }
perDay= trip 每一天（按 visibleDays 顺序）main 中 expenseDate === 该天日期的合计；行前、行后、未记日期不进柱状图
hi    = 今天在旅程内 → 今天的下标；否则 perDay 最大值的下标
top   = main 按金额降序前 4 项：{ title: expenseTitle(), dayText:'第 N 天'|'行前'|'行后'|'未记日期', amount }
```

- 主数字取整到元（与费用页「已支付合计」同口径，只是不显示角分）。
- 小号副文案「人均 ¥X · N 笔」；没有已支付记录显示「还没有记账」。
- 中号右栏「花得最多」列 `top`；底部「预计还有 ¥X」（虚线胶囊）和「另有 JPY」（只列币种代码，金额见费用页）。
- 导出图片时提供「隐藏金额」开关，开启后金额显示为「¥ ···」。

### 4.9 重绘依据

`widgetDeps()` 返回该小组件依赖的源数据片段；客户端以它的序列化值做 memo，变化才重绘：

| kind | 依赖 |
|---|---|
| activity | 目标 activity；同一天 `orderedActivities` 的 id 列表；到达它的 route |
| day、route | 该天 `orderedActivities` 全量 payload 与 state；该天相关 route；day 本身 |
| place | 目标 favorite；`linkedActivityId` 指向的 activity 及其 day |
| countdown | 目的地时区的今天；trip 的 startDate、dayCount；active activity 数 |
| clock | 每秒（只更新指针与数字，不重建 DOM） |
| expense | 全部 expense；全部 activity 的 id、state、dayId、title；day 日期；成员数；今天 |

「已移除」不是小组件自己的状态，不写入 boardItem，不产生操作。

## 5. 小组件设计系统

原型 `<style>` 中「小组件」一段可以直接搬到 `app/src/components/widgets/widgets.css`。本节把规则写明，新增或修改小组件时照此执行，保证风格统一。

### 5.1 网格与规格

| 规格 | 基准尺寸 | 用途 |
|---|---|---|
| S 小 | 168 × 168 | 一个数字或一个对象 |
| M 中 | 352 × 168 | 左边主信息 + 右边详情 |
| L 大 | 352 × 352 | 上半图形 + 下半列表，或完整时间线 |

- 两个 S 并排加 16px 间距 = 一个 M 的宽；两个 M 上下叠加 16px 间距 = 一个 L 的高。白板上用 184px（168 + 16）作为排布步长，原型的样例就是按这个网格摆的。
- 内部一律按基准尺寸排版，再用 `transform: scale(frame.w / 基准宽)` 整体缩放。缩放范围为基准的 60%–250%。切换规格时保持当前倍率。

### 5.2 外壳

| 属性 | 值 |
|---|---|
| 圆角 | 30px（随缩放一起缩） |
| 内边距 | 14–16px；中号左右分栏时栏间距 16px |
| 阴影 | `inset 0 1px 0 #ffffff38, inset 0 0 0 1px #ffffff14, 0 1px 2px #0002, 0 18px 36px -14px #0007` |
| 裁切 | `overflow: hidden; isolation: isolate` |
| 字体 | `ui-rounded, 'SF Pro Rounded', 'Nunito', -apple-system, …, 'PingFang SC', 'Microsoft YaHei', sans-serif` |
| 交互 | 小组件内部不响应指针，整个小组件是一个可选中对象；打开详情走操作条「打开」 |

固定的角落约定（所有小组件一致）：

- **左上**：眉标或胶囊，说明「这是什么 / 哪一天」。眉标 12px、字重 650、不透明度 0.85；胶囊高 22px、字号 11.5px、字重 600。深色或彩色底上的胶囊为 `#ffffff2e` + 8px 模糊；浅色底上为 `selected` 底 + `primary` 字。
- **右上**：状态。序号用 24px 白色圆（日程）；图标用 26px 圆（费用）；「已移除」胶囊也在这里。
- **左下**：主数字或主标题。小组件只能有一个视觉主角。

### 5.3 字级

| 角色 | 字号 / 字重 | 用在 |
|---|---|---|
| 巨型数字 | 68 / 800，字距 −0.05em | 倒计时 |
| 大日期 | 56（中）、42（小）/ 300 | 这一天 |
| 主数字 | 44 / 300（时钟数字）；38 / 800（站数）；34 / 750（日程时间，灵活时间 26）；31 / 800（金额） | |
| 标题 | 16–18 / 700 | 日程、地点名称 |
| 正文 | 13–14 / 600–700 | 列表项名称 |
| 辅助 | 11–12.5 / 500–650 | 地址、时间、路程、说明 |
| 微型 | 9.5–10.5 | 柱状图日序、路程段 |

数字一律 `font-variant-numeric: tabular-nums`。货币符号比数字小（金额 31px 时符号 17px）。

### 5.4 色彩语言

每种小组件有自己的底色语言，但都从同一套 token 取色：

| 小组件 | 底色 | 随色板（绿/蓝） | 随明暗 |

| 倒计时 | `brand-a → brand-b` 径向渐变 + 同心圆纹 | 是 | 否 |
| 当地时间 | 固定深色表盘 `#2a2d33 → #111316`，秒针 `#ffa62b` | 否 | 否 |
| 费用 | `surface`，柱状图 `primary`（非重点柱 28% 透明） | 是 | 是 |

### 5.5 状态

| 状态 | 表现 |
|---|---|
| 正常 | 如上 |
| 已移除（源对象被删） | 整体 `filter: grayscale(1) contrast(.85) brightness(.92)`；外加 2px 虚线描边（偏移 3px，随缩放）；右上「已移除」胶囊（`#000a` 底）；标题加删除线；中号及以上另有一行「已从行程移除，恢复后这里会复原」（收藏为「已从收藏移除…」）。位置与大小不变 |
| 空 | 每种小组件有自己的空文案：「这天还没有安排」「这天的安排还没有地点」「还没有记账」「还没定出发日期」。空状态不显示 0 进度条以外的占位图形 |
| 缩小到屏幕宽度 < 80px | 只显示底色与主数字（或图钉），隐藏其余文字，保持画布流畅 |
| 减少动态效果 | 秒针隐藏；不播放进入动画 |

小组件永远不显示加载状态：它们读的是本地快照，离线也能完整显示。

### 5.6 示意地图

地点与当日路线小组件用**客户端绘制的示意地图**作底，不请求地图服务：

- 由目标 id（地点：favoriteId；路线：`'route-' + dayId`）做种子，生成街区、公园、河流、主次道路；同一 id 在三端、每次渲染都一样。算法照搬原型 `mapSvg()`：种子哈希 `x = (x * 31 + charCode) >>> 0`，随机数 `x = (x * 1664525 + 1013904223) >>> 0; r = x / 2^32`，绘制顺序与次数不变。
- 颜色全部取 5.4 的 map token，随明暗切换。
- 图钉（地点）与站点（路线）的**相对位置是真实的**：路线按 4.6 的投影放置；地点图钉固定在地图中央偏上。
- 好处：离线可用、三端一致、两套色板和明暗下都协调、没有额外的服务端代理与 key。真实街道底图作为后续增强，不在本期。

- 点预览即贴到视口中央，默认规格：倒计时 S、时钟 S、这一天（≤ 2 项 M，否则 L）、路线 M、日程 M、地点 S、费用按所点预览。

### 7.2 页面与状态

- `App.jsx` 页面表增加 `['board', '白板', <图标>]`，位置在 `map` 之后；手机底栏五项。白板页与地图页一样全视口。
- `context.board = { boardId, viewport: { x, y, zoom } }`，随现有 context 持久化；再次进入回到上次的板和位置。
- 首次进入且旅程没有 board：客户端创建一块「白板」（`order: 0`）。两台设备同时创建会得到两块，这是允许的，不做去重。
- 白板对象本地状态：`Map<id, Object>`，来源是增量接口 + 本机乐观写入。本机写入复用 `mutate()`。

### 7.3 渲染

- 画布：一个铺满视口的容器，内部一层 `transform: translate(x, y) scale(zoom)`；背景点阵间距 24px × zoom，zoom < 0.4 时放大 4 倍以免太密。缩放范围 10%–400%。
- 所有对象在同一个容器里按 `z` 排序（`z-index` 取排序后的名次），贴纸与小组件是 DOM，每一笔是一个 SVG。只渲染与视口相交（外扩 200px）的对象。
- 小组件：外层元素尺寸为 `frame.w × frame.h`；内层固定为基准尺寸，`transform: scale(frame.w / 基准宽)`，`transform-origin: 0 0`。内层只在 `widgetDeps()` 变化或规格变化时重建。
- 选择框、手柄、他人编辑框画在对象层之上的叠加层；线宽与手柄按 `1 / zoom` 反向缩放，保持屏幕上固定大小。
- 不引入第三方白板框架。

### 7.4 尺寸控制

选中单个对象时四角都有手柄（可见 13px，热区 44px），拖动时以对角为锚点，选框下方显示当前宽高（小组件显示百分比）。

| 对象 | 方式 | 范围 |
|---|---|---|
| 便签 | 宽高自由；字号不变，文字放不下时向下增高 | 100×80 – 900×900 |
| 文字 | 等比，改 `frame.scale` | 0.3 – 8 倍 |
| 表情、图片、GIF | 等比，改 `w/h` | 24 – 2400 |
| 小组件 | 等比，改 `w/h`；操作条另有小 / 中 / 大切换 | 基准的 60% – 250% |
| 笔迹、形状 | 等比，改 `w/h`；渲染时按 `w / 点集外接框宽` 缩放 | 24 – 2400 |

触屏：先按住已选中的对象，再落第二指捏合，缩放这个对象（以中心为锚点）；其他情况双指平移、缩放画布。键盘：`]` 置顶、`[` 置底。缩放过程通过 presence `live` 同步给其他人，松手提交一次 `frame`。

### 7.5 操作条

选中后显示在对象上方（空间不足时在下方）。顺序：类型专属主操作 → 规格切换 → 编辑 / 打开 → 颜色 → 置顶 · 置底 · 复制 · 锁定 · 删除。

| 选中对象 | 专属项 |
|---|---|
| 地点小组件 | 主按钮「加入行程」/「再加一次」；「打开」→ 地图页并选中该收藏；独立地点另有「收藏」 |
| 写了字的便签 | 主按钮「加入行程」；「编辑」；6 色 |
| 日程小组件 | 规格切换；「打开」→ 行程页并选中该活动 |
| 这一天 / 当日路线 | 规格切换；「打开」→ 行程页该天 / 地图页该天路线 |
| 费用 | 规格切换；「打开」→ 费用页 |
| 倒计时、时钟 | 规格切换 |
| 文字 | 字号档位 |
| 图片 | 拍立得 / 去掉相框 |
| 源对象已移除的小组件 | 只有「打开」（→ 对应页面的最近删除）与「删除」 |

「加入行程」：选择哪一天（列表含「暂不定日期」）→ 依次提交 `create activity` 与 `patch boardItem { linkedActivityId }`；第二条失败不回滚第一条。映射：地点 → `place` 取收藏、`title` 用地点名；便签 → `title` 取第一行前 40 字、其余进 `notes`；链接卡 → `title`、`url`。

### 7.6 在线提示

- 右上头像栏列出在这块白板上的其他成员；点击头像把视口移到对方选中的对象。
- 他人选中：对方颜色 2px 实线框，左上标签显示名字。他人正在编辑文字：虚线框，标签「某某 正在编辑」。
- 软占用：有人正在编辑某便签时，本机不能进入它的文字编辑，提示「某某 正在编辑这张便签」；仍可选中、移动。两人几乎同时进入编辑，`userId` 较小者保留，另一方自动退出并保存已输入内容。服务端不据此拒绝操作。
- 他人已保存的修改到达时，对象边缘闪现对方颜色 1.2 秒；变化在视口外时，屏幕对应边缘出现对方小头像，点击移动过去。减少动态效果时改为 3 秒静态角标。

### 7.7 撤销与删除

撤销 / 重做只作用于本机本次会话自己的操作，最多 50 步，不回滚别人的修改。删除后底部 5 秒「已删除 · 撤销」；「更多 → 最近删除」列出该白板 `deleted` 对象，任何成员可恢复。

## 8. 引用同步与「已移除」

| 源对象的变化 | 白板上的表现 |
|---|---|
| 活动改名、改时间、改地点、换天 | 日程、这一天、当日路线在下一次同步后更新；原来那天与新的一天同时更新 |
| 活动排序变化 | 序号与时间线顺序随 `orderedActivities` 更新 |
| 路程新增、修改、删除 | 日程中号的路程行、这一天大号、当日路线同步更新；删除的路程段变虚线 |
| 收藏改名、换标记 | 地点小组件名称、图钉形状与颜色更新 |
| 费用新增、修改、标记已支付、删除 | 费用小组件金额、笔数、柱状图、前 4 项更新 |
| 活动或收藏被临时删除 | 对应小组件**保留原位**，显示 5.5 的「已移除」状态；这一天与路线中不再列出该活动 |
| 某天被删除 | 这一天、当日路线显示「已移除」 |
| 源对象恢复 | 小组件自动恢复正常，不需要任何操作 |
| `linkedActivityId` 指向的活动被删除 | 「已安排 · 第 N 天」消失，操作条恢复「加入行程」 |

无障碍名称同步变化，例如「日程小组件：黑门市场午饭，已从行程移除」。

## 10. 原型

`prototype-board/index.html` 是单文件、无依赖、无服务端的交互原型，数据是样例，刷新即重置。

| 原型里的东西 | 正式实现 |
|---|---|
| 脚本第 1 段 `applyOp` 的 create / patch / state | `POST /operations` 的 create / patch / delete+restore |
| 字段 `link` | `linkedActivityId` |
| `type:'widget'`、`content.kind`、`style.size: 'S'|'M'|'L'` | 同名 |
| 第 2 段 `dayActs`、`legRoute`、`routeText`、`*Model()` | `orderedActivities`、行程页取路程规则、`travelAdvice`、`board-widgets.js` |
| 第 2 段 `sky()`、`mapSvg()`、`project()` | 5.4 时段色、5.6 示意地图、4.6 投影 |
| `content.src`（data URL） | `content.assetId` + 3.2 |
| BroadcastChannel 的 `ops` / `presence` / `live` | `/operations` + SSE `change`；`/presence` + SSE `presence` |
| 「模拟同伴」阿哲 | 无对应，仅用于单人演示在线提示 |

## 13. 开发 agent 容易做错的地方

1. 把小组件的数据复制进 boardItem。只存 id，显示内容每次现算。
2. 两项之间的路程只按 `toId` 找。必须同时匹配 `fromId === 前一项`，否则活动换天后会显示别的天的路程。
3. 自己写一套时间排序。必须用 `orderedActivities`，灵活时间项目的位置由 `order` 决定。
4. 「今天」用设备本地日期。倒计时、费用重点柱都按目的地时区。
5. 给笔迹单独一层。笔迹与贴纸必须同一个 z 序。
6. 用 SVG `<text>` 写表盘数字或站点序号。会在缩放容器里错位，用 HTML 叠加。
7. 小组件里放可点击元素。小组件整体是一个对象，「打开」走操作条。
8. 预计金额计入合计、其他币种折算进主币种。都不做。
9. 为小组件去请求地图服务或新增后端接口。本期地图是客户端示意图，小组件没有任何后端接口。
10. 源对象删除时删掉或隐藏小组件。必须原位保留并显示「已移除」。
