# 00｜设计依据与范围

版本 v0.9｜2026-10-12｜当前正式设计基线

## 产品目标

让同行者轻松记录想去的地方、一起修改安排，并在旅途中直接使用同一份行程。用户可以只写“下午逛逛”，逐步补充时间、地点和开销，也可以到现场再决定。

日常主线是：进入旅程 → 添加或收藏地点 → 按天安排 → 共同编辑与同步 → 按行程出行并记账。地图、行程和费用可随时往返，不设必须依次完成的阶段。

## 已确定的产品范围

| 范围 | 当前要求 |
|---|---|
| 启动与旅程入口 | 手机号或邮箱登录；继续时恢复完整旅程及编辑上下文；创建时填写名称并选择团队类型；加入及查看其他旅程 |
| 加入方式 | 编码、手机扫码、邀请链接均用于加入同团队；分享复用邀请，生成时选择期限 |
| 团队治理 | 管理员团队和平等团队；全员可增改，创建者管理管理员和邀请权限，离开后按加入顺序继任；删除与恢复按团队规则 |
| 行程 | 按天列表为中心；直接添加活动和选址；灵活或精确时间；通勤与提前到场缓冲；途中直接使用和修改 |
| 地图 | 团队共享收藏，默认全部显示，可突出某天路线；地点类别及安排状态标记与筛选；可直接加入行程 |
| 费用 | 以已支付记录及合计为主；预计单独标明；支付后以实际金额替换同一笔预计金额 |
| 协作 | 完成修改后自动保存并在线共享；普通竞争按修改发生时间取最新；删除独立于内容更新 |
| 离线与恢复 | 修改持久存本地，联网自动上传；常规业务删除临时可恢复，恢复保留期间的新修改；最后一人退出永久清除旅程 |
| 界面 | 行程、地图、费用三个主入口；无图和部分填写时布局完整；次级操作按需展开 |
| 视觉与动效 | 类Apple Liquid Glass材质，简洁、连续、可中断的动画；稳定的阅读与操作体验 |
| 正式实现质量 | 真实账号、服务端权限、跨会话同步、真实地点路线服务、数据恢复和桌面/手机验收 |

行程主页面移除常驻地图与账本侧栏。通用沟通、评论、议题投票和独立出行手册退出范围。针对删除与恢复保留对象上的轻量表态：平等团队集体删除须至少一人明确希望删除，且不参加或希望删除的去重人数严格超过当前全体成员一半；只有不参加过半时保留活动。创建者/管理员可直接恢复，成员也可通过全团队过半支持恢复。日常使用不需要逐项核对、填写保留原因或生成定稿。费用不保留预计与实际的对照功能。

## 允许留白的规划

具体日期、活动时间、地点、通勤和费用可以逐步确定。缺失信息本身不形成待办、警告计数或使用门槛。只有用户正在执行的动作需要某项信息时，才就地询问，例如导航需要可定位的地点。

已经填写的内容仍应准确保存。时间重叠或赶路困难以具体建议呈现，用户可保留安排；保存失败准确反馈；普通修改竞争自动按操作发生时间合并，删除和恢复按独立规则处理。提示不代替用户作旅行决定。

每项业务内容在设计中具有来源、维护入口和空值表现。样例图片、固定通勤数值、自动旅行感言不作为正式界面的填充材料。

## 交付约束

- 开发团队为3人，目标在2026年12月底完成；确切提交日、每周投入及课程评分材料待提供。
- 正式形态为响应式Web，覆盖电脑浏览器、iOS Safari和安卓手机浏览器；具体测试机型与版本在实施前确定。
- PWA安装体验和原生安装包作为后续扩展。
- 交付完整前后端、真实服务集成、测试与研究记录、部署说明、备份恢复方法；不要求实际公开发布。
- 首轮实现以同一目的地时区、人民币、熟人结伴的短途旅行为设计场景。跨时区、跨币种与自动多路线在后续另立需求。
- 记账记录用户支出；系统不代订、支付、转账或代办退款，不持续追踪成员位置。
