# 04｜研究验证与实施计划

版本 v0.9｜2026-10-12

## 1. 验证目标与交付基线

研究验证用户能否从空白账号开始共同安排行程，在手机和电脑之间继续工作，并在旅途中查看、修改与记账。重点观察入口发现、状态理解、输入保留和失败恢复。正式产品原则见[02-交互与界面设计稿](02-交互与界面设计稿.md)，连续任务见[06-完整用户旅程与交互流程](06-完整用户旅程与交互流程.md)，已确认决策与待议问题见[05-小组设计决策工作坊](05-小组设计决策工作坊.md)。

| 项目 | 基线与执行方式 |
|---|---|
| 团队与时间 | 3人小组，按2026年底交付倒排；暂用12月31日规划，课程最终提交时刻及每周容量由团队确认 |
| 最终交付 | 响应式Web，覆盖电脑及iOS、安卓手机浏览器；完整包含真实跨会话同步、地点搜索及地图路线能力；不要求公网部署 |
| 过程产物 | 纸面设计与交互原型用于验证信息结构和操作；已有原型测试只覆盖其对应实现，正式应用逐项重新取得证据 |
| 研究招募 | 访谈计划3–5人，可用性测试计划5–8人；实际人数、来源和未覆盖人群在执行后记录 |
| 测试环境 | 独立测试账号、隔离数据、可复现构建；真实数据服务与受控故障分别记录，不混用结果 |
| 结果记录 | 每项填写版本、设备、网络、执行日期、通过/失败/未验证及证据；当前文档是待执行计划 |

主线为登录与继续旅程、创建与加入、按天行程、地图收藏与每日路线、费用账本、自动保存和云端同步。内置沟通、评论和通用议题投票已取消；业务对象删除与恢复使用轻量表态。可行性建议不构成保存或分享门槛，未定资料可以留白。常规业务删除可恢复，最后一人退出永久清除旅程；分享为邀请加入同一团队。账本保持已支付与预计支付替换的最小流程。

## 2. 研究问题

| 编号 | 需要观察的问题 | 证据 |
|---|---|---|
| RQ-1 | 用户能否区分继续、创建、加入和其他旅程，并回到正确位置？ | 首次动作、回退、目标旅程与日期、求助次数 |
| RQ-2 | 用户能否直接添加活动，也能理解收藏与已安排地点的关系？ | 直接选址、收藏后排程、取消收藏后的理解 |
| RQ-3 | 灵活时间、精确时间、通勤和提前到场是否足以表达真实安排？ | 活动编辑结果、时间解释、移动后的预期与实际 |
| RQ-4 | 用户能否保留留白，理解具体时间提示并自主决定是否调整？ | 是否被缺项困住、是否误认提示阻止保存 |
| RQ-5 | 用户能否理解完成修改后自动保存共享、真实操作时间较新值生效及离线恢复？ | 两端状态复述、离线晚到结果、草稿和队列持久化 |
| RQ-8 | 用户能否理解两种团队的删除权限、过半表态及恢复结果？ | 去重计数、删除与恢复条件、删后修改与恢复后的字段 |
| RQ-6 | 用户是否理解已支付合计、预计条目以及支付后的替换结果？ | 金额复述、是否重复记账、原预计是否退出清单 |
| RQ-7 | 无图、稀疏、长文本和玻璃背景下，手机及键盘操作是否清楚顺畅？ | 阅读错误、焦点、触控、缩放和动画中断记录 |

设计假设是：按天行程作为主入口能减少寻找下一步的成本；直接选址能减少添加活动的中间步骤；轻量同步状态有助于理解保存结果；可中断的连续动画有助于保持上下文。每项同时记录支持、反例和无法判断的证据。

## 3. 形成性研究与伦理

### 3.1 招募与同意

邀请近两年有多人出游规划经历的人，兼顾手机和电脑使用习惯。筛选仅询问经历、常用工具及是否愿意参加20–30分钟访谈。记录实际招募方式和人数。

开始前说明课程研究目的、记录形式、可访问者和删除日期。参与者可以跳过问题或退出。默认采用去标识化笔记；录音、屏幕录像分别取得明确同意。研究任务使用测试账号和虚构旅行，预先授予完成任务所需权限并记录；不收集个人口令、支付信息、证件、同行者联系方式或非必要精确住址。研究材料按约定日期删除，展示前复查可识别内容。

### 3.2 访谈提纲

1. 回忆最近一次多人规划旅行，从哪里开始，后来如何找到每天的安排？
2. 你如何保存地点，又如何把地点排进行程？有没有直接写一项安排而暂不选地点的时候？
3. 哪些时间、地点或费用通常直到出发后才确定？当时怎样记录？
4. 通勤和提前到场怎样影响一天的安排？临时更改时怎样通知同伴？
5. 多人修改同一份计划时，有没有遇到覆盖、重复或不知道是否保存的问题？
6. 提前订票和途中消费怎样记账？预计费用在付钱后还会怎样使用？
7. 在手机上找下一项安排、地址或路线时，最费力的步骤是什么？
8. 你怎样邀请同伴加入同一份旅程？删掉一项安排后，何时会想恢复它？

追问具体经历、动作与结果，避免以预设功能引导回答。记录表包含匿名编号、同意范围、情境、动作、原话短摘、研究者解释、反例和后续问题。一人归纳主题，另一人复核分歧。

## 4. 可用性测试

### 4.1 组织方式

早期用纸面或交互原型检查入口、页面层级和状态表达；集成阶段使用正式应用检查真实持久化、权限、同步、地图和账本。每场约45–60分钟，主持与观察分工，三人轮换。参与者任务分组轮换，技术验收由团队补足。

主持人只读目标，观察参与者自行寻找入口；可中性询问“你现在在找什么”，求助另记。遇隐私暴露或可能损坏测试外数据时停止对应任务。每轮固定版本、浏览器、网络和数据；主持人预走查单独记录。

### 4.2 场景与任务脚本

S1与S2使用不同虚构活动名，保留相同任务结构。每套预置管理员团队和平等团队，分别含创建者、管理员和普通成员账号，使用5人、4人和1人规模验证严格过半边界。每套含一个空白旅程、一个只有两项短安排的无图旅程、一个长标题密集日程、一个已有收藏的地图和一笔预计费用。故障任务单独重置，避免前项故障污染后续结果。真实地点及路线测试调用高德服务，保存请求条件和可核验返回。

| 任务 | 主持人给出的目标 | 完成状态 |
|---|---|---|
| T01 启动与继续 | 用手机号或邮箱登录，找到上次旅程，再打开另一趟 | 完整恢复页面、日期、滚动与编辑草稿；本地未上传草稿只在原设备可见 |
| T02 从空白创建 | 填写旅程名称并明确选择管理员或平等团队，再只写“下午逛逛”，暂不确定日期、地址、时间或费用 | 安排保存并在重新打开后可见；可继续使用 |
| T03 加入 | 生成带自选期限的邀请，通过编码、扫码和链接加入 | 登录回原邀请，加入同一团队；重复接受保持同一成员身份 |
| T04 直接添加 | 给第一天添加一个有地址的活动，尝试搜索地址和地图选点 | 地点直接进入活动；无需先收藏 |
| T05 收藏和路线 | 收藏一个地点，加入第二天，切换每日路线，再按当前角色取消收藏或表达删除意愿 | 路线与日期对应；删除按团队规则生效后，关联活动仍保留 |
| T06 调整安排 | 改一项活动为精确时间，设置提前到场和通勤；用非拖拽方式跨日移动 | 时间含义正确，改动范围符合用户预期 |
| T07 留白与提示 | 保留一项时间未定的活动，再保留一组已知重叠安排，分享当前行程 | 保存和分享成功；用户能理解重叠提示并自行选择 |
| T08 记账 | 记一笔已支付餐费，把预计200元门票改为实付180元 | 已支付合计正确；门票只保留180元已支付条目 |
| T09 出行使用 | 在手机找到今日下一项，打开导航；下雨后直接改地点，再记车费 | 同一行程内完成；另一成员可见已同步结果 |
| T10 同步恢复 | 两端改不同活动，再按不同操作时间改同一内容；离线编辑后刷新重开，再联网 | 本地草稿和队列恢复，自动上传；按操作时刻保留较新值，焦点不丢失 |
| T11 删除与恢复 | 在两种团队中删除并恢复活动，测试删后另一成员改时间 | 权限正确、表态去重、严格过半；删后修改不复活，恢复显示新时间 |

扫码权限拒绝、无摄像头和邀请失效任务验证替代入口。每次修改完成自动保存，在线自动共享；离线完整编辑、本地持久化、重开恢复与联网自动上传均执行正式验收。

另安排至少2组、每组2–3位参与者进行15–20分钟共同规划，可从自愿参与者中组成。观察他们如何分工修改、发现同步和处理同对象竞争。只完成单人任务时，群体协作记为未验证。

### 4.3 指标与比较

记录任务完成/部分完成/未完成、秒数、首次入口、回退、求助、错误后果、恢复步骤、状态复述和1–5级主观难度。同步任务额外记录未提交输入丢失、静默覆盖、重复条目以及无关编辑互相阻塞。时间和账本任务记录用户能否解释当前内容，视觉任务记录阅读与操作障碍。

如与“聊天工具＋地图收藏＋共享表格”比较，双方完成结构等价的任务，轮换工具顺序及S1/S2数据，记录工具版本与实际能力。按实际人数报告原始计数、典型观察、反例和条件差异；小样本结果采用描述性分析。

## 5. 正式产品体验验收

以下用例待正式应用实现后执行。每项同时记录真实创建路径与结果；不得只用预装样例截图验收。需求追踪使用[01-软件需求规格说明书](01-软件需求规格说明书.md)的当前编号，以下独立ID用于复测。

| ID | 操作与通过条件 |
|---|---|
| A01 启动 | 手机号或邮箱可登录，继续完整恢复上次旅程页面、日期、滚动及编辑草稿；未上传草稿仅原设备恢复，跨端仅见已同步内容；有最近旅程可继续；创建、编码/扫码/链接加入及其他旅程均可到达。最近旅程失去访问权后返回可访问列表，说明当前结果 |
| A02 空白创建 | 填写旅程名称并明确选择管理员或平等团队，无预选团队类型；仅名称和日序即可保存“下午逛逛”活动；日期、地点、精确时间、费用、图片均可留白，重开仍在 |
| A03 加入 | 生成邀请时选择期限，独立账号通过三种方式加入同一团队；认证保留邀请目标，重复接受不重复建立成员；失效邀请、相机拒绝和网络失败有可行恢复入口 |
| A04 行程 | 默认按天无图列表，显示“第1天”；新增、编辑、删除和跨日移动连通，手机和键盘有非拖拽等效路径。改变日期不静默丢失活动 |
| A05 直接选址 | 活动中直接搜索地址、地图选点或选收藏，均可维护地点；重复访问同一地点仍可建立独立活动 |
| A06 地图 | 收藏星标与每日路线分别表达；切换日期对应路线，地点选择与详情联动。取消共享收藏遵守团队删除权限，生效后保留活动；删除活动保留独立收藏 |
| A07 时间 | 灵活活动不伪造时刻；精确活动、到场缓冲、通勤可以创建和修改。服务返回与用户设定值沿真实输入产生，未取得路程数据时时长留空 |
| A08 自主使用 | 留白可保存、同步、查看与分享；已知重叠就地提示但仍可保存。全流程无强制核对、接受原因、定稿发布或草稿转换 |
| A09 账本 | “记一笔”可直接记已支付；预计单独标明；预计200元支付180元后原条目更新，合计只计180元，不展示旧预计或差额对照；重试不产生重复账目；独立账目名称可保存并重开恢复，名称留空时按状态和金额辨识 |
| A10 自动保存 | 完成一次修改即自动保存，在线自动上传共享，他人自动更新；未确认云端前不显示已同步；切日期、刷新及重开恢复草稿和待上传队列 |
| A11 跨端同步 | 独立账号与会话真实协作，不同活动改动保留；普通同内容修改按真实操作时刻较新值生效，上传时刻不决定结果；更新保持输入、焦点和阅读位置 |
| A12 失败恢复 | 保存失败、响应丢失、断线、会话过期均保留输入；联网后自动上传同步，复核权限，重试无重复活动或费用 |
| A13 途中使用与分享 | 手机直接在行程查看当天、地址和导航，临时修改无需组织者发布；分享生成有自选期限的邀请，接收者登录加入同一团队，看到已同步内容 |
| A14 真实内容 | 每项显示值能追溯用户输入、正式服务或业务计算，并有维护入口；无固定20分钟、示例图片、自动旅行感言、空图片框、未知核对清单或完整度任务 |
| A15 稀疏与密集 | 用户实际录入的无图短行程与长标题密集行程都可读，首要动作明确，装饰随空值收起 |
| A16 材质 | 导航、日期选择器及地图浮动控件采用统一类Liquid Glass层次；正文和长表单背景稳定；明暗地图、文字滚动和高对比条件下文字控件清楚 |
| A17 动画 | 连续切日期、快速开关详情、重排中再操作可中断衔接；无丢点击、输入、焦点抢夺或同步触发反复入场 |
| A18 降级体验 | 减少动态、减少透明及基础样式环境仍完成相同任务；状态变化可直接理解 |

### 5.1 日期和时间联动专项

| ID | 操作与通过条件 |

| A30 范围外与跨午夜 | 5天缩为3天，多出内容仍在行程外安排，已有日期、时间和地点完整保留，可移回；23:00至次日01:00为一个活动，次日延续打开同一对象；范围变化不触发删除 |

### 5.2 权限、删除恢复与事件顺序专项

| ID | 操作与通过条件 |
|---|---|
| A19 管理员团队 | 全员可新增和修改；创建者/管理员可直接删除，普通成员只能表达不参加或希望删除；创建者可设置及撤销管理员；离开后从剩余管理员中按加入团队顺序继任 |
| A20 平等团队 | 全员可增改；至少一人希望删除，且当前全部成员去重后的“不参加∪希望删除”人数严格过半才软删除；创建者可单独决定删除 |
| A21 删除计数 | 5人团队：3人仅不参加仍保留；其中至少1人再希望删除则临删；2人不参加加另1人希望删除则临删；1人同时两种表达加另1人不参加只计2人，仍保留；4人中2人不过半，3人过半 |
| A22 恢复 | 两种模式创建者/管理员可直接恢复，普通成员独立表达赞成恢复；全部当前成员去重后严格过半恢复。5人2票不恢复、3票恢复，重复表态不增票；删除表态不计作恢复票；删除与恢复后，原有个人“不参加”状态保持不变 |
| A23 删除与修改并发 | A先删除，B后修改时间，对象仍删除；恢复后B的新时间保留。分别交换上传顺序并重放事件，结果一致；常规业务删除可恢复，最后一人退出按A38永久清除 |
| A24 离线晚到 | A10:30离线改字段，B10:40已同步改同字段，A10:50上传；最终保留B。交换网络到达顺序、刷新重开A后重传，结果仍一致 |
| A25 普通更新顺序 | 按真实操作时间验证较新修改生效；不同字段与对象不丢改动，延迟旧响应不回滚新内容；重复和失序事件不重复创建、不重复计票、不误删或误恢复 |
| A26 持久化与继续 | 离线完成活动/账目修改后刷新、关闭重开，恢复完整上下文、输入和队列；联网自动同步，其他设备仅看到同步后的内容；他人更新不抢焦点 |
| A27 时钟异常 | 用独立参考时钟记录真实操作次序，注入设备时间前后偏移、回拨、休眠重启及长期离线；时间证据足够时仍采用较新操作；证据不足时保留未决操作并反馈原因，不按上传先后或未经校验的设备时间覆盖已存内容。记录偏差、证据与合并结果 |

删除、恢复和普通字段更新分别检验；普通修改不得改变删除状态。按A32–A35验证共享地图、邀请权限、表态触发和创建者继任。可行性提示不得成为保存限制。
