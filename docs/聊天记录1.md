多人协作旅行规划工具
这个题目很适合四人组，因为功能容易拆分，又有明显交互性：
- 成员分别收藏景点
- 拖拽景点生成日程
- 投票和表达偏好
- 自动检测营业时间、路程及时间冲突
- 调整预算后，行程方案实时变化
- 显示某项决定是谁提出、谁反对以及替代方案
研究问题可以是：怎样减少多人规划中的沟通成本和决策冲突？

# 多人协作旅行规划工具｜完整业务流程（四人小组项目版）
> 核心定位：**多人实时协同行程规划**，支持成员独立收藏景点、拖拽排日程、偏好投票、时间冲突校验、预算联动、决策留痕。下面分【前置准备 → 景点收集阶段 → 行程编排阶段 → 方案投票评审阶段 → 预算迭代阶段 → 方案定稿 & 导出分享 → 行程执行阶段】，同时标注每个阶段四人可以拆分的任务。

## 一、项目前置准备（项目初始化，项目组长主导）
**目标**：确定旅行基础信息，建立协作空间，邀请成员，统一基础约束
1. 创建旅行项目：填写旅行名称、目的地、出行起止日期、出行人数、总预算上限
2. 邀请成员（4人）加入项目空间，分配基础权限（默认全员可编辑；可设置只读查看权限）
3. 录入全局基础约束：
    - 成员固定不可变动时间（例如A同学10.1上午有事不能出行）
    - 出行交通基础规则（公共交通/自驾）
4. 系统初始化空白景点库、空白日程表、投票面板、预算面板
> 产出：项目协作空间，基础约束配置完成

## 二、景点收集阶段（成员独立并行操作）
**目标**：每个人独立搜集、收藏心仪景点，表达个人偏好，不强制统一
1. 成员各自检索景点：系统调用外部API获取景点**营业时间、地址、门票、建议游玩时长、图片简介**
2. 成员操作：
    - 收藏景点到项目公共景点池；可给景点打标签：【想去/一般/不想去】
    - 给景点写备注（个人理由：比如想看日落、美食多）
    - 对景点标注个人偏好评分（1~5分）
3. 系统自动汇总公共景点池：展示每个景点**谁收藏、谁拒绝、个人评分**
4. 小组内部可筛选：只看所有人高评分景点，过滤掉有人明确拒绝的景点
> 产出：公共候选景点池，带全员偏好标记
> ✅ 分工建议：四人可以每人负责搜集一类景点，比如A搜自然风光，B搜美食，C搜博物馆人文，D搜住宿商圈

## 三、行程编排阶段（拖拽式构建日程，冲突自动检测）
**目标**：从景点池拖拽景点到每日时间轴，生成初步行程，系统自动校验
1. 编排操作：
    - 拖拽景点到对应日期、时间段；设置游玩时长、停留时间、景点间交通耗时
    - 可调整顺序，拖拽重新排序；支持新增午休、吃饭、住宿节点
2. 系统实时自动校验（核心功能）：
    - ⏰ 时间冲突检测：景点营业时间不匹配、上一个景点结束时间晚于下一个景点开始、成员不可用时间冲突，标红提示
    - 🚗 路程校验：根据地理位置计算两点之间通勤时长，若预留时间不足告警
3. 多人协同：支持多人同时编辑，实时同步，记录**每一条修改是谁操作**
4. 成员可对某一段行程添加评论：提出修改意见、备选方案
> 产出：1版或多版候选行程草案（可以同时维护方案A、方案B两套行程对比）

## 四、方案投票评审阶段（偏好表决，决策留痕）
**目标**：对候选行程/景点进行投票，记录观点、反对理由、替代方案
1. 创建投票主题：
    - 场景1：二选一整套行程方案投票（方案A vs 方案B）
    - 场景2：单个景点投票（要不要加入行程）
2. 成员操作：
    - 投票：同意 / 反对 / 弃权
    - 反对时，**必须填写理由 + 推荐替代景点/方案**（需求里的核心点：记录反对意见+替代方案）
3. 系统汇总投票面板：
    - 展示：议题、投票结果、**谁同意、谁反对、反对理由、备选方案**
4. 小组讨论：可基于投票结果修改行程，重新生成新版本，再次投票
> 产出：投票记录、决策历史，每一次决定永久留痕，方便回溯

## 五、预算联动迭代阶段（修改预算，行程实时联动）
**目标**：预算变动，行程方案自动评估，辅助取舍
1. 行程中每一项条目绑定成本：门票、交通、餐饮、住宿预估费用
2. 系统实时汇总总花费，对比总预算上限
3. 用户操作：
    - 修改总预算上限 / 修改单项费用
    - 系统实时更新总预算；如果超预算，高亮标记高成本项目
    - 可选：自动提示可替换的低成本备选景点
4. 小组可协商：删减高价景点，替换备选方案，再次投票确认调整
> 产出：带完整预算明细的行程版本

## 六、方案定稿 & 导出分享
1. 小组确认最终版本，标记【定稿】，锁定基础内容（锁定后修改会生成新版本，保留历史版本）
2. 支持导出：PDF行程单、日历文件（ics导入手机日历）、预算明细表格
3. 分享链接：可对外分享行程，设置查看/编辑权限
4. 自动生成每日行程清单、景点信息、预算汇总、决策日志（历次投票、修改记录）

## 七、行程执行阶段（出行中）
1. 查看当日行程、导航跳转景点、查看门票信息
2. 行程临时变更：成员可现场修改，记录变更人，再次发起简易投票
3. 实际花费录入：对比预估预算，记录实际开销

# 配套核心业务规则（写进需求文档）
1. **版本与决策留痕**：所有拖拽修改、投票记录，绑定操作人，保存历史版本，可回滚旧方案；每条反对意见必须支持填写替代方案
2. **冲突检测规则**
    - 景点不在营业时间内 → 冲突
    - 前一个地点结束 + 通勤时间 > 下一个景点开始时间 → 时间冲突
    - 该时间段存在成员不可用时间 → 人员冲突
3. **预算联动**：预算是**视图联动**，不是自动删除景点（不替用户做决定，只高亮告警+推荐备选）
4. **权限**：项目内成员默认可编辑；支持项目只读访客

# 四人组模块拆分建议（适配课程大作业）
- 成员1：用户登录、项目空间、成员邀请、权限模块（项目初始化模块）
- 成员2：景点搜索收藏、偏好打分、公共景点池（景点收集模块）
- 成员3：拖拽日程编排、时间/路程冲突检测、多人实时协同（行程编排核心）
- 成员4：投票系统、预算计算、版本管理、导出、决策日志（投票&预算&导出模块）
